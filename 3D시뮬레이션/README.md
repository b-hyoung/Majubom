# 마주봄 · 실험 공간 스터디

촬영 전 공간과 행동을 검토하기 위한 로컬 Three.js 모델. 원본 영상의 상대 배치를 재현하고 안전바 넘기 30초 동작 리허설을 제공한다. 실제 센서 판정이나 물리 시뮬레이션이 아닌 수작업 키프레임 연출이다.

## 실행

이 폴더에서 `python3 -m http.server 8766 --bind 127.0.0.1` 실행 후 http://127.0.0.1:8766 접속. 외부 CDN 없이 동작한다.

드래그 회전, 우클릭 이동, 휠 확대. 공간 시점 프리셋, 측면 벽/천장/이름 표시, 침대 폭·길이 조정, PNG 저장, 원본 프레임 비교를 지원한다.

## 파일

`app.js`: 미터 단위의 절차적 공간 모델 및 조작. Y축이 위쪽, 뒤 유리 칸막이는 -Z, 침대 머리는 -Z 방향.
`index.html`, `style.css`: 공간 뷰어.
`vendor/`: 로컬 Three.js와 OrbitControls/RoundedBoxGeometry (라이선스 동봉).
`assets/`: 참고 프레임, 정지 대시보드, 글꼴.

공간 수정 시 임시 치수를 실측으로 단정하지 말고 근거/상태를 함께 갱신한다.

- 왼쪽 작업대 배치 수정(2026-11-15 사용자 확인): 꺾임 없이 큰 책상–작은 책상–큰 책상 순서의 일자 배치. 모델의 각 길이 1.45/0.65/1.45m와 깊이 0.9m는 임시값.

- 사용자 배치 보완: 침대 오른쪽은 낮은 사물함이며 그 위에 노트북. 침대 오른쪽 난간이 사물함 옆에 오도록 이동(모델상 여유 2cm). 폭 변경 시 오른쪽 정렬을 유지하고 ToF/mmWave도 침대 중심을 따라 이동. 머리맡 끝 사물함 위에 Raspberry Pi와 개략 전원/LAN 케이블을 배치. 사물함 개수·치수·배선 경로는 시각적 근사값.

- 사용자 보완: 사물함 쪽 오른쪽 난간은 매트리스 아래로 내림. 반대쪽 난간은 올린 상태 유지. ToF 지지대는 머리판/발판 바깥 뒤쪽 중앙에 배치.

- 사용자 공간 보완: 왼쪽 의자는 책상 안쪽으로 넣음. TV와 머리맡 ToF 사이 깊이에 좌우 유리 칸막이를 추가하고, 더 뒤쪽 닫힌 유리문은 유지. 앞 칸막이 폭/중앙 통로 폭은 설명을 바탕으로 한 임시값.

- 중간 공간 깊이: 사용자 설명에 따라 앞 구역 약 3.74m(앞 가장자리 z=2.8 → 앞 칸막이 z=-0.94)의 2/3인 약 2.49m로 조정. 뒤 유리문 z=-3.43. 절대 치수는 모델 임시값이며 사용자 확인값은 비율이다.

- 침대 맞은편 책상은 서로 연결되지 않은 독립 책상으로 수정. 큰 책상 1.30m / 작은 책상 0.55m, 사이 약 17.5cm 간격은 분리 상태를 표현하는 임시값.

- 문 경계 보완: 앞/뒤 유리문에 바닥 턱과 2줄 레일 추가(높이·폭은 시각적 임시값). 앞쪽 왼 책상/오른 사물함은 앞 문 레일 전에 끝나도록 이동·단축. 중간 공간 왼쪽에는 별도 책상·데스크톱·의자 추가. Raspberry Pi는 침대 머리판 바로 옆 사물함 위로 이동. 유리문은 현재 열린 배치 표현이며 개폐 조작은 아직 없음.

- 사용자 추가 확인: 라즈베리파이 쪽 문턱 뒤(중간 공간 오른쪽)에 책상 한 대 추가. 크기와 위치는 개략 배치이며 문 레일과 간격을 둔다.

- 사용자 확인: 오른쪽 문턱 뒤 책상에 PC를 배치하고 라즈베리파이와 유선 연결을 표현. 케이블은 벽 쪽으로 내려 문턱을 넘어 PC 본체로 연결하는 개략 경로이며 실제 포트/통신 규격은 미확인.

## 원본 기반 행동 리허설

`scenario.js`에 의복을 입은 관절형 인물과 두 가지 30초 타임라인을 정의한다.
- 안전바 넘기: 누움 → 누운 채 무릎 세우고 한 손으로 난간 잡기 → 몸 비틀어 일어나 다리 접고 앉기 → 골반 회전 → 한쪽 다리 넘기(반대쪽은 침대 위) → 유지 → 다리 회수 → 침대 안으로 복귀.
- 침상 가장자리 이동: 누움 → 무릎 굽히고 매트리스 짚어 일어나기 → 다리 접고 앉기 → 옆으로 회전하며 양다리 내리기 → 걸터앉기 유지 → 침대 안으로 복귀. 이 모드에서는 왼 난간을 내리고, 난간 모드로 돌아오면 다시 올린다.
- 기준: nurse 저장소 카메라 원본의 1~3초 간격 프레임 검토. 모션 캡처나 프레임 단위 실측 복원이 아닌 수작업 동작 연출이다. 후반 유지 시간을 포함해 각각 30초로 구성했다.
- 알림: 정상→주의→위험. 난간은 14초, 가장자리 이동은 16초에 연출용 위험 표시. 원본에서 관찰한 폰 문구 불일치와 위험/주의 변동을 그대로 재현하지 않고 각 행동에 맞는 문구로 정리했다. 복귀 후 알림 유지도 촬영용 설정이다. 실제 판정·전송 지연·예측 선행 시간을 증명하지 않는다.
- 재생/일시정지, 시간 이동, 처음으로, 0.5배속, 사람 표시, 시나리오 전환 지원. 모드 전환은 0초로 초기화하며 음성을 취소한다. 숨겨진 탭에서는 일시정지.
- 선택적 음성은 브라우저 SpeechSynthesis 한국어 음성. OS 지원과 출력 환경에 의존하며 실제 청취 확인은 미실시.
- 모니터는 기존 dashboard.png를 유지한다. 폰과 자막만 타임라인에 따른 연출이며 서버/센서에 연결하지 않는다.
- 검토: 난간 준비/앉음/다리넘기/복귀, 가장자리 앉음/복귀 렌더를 확인. 모드 전환 시 난간 높이, 타임라인 초기화, 재생 진행, JS 오류 없음 확인.

## mmWave 배선

사용자 확인에 따라 천장 mmWave에서 천장·벽 몰딩을 따라 머리맡 Raspberry Pi로 연결되는 케이블을 추가했다. 경로와 몰딩 단면 치수는 개략 모델. 센서 위치가 바뀌면 케이블 시작점도 갱신한다. 실제 포트와 케이블 규격은 미확인.

### 지지 다리·앉은 자세 수정

원본 난간 영상 9~18초를 다시 확인해 접어 앉기와 반대 다리 지지를 함께 수정했다. 모든 무릎을 위로 향하게 하던 pole을 자세별 방향으로 대체하고, 골반은 앉은 높이에서 수평 회전하며 상체 기울임은 척추가 담당하도록 분리했다. 13~20초 동안 반대쪽 발목·무릎과 골반 위치를 고정한다. 지지 발목은 침대 좌표 약 (-0.05, 0.79, 0.36), 골반은 난간 가까운 x=-0.24m에서 유지된다. 접은 발은 bind-local 축에서 최대 25도 굽힘을 주며 세계 방향을 강제하지 않는다.

`evidence/seated-support-positions.json`은 전환·넘기·유지·복귀 구간의 실제 스킨 모델 관절 위치, `evidence/seated-support-audit.json`은 두 주요 시나리오의 0.05초 샘플 검사다. 접촉력이나 전신 균형의 물리적 검증을 의미하지 않는다.

### 가상 사고 시나리오

fall-scenario.js는 치매 환자가 난간을 넘어 내려가려다 지지를 잃고 측방으로 넘어지는 30초 촬영 초안이다. 원본 nurse 영상에 실제 낙상은 없으며, 손·다리·골반 경로와 14초/22.2초 알림은 연출이다. FDA/MHRA의 난간 넘기 사고 자료와 Robinovitch 등(2022)의 고령자 낙상 영상 연구를 참고했다. 후자는 난간 넘기 전용 연구가 아니므로 관절 궤적을 입증하지 않는다. 출처 URL과 적용 범위는 evidence/scenario-basis.json에 보관했다.

Claude 화면 검토 후 반대쪽 다리를 접고 손이 난간에서 떨어지는 자세를 수정했다. 바닥 자세에서 아래쪽 팔꿈치가 지면을 관통하던 문제를 수정했다. 뼈 좌표 유한성·바닥 정점·연속성 검사는 물리적 균형, 접촉력 또는 전신 충돌 검증이 아니다. exports/majubom-rail-fall-demo.mp4는 1280×720, 20fps, 30초 무음 시연본이다. 웹의 위험 알림 음성 옵션은 별도다.

추가 검토 반영: 마지막 손 지지를 17.6초까지 유지하고 17.7초에 해제, 18.25초 접촉 자세로 이어지도록 하강 시간을 단축했다. 17.6~18.6초를 0.05초 간격으로 검사한 최소 정점 높이는 양수다(evidence/fall-contact-audit.txt). 바닥 접촉 전 발끝 관통도 수정했다. Claude의 L/R 지지 다리 해석에는 혼동이 있어 결과를 그대로 물리 검증 판정으로 사용하지 않았다.


## 촬영 구도 검토 UI (2026-11-15)

- `/?v=red-guide`: 상단 01~10 구도 버튼으로 TV와 촬영 카메라를 함께 변경한다. 기본 필터는 머리맡 ToF·발치 ToF·천장 mmWave의 세 설치 위치를 포함하는 구도다. 두 ToF와 mmWave는 센서 3종을 의미하지 않는다.
- 공간 보기에서 주황색 촬영 카메라를 드래그하거나 오른쪽 슬라이더로 좌우·앞뒤·렌즈 높이·화각·시선 높이를 조절한다. 카메라를 클릭하면 촬영 화면으로 전환한다.
- 공간 보기의 오른쪽 미리보기는 촬영 화면, 촬영 보기의 오른쪽 미리보기는 전체 공간과 촬영 카메라 위치를 보여준다.
- 센서 포함·TV 크기·사람 크기·검토 상태 필터와 구도별 피드백 체크를 지원한다. 체크는 해당 브라우저의 localStorage에 저장한다. 수동으로 카메라를 이동하면 기존 구도의 검토 결과를 적용하지 않는다.
- `shots.html`: 현재 후보별 정상·난간 넘기·추락·바닥 캡처 비교. `references.html`: 근거 문헌과 영상 검토.
- 최근 탐색은 86,400개 격자 조합에 대한 프레임·경계 상자 충돌·센서 시선 검사를 수행했다. 카메라 수평 위치 또는 TV가 50cm 이상 다른 안을 선택했고, 높이만 다른 안은 중복 처리했다. 결과는 `evidence/search/results.json`, 탐색 구현은 `optimize-shots.js`에 있다.
- 1~5번은 사람·TV 균형 후보, 6~10번은 TV가 작아지는 배치 비교용이다. 일부는 카메라 높이 2.3~2.5m가 필요하다. 센서 위치의 프레임 포함과 화면 글자 판독/장비 식별은 별개다. 실제 삼각대 설치 공간·가구 간격·노출은 현장에서 확인해야 한다.
- `camera-placement.js`: 촬영 카메라 모델·드래그·실시간 상호 미리보기. `review-header.js`: 구도 선택·필터·검토 체크. `shots.js`: 현재 10개 후보.
- `exports/distinct-sensor-shots/`: 현재 후보의 캡처 40장. 다른 exports 하위 폴더는 이전 비교안과 작업 검증 캡처의 기록이다.

검증: 10개 구도 버튼의 카메라/TV 이동 및 센서 프레임 포함, 미리보기 전환, 드래그/슬라이더, 필터와 브라우저 체크 저장·복원, 페이지 JavaScript 오류 유무를 Playwright로 확인했다. 센서 시선 검사는 0.5초 단위 관절·몸통 근사이며 물리 시뮬레이션이나 실제 센서 판정 검증이 아니다.
