# 운영 개념 — 주간/야간 모드 (이탈 알림 · 보행 위험도) — 2026-07-06

> 아이디어: 시간대별로 같은 센서 스트림을 다르게 해석.
> **야간 = 침대 이탈 예측 → 간호사 알림 (환자 상태별 위험도)**,
> **주간 = 침대 밖 보행 실시간 분석 (baseline 대비)**.
> 결론: **가능하고 부품의 ~80%는 이미 있음.** 남은 건 정책층 + 알림채널.

## 같은 스트림, 다른 해석
`unified_reader.py` 가 한 스트림에서 보행(트랙 1010)+자세/이탈(점군 1020)을 동시 처리.
낮/밤은 **해석·액션**만 다름.

| | 야간 | 주간 |
|---|---|---|
| 관점 | 침대 이탈 = 위험(낙상·배회) | 침대 이탈 = 정상(보행) |
| 주 파이프라인 | 이탈 예측(LSTM)+자세전이 | 보행 z-score vs baseline |
| 액션 | 간호사 알림 | 대시보드 실시간 표시 |

## 🌙 야간: 이탈 예측 → 알림
**이미 있는 부품**
- 이탈 감지: `exit_seq` LSTM(임박) + `posture_probe` 전이(inside→edge(전조)→OUTSIDE(이탈))
- 위험도 3단계: 서버 `TH_CAUTION / WARNING / CRITICAL`
- 환자 특정: 침대 소속도(main_tid)

**"상태별 위험도" 매핑(안)**
- 환자 baseline 보행 불안정도↑(과거 z-score) → 이탈 시 위험도 상향
- 자세 전이 속도(급하게 일어남) → 낙상 가중
- 야간 기본 +1 (방향감각 저하)

**신규 필요**: ① 간호사 알림 채널(푸시/콜벨) — 유일한 진짜 신규, ② 야간 스케줄러

## ☀️ 주간: 침대 밖 → 실시간 보행 vs baseline
**이미 있는 부품**
- `unified_reader` 보행 지표(speed/sway/stride/freeze/cv) + baseline **z-score**
- 검증됨: 정상 total_abs ~2 vs 불안정 3.7→7.9

**주의(baseline 비교 고민에 대한 답)**
- 직진성 게이트 통과분만 쓰면 실시간도 z-score 안정 (WINDOW 6s 검증).
- baseline이 아직 얕음(1인·1세션) → 여러 날 축적 필요(`WARMUP_DAYS=14` 설계에 존재).

## 실제로 만들 것 (기존 위에 얇게)
1. **모드 스케줄러** — 병동 소등시간 기준 주/야 정책 전환
2. **상태 머신** — 침대안(취침)→전조(걸터앉기)→이탈→보행, 모드별 분기
3. **위험도 융합 규칙** — (환자 baseline) × (자세 전이) × (시간대) → 알림 등급
4. **간호사 알림 채널** — 신규 인프라(푸시/콜벨)
5. 대시보드 **모드별 뷰** — 야간=이탈경보, 주간=보행 게이지

## 정직한 제약
- 이탈 예측 F1 ~45 → 완벽 아님. 야간엔 **미탐<오탐** 방향(recall 우선) 튜닝.
- baseline 얕음 → 주간 비교 신뢰도엔 데이터 더 필요.
- 알림 **오탐 피로** 관리가 관건.
