# ROI 마스킹 비교 실험 — dataset_v4 (센서 1.5m, 6인), 2026-11-06

## 결론

- **기존 `TOF/ml/roi.py` 마스킹(`roi_py`)이 7종 모델 모두에서 정확도를 올렸다.** 마스킹 안 함(`none`) 대비 평균 +1.33%p다.
  - 시드 3개 × 7모델 = 21쌍 비교 중 19쌍이 이겼다.
  - 원시 RF(현재 최고 모델)는 88.20 → 88.95%(+0.76%p, 2/3 시드)다.
  - CNN 계열은 +1.0~2.4%p다.
- 사용자 결정(2026-11-06): **ROI 마스킹을 넣는다.**
  - 운영 반영(학습 입력·`predict_posture` 입력에 같은 마스크 적용, 새 모델 학습)은 별도 작업이다. 아직 하지 않았다.
- 실험은 시드 5개(42, 0, 1, 2, 3)로 계획했다. 사용자 요청으로 **시드 42, 0, 1 세 개에서 멈췄다**(35회 중 22회).
  - 아래 표는 모두 이 세 시드의 평균이다.
  - `none`만 시드 2도 끝났다(raw_rf 88.49, cnn 76.89). 비교에는 쓰지 않았다.

## 실험 설정

- 데이터: `TOF/dataset_v4`
  - 111세션, 짝 맞춘 프레임 24,232쌍
  - 정리된 값(상태 5·9 유효, 빈 칸은 3프레임까지 채움)
- 빈 침대 기준: 노트북 학습과 같은 `training_baseline.json`
  - 위치: `TOF/ml/incoming/2026-11-05/v4-150cm-6p-5seeds-6lE7WB/`
  - `없음` 빈 침대 3세션의 칸별 중앙값
- 분할: 사람 단위 6겹(S01~S06 leave-one-subject-out)
  - `없음` 빈 침대는 회차별로 나눈다.
  - 각 참가자 이름의 빈 침대는 그 참가자의 시험 묶음에 넣는다.
  - 노트북 `session_data.py` 규칙 그대로다.
- 모델 7종(노트북 `session_train.py`와 같은 하이퍼파라미터):
  - 원시 128거리: `raw_rf`(200그루, balanced), `raw_xgboost`(200, 깊이 4, hist), `raw_lightgbm`(200, 잎 15, min_child 5)
  - 3채널 CNN: `cnn`(AdamW 1e-3, wd 1e-3, 배치 128, 최대 60에폭, 내부 검증 macro-F1 조기 종료 10 → 고정 에폭으로 다시 학습)
  - CNN 특징 + 트리: `cnn_rf`, `cnn_xgboost`, `cnn_lightgbm`
- 마스크 적용 방법:
  - 제외한 칸은 원시 거리를 `-1`(측정 실패와 같게)로 둔다.
  - 빈 침대 기준에도 같은 마스크를 적용한다.
  - CNN 3채널(거리·기준 차이·유효 칸)은 마스크 뒤 값으로 다시 계산한다.
- Pi 재현 확인: 마스킹 없는 시드 42가 노트북 결과와 맞는다.
  - raw_rf 88.57%(노트북 5시드 87.86~89.27%)
  - raw_xgboost 86.39%·raw_lightgbm 82.56%(노트북과 같은 값)
  - cnn 79.76%(노트북 평균 78.30±1.27%)

### 비교한 마스크 변형

| 변형 | 정의 | 남는 칸 (tof1/tof2) |
|---|---|---|
| `none` | 마스킹 없음(현재 노트북 학습과 같음) | 64/64 |
| `roi_py` | 기존 `TOF/ml/roi.py`의 `on_bed(sensor, zone, distance)`를 프레임마다 적용한다. 칸 방향과 실제 거리로 닿은 점을 계산해 침대 폭 밖·바닥이면 제외한다(동적 마스크). | 프레임당 평균 약 1.5칸 제외(유효 칸 약 103개 중) |
| `cols` | 각 센서의 맨 왼쪽·오른쪽 열(0, 7열)을 뺀다(정적) | 48/48 |
| `base_valid` | 빈 침대 기준이 유효한 칸만 남긴다(정적) | 56/53 |
| `base_off` | `base_valid`에 더해 같은 줄 중앙값보다 300mm 넘게 먼 칸(바닥·벽)을 뺀다 | 56/51 |
| `act2` | 학습 묶음(시험 사람 제외)의 사람 자세 프레임 중 기준보다 100mm 넘게 가까워진 비율이 2% 이상인 칸만 남긴다(겹마다 따로 계산) | 약 49~52/53 |
| `act5` | 위와 같고 기준은 5% | 약 39~42/52 |

- `roi.py`는 예전 설치 기하를 쓴다(높이 1.2m, 수직 기준 기울기 40°/60°, 센서 간격 2.12m, 침대 폭 0.95m).
  - 1.5m 설치의 실제 각도는 재지 않았다.
  - v4 빈 침대 기준으로 높이·각도를 역산해 보았다. 높이를 1.5m로 고정해도 칸별 오차가 160~230mm라 기하가 맞지 않았다(dataset_v3에서는 15~22mm로 맞았다).
  - 그래서 v4에 맞춘 '실측 기하 ROI'는 만들 수 없었다.
  - `roi_py`의 이득은 정확한 침대 경계보다 '먼 거리·가장자리 이상값 몇 칸을 프레임마다 지우는 효과'로 해석하는 것이 안전하다.

## 해석과 한계

- 이득은 작다. 원시 RF +0.76%p는 시드 간 흔들림(표준편차 약 1%p)과 비슷한 크기이고, 3시드 중 2번만 이겼다.
  - 그래도 7종이 같은 방향으로 움직였다. 특히 CNN 계열 4종은 3시드 모두 이겼다. 그래서 '넣어서 손해는 없고 약간 좋아진다'고 본다.
- 시드를 3개만 돌렸다(계획 5개). 원시 XGB·LGBM은 시드와 무관하게 결과가 같아 사실상 1회 값이다.
- `roi.py`는 예전 설치(1.2m) 기하라 1.5m 설치의 침대 경계와 정확히 맞지 않는다.
  - 운영에 넣을 때 기하 숫자를 v4에 맞게 바꾸면 결과가 달라질 수 있다. 바꾸면 다시 평가해야 한다.
  - 설치 각도를 재면 기하 역산을 다시 시도할 수 있다.
- 빈 침대 기준은 `없음` 세션으로 만들었다. 이 세션들은 회차별로 시험 묶음에도 들어간다(노트북 평가와 같은 조건).
- `act2`·`act5`의 칸 선택은 겹마다 학습 묶음으로만 계산했다(시험 사람 정보 누설 없음).
- 6명, 검정 옷 1명(S06), 각도 미측정, 정리된 입력이라는 dataset_v4 자체의 한계는 그대로다.

## 운영 반영 시 할 일 (아직 안 함)

1. 학습 입력에 `roi_py` 마스크를 적용해 최종 모델을 다시 학습한다.
   - 대상: 전체 6인 + 빈 침대, 원시 RF, 시드 42.
   - 마스크 칸은 `-1`, 기준도 같은 마스크를 쓴다.
2. `TOF/ml/predict_posture.py`의 모델 입력에도 같은 `roi.on_bed` 마스크를 적용한다. 학습·운영 입력을 같게 한다.
3. 모델 묶음 `preprocessing.json`에 'ROI = roi.py 동적 마스크(기하 값)'를 기록한다.
4. 서버 재실 판단(`ROI_MAX_MM` 거리 제한)과 화면은 바꾸지 않는다. 이 실험은 자세 모델 입력만 다룬다.

## 재현

실험 코드와 결과는 `TOF/ml/roi_experiment_20261106/`에 있다.

- `run_roi.py <v4> <변형> <시드> <출력.json>` — 한 변형·한 시드 6겹 평가. 7종 모델을 모두 돌린다.
- `queue.sh` — 전체 대기열. 결과가 있으면 건너뛴다.
- `aggregate.py` → `summary.json`, `tables.py` → `tables_output.md`(이 문서의 표).
- `res/` — 변형·시드별 정확도(json)와 예측 배열(npz).
- `tl/` — `minhyuk` 브랜치 `camera-pose/src/bed_pose/tof_learning/`의 데이터·모델 코드 사본.
- 실행 환경:
  - Pi 5, `.venv`(torch 2.14.1 CPU, scikit-learn 1.9.1)
  - xgboost 3.4.1·lightgbm 4.7.0
  - 3스레드, 한 회 약 24분
