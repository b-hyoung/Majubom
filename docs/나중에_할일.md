## 1. ToF 빈 침대 기준값 자동 재캘리브레이션

기록: 2026-10-08

### 현재 상태
- 빈 침대 기준값(`server/tof_baseline.json`)은 수동으로만 바뀐다.
  `POST /tof/calibrate`를 호출할 때와 서버 시작 시 파일을 읽을 때뿐이다.
- 수동 버튼은 간호사 대시보드가 아니라 예전 상태 페이지(`:5001/`)에만 있다.
- 캘리브레이션은 **한 프레임**을 그대로 저장한다. 측정 잡음이 기준값에 들어간다.
- 2026-10-08 16:26 새 설치 위치(ToF 1.2m·하향 20°)에서 처음 캘리브레이션했다(유효 칸 tof1 20, tof2 25).

### 왜 필요한가
베개·이불 위치가 바뀌면 기준값과 실제 빈 침대 모양이 달라져 재실 판정이 틀어진다.

### 위험: "빈 침대로 판단될 때마다" 다시 잡으면 안 된다
- 마른 환자가 이불을 덮고 가만히 누워 있어 "빈 침대"로 오판된 순간 갱신하면,
  환자 모양이 기준값에 흡수되어 이후 계속 "빈 침대"로 나온다(가장 위험한 놓침).
- 반대로 이불이 뭉쳐 "사람 있음"으로 오판되면 갱신 조건이 영영 충족되지 않아 오판이 이어진다.

### 채택한 조건 (사용자 결정, 2026-10-08)
**ToF가 "빈 침대"이고, 동시에 mmWave가 환자를 침대 밖에서 추적하고 있거나 방에 아무도 없을 때만 갱신한다.**
두 센서가 모두 동의해야 하므로 ToF 단독 오판으로 환자가 기준값에 흡수되는 것을 막는다.

### 함께 검토할 보조 조건
- 빈 침대 판정이 일정 시간(예: 10분) 이상 이어지고 거리값 변화가 거의 없을 때만.
- 한 번에 교체하지 않고 기존 값에 서서히 섞는다(지수 이동평균). 수십 초 구간의 중앙값을 쓴다.
- 기준값과 차이가 너무 크면(침대 이동·물건 올려둠) 자동 갱신하지 않고
  간호사 화면에 "재캘리브레이션 필요"를 표시한다.
- 언제·왜·얼마나 바뀌었는지 모두 기록한다(연구 데이터 해석용).

### 선행 조건
- [x] mmWave 설치 확정: **높이 2.5m(실측)·하향 50°**(사용자 확인, 2026-10-08). cfg `AOP_diag_2m5_d50.cfg`의 `sensorPosition 2.5 0 50`과 일치.
- [ ] 각도 확정 후 mmWave 침대 영역(`mmWave/send_mmw.py`의 `BED_X`/`BED_Y`) 재튜닝.
      이게 맞아야 "환자가 침대 밖에 있다"는 mmWave 판단을 믿을 수 있다.

### 구현 (2026-10-13)
- [x] 자동 재캘리브레이션 `server/tof_autocal.py` + tof_server `_autocal_worker`: ToF 이탈 확정 10초 뒤, 레이더가 추적 중이고 그 사람이 이탈 후 0.3m 이상 움직였으면 다음 5초 칸별 중앙값으로 갱신(흔들린 칸·유효 부족 칸은 예전 값). 30cm 넘게 바뀐 칸이 16칸 초과면 적용하지 않고 activity_log '빈 침대 기준 재확인 필요'. 이력 server/tof_baseline_history.jsonl(이전·새 값), 최근 결과 /tof/presence의 baseline_auto. 레이더 침대 영역(BED_X/Y) 재튜닝 대신 '이탈 후 0.3m 이동'으로 침대 위 누운 환자 흡수를 막는다(사용자 결정).

## 3. mmWave 높이 기반 낙상 판정 기준 재설정

기록: 2026-10-08. 현장 측정: **침대 매트리스 윗면(눕는 면) 높이 = 바닥에서 37cm.**

### 현재 동작
- mmWave는 프레임마다 추적 중인 사람의 **높이 위치 값(`posZ`)**을 보낸다. 높이 *변화*가 오는 것이 아니다.
- `mmWave/send_mmw.py`가 6초 구간마다 `height_drop = max(z) − min(z)`를 계산한다(시간 순서는 보지 않음).
- `server/mmw_logic.py`의 `HEIGHT_DROP_FALL = 1.2`(m)를 넘으면 기준선과 관계없이 즉시 "위험"으로 판정한다.

### 문제
- `posZ`는 머리 높이가 아니라 **추적 점들의 중심(대략 몸통)** 높이일 가능성이 높다. 서 있을 때 약 1m 안팎이면
  바닥에 쓰러져도 차이가 1.2m에 못 미쳐 **실제 낙상에서도 이 규칙이 울리지 않을 수 있다.**
- 반대로 37cm 침대에 눕는 동작도 높이가 크게 떨어진다. 기준을 낮추면 정상적으로 눕는 동작과 구분해야 한다.
- 쓰러지면 추적(track)이 끊기는 경우가 많다(발표 노트). 끊기기 직전 값만 남는다.
- TLV 1012(track height)는 파싱 목록에만 있고 쓰이지 않는다. 실제 높이 추정에 더 적합한지 확인 필요.

### 2026-10-12 변경(사용자 결정)
- 낙상 규칙을 **몸 높이(최근 1초 z 중앙값, `low_z`) < 0.4m**로 바꿨다(`server/mmw_logic.py` `FLOOR_FALL_Z`). 이전 height_drop은 기록용.
- 아래 실험으로 침대 위 누움 오탐과 쓰러진 뒤 추적 유지 시간을 확인해야 한다.

### 실험 계획 (사용자가 직접 수행, 안전 매트 사용)
- [ ] 자세별 `posZ` 기록: 서 있음, 걷기, 침대에 걸터앉음, 침대에 누움(37cm), 바닥에 앉음, **바닥에 쓰러짐(모의 낙상)**.
- [ ] 각 동작에서 `posZ` 값의 범위, 쓰러진 뒤 추적이 유지되는 시간, TLV 1012 값 비교.
- [ ] 결과로 낙상 기준을 다시 정한다. 후보: 바닥 근처 높이(예: 침대 높이 37cm보다 낮음)에서 일정 시간 머묾 +
      직전 높이에서의 급격한 하강(시간 순서 반영). 정상적으로 침대에 눕는 동작은 ToF "침상에 있음"으로 구분한다.
- [ ] 4장의 낙상 의심 규칙(걸터앉음 → 이탈 → 보행 없음 + 높이 급락)과 함께 구현.
- mmWave 설치 확정(2026-10-08, 사용자 실측): **높이 2.5m·하향 50°.** 설치가 바뀌면 높이 값도 다시 확인한다.

- 레이더 평면도 뒤틀림: ToF가 재실/몸 위치를 아는 순간의 레이더 좌표를 모아 레이더→방 회전·이동을 자동 맞춤(수동 각도 입력 대신).
- 탁자·TV 등 가구: 레이더 track이 며칠간 지나간 곳 = 다닐 수 있는 바닥, 한 번도 안 지나간 곳 = 가구/벽으로 자동 지도화.
  현재 사람 추적 펌웨어는 정지 물체를 지우므로 가구를 직접 '보는' 방식은 어렵다(하드웨어·펌웨어 한계).

## 레이더 낙상: 의자에 털썩 앉기 구분 (2026-10-12)

- 사용자 기준으로 어르신이 의자에 털썩 앉는 것도 낙상이지만, 높이만으로는 보통 앉기(라이브 80%→40% 0.2~0.4초)와
  빠르게 주저앉기(0.38초)가 구분되지 않아 `mmWave/fall_detect.py`에서 의자 높이 규칙을 뺐다(라이브 오탐 12회).
- 어르신 실측 속도·충격(하강 직후 정지 패턴, 레이더 속도 velZ)으로 다시 판단할 것. 지금은 바닥 높이(25%)까지 1초 안 하강만 즉시 낙상.
- 실험실처럼 여러 명이 있으면 누구든 판정한다 → ToF가 침상 이탈을 본 순간 그 자리 추적을 환자로 지정하는 방식 검토.
