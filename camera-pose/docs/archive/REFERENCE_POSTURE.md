# 기준 자세 비교 판정 · 실험용

> **과거 이력/호환 자료:** 본문에서 말하는 현재·미구현·다음 작업은 작성 당시 기준입니다. [현재 상태](../PROJECT_STATUS.md) · [문서 목차](../README.md).


2026-10-28. 현재 실행에서 실제 자세명을 출력하는 첫 분류 기준선이다. 사전학습된 범용 침대 자세 분류기는 아니다. 신경망 가중치 학습을 추가하지 않고 **운영자가 라벨을 지정한 기준 예시를 저장하는 지도 방식(최근접 기준 비교)**을 사용한다. 학습 자료가 전혀 없이 정확도가 검증된 판정기를 제공한다는 뜻은 아니다.

## 기준 등록 없는 자동 판정 · 2026-10-28

사용자가 수동 기준 등록 없이 자동 판단하도록 요청해 실제 카메라/영상의 기본을 실험용 2D 기하 규칙으로 변경했습니다. 침대 영역 지정 후 바로 누움·옆으로 누움·걸터앉음 또는 보류를 출력합니다. 기본 사선·측면 배치와 위 시점 설정의 차이가 있으며 위 시점은 걸터앉음을 판정하지 않습니다. 임계값·정확도는 아직 미검증입니다. 두 시점은 시간/대상 게이트와 양쪽 라벨 일치로 결합합니다. 기준 등록 화면은 기본 흐름에서 제거하고 이전 기록 호환은 유지합니다. [사용법·가정·한계](../design/AUTOMATIC_POSTURE.md).


## 실행과 사용

기존처럼 `python -m bed_pose live`로 실행한다. 카메라나 저장 영상을 연결하고 침대 영역을 지정한다. 오른쪽 자세 카드의 **실험용 자세 기준 등록**을 펼친다.

1. 고정 카메라에서 한 사람의 해당 자세와 관절이 보이는지 확인한다.
2. 등록할 실제 자세(바로 누움/옆으로 누움/걸터앉음)를 고르고 확인 체크 후 **현재 프레임 등록**을 누른다.
3. 나머지 두 자세도 각각 등록한다. 등록된 현재 프레임 ID를 근거로 사용하며 이력이 만료되면 다시 요청한다. 같은 라벨은 교체되고 다른 라벨 기준과 설정 차이보다도 비슷한 예시는 거부한다.
4. 세 기준이 있으면 이후 프레임에서 자세명 또는 보류 사유와 거리 값을 표시한다. 측정 시작 전에도 판정한다. 저장 영상이 일시정지 중이면 새 프레임을 재생할 때 새 기준으로 판정한다.
5. 측정을 시작하면 입력별 원본 기록에 판정을 남긴다. 기준/실험 설정 변경은 측정과 그룹 진행을 종료한 뒤 한다.

어깨·골반·무릎·발목의 좌우 8관절이 모두 화면 안에 있어야 한다. 가려지면 억지로 채우지 않고 보류한다. 카메라 이동, 입력 재연결, 다른 참가자/시점·큰 배치 변경 시 기준을 지우고 다시 등록한다. 기준은 현재 입력 연결에 보관하며 새 연결/앱 재실행에 자동 복원하지 않는다. 측정 manifest에는 재검사용 스냅샷을 남긴다. 기준 사진은 저장하지 않는다. 다른 자세의 기준을 등록하려고 계획 측정의 목표를 바꾸는 방식은 사용하지 않는다.

기준을 등록할 실제 자세 사례가 없으면 판정 기준도 만들 수 없다. 현재 방식은 운영자의 잘못된 라벨이나 잘못 추정된 관절을 자체적으로 정답으로 교정하지 못한다.

## 특징·판정

- COCO17 중 좌우 어깨/골반/무릎/발목의 좌표를 사용한다. 0 좌표와 결측을 구분하고 미출력/비정상/화면 밖 좌표는 사용하지 않는다.
- 골반 중심으로 평행이동하고 어깨 중심–골반 중심 길이로 크기를 정규화한다. 회전은 정규화하지 않아 해당 시점의 몸통 방향을 유지한다.
- 이 8관절의 16성분에 침대 사각형 내 골반 상대 x/y를 더한 18차원 특징을 만든다. 물리 좌표·3D 위치는 아니다.
- 현재 벡터와 라벨별 기준 벡터의 RMS 거리를 비교한다. 최소 거리와 1·2위 거리 차이 조건을 모두 만족해야 실험 예측을 출력한다.
- 초기 UI 값인 허용 거리 0.35와 최소 차이 0.10은 **검증 전 실험 설정**으로 편집 가능하다. 성공률/신뢰도/권장 프로토콜이 아니다. 현재 프레임만 사용하며 시간 평활화는 없다.
- 목표·정답·센서·파일명을 예측 특징으로 받지 않는다. 등록 라벨은 `operator_reference_not_verified`로 출처를 남긴다. 실제 수행 정답은 계속 null이다.

등록 미완료, 핵심 관절 부족, 영역/영상 크기 불일치, 미검출·대상 혼동·추적 보류, 거리 초과 또는 작은 1·2위 차이는 label=null로 보류한다. 보류 중 직전 자세를 현재 자세로 유지하지 않는다. 영역을 수정하면 예전 기준은 보류하고 새 영역에서 다시 등록할 때 기준 목록을 새로 시작한다. 카메라만 움직여 같은 영역 좌표가 유지되는 경우는 자동 감지할 수 없다.

**한계:** 서 있음·엎드림 등 등록하지 않은 자세도 특징이 가까우면 잘못 분류될 수 있다. 거리 거부는 완전한 범위 밖 자세 탐지가 아니다. 가림 속 관절의 잘못된 추정, 좌우 뒤집힘·체형 차이·다른 옆누움 방향·카메라 변화에도 취약하다. 좌표가 있다는 것만으로 관절 정확도는 보증되지 않는다. 한 라벨당 예시 한 개의 기준선이며 실제 분류 품질을 확보한 최종 모델이 아니다.

## 두 카메라

각 입력에 같은 세 자세의 기준을 등록하고 대상 선택/양쪽 동일인 지정·허용 수신 시각 차이를 설정한 뒤 그룹 측정을 시작한다. 오른쪽 **두 시점 판정 상태**에 통합 실험 판정과 입력별 근거가 표시된다.

양쪽 관측이 유효하고 잠정 추적 구간의 운영자 확인이 해당 두 수신 시각 이전에 있으며, 최신 수신 시각 차이가 설정 안에 있어야 한다. 오래된 관측은 해당 입력 추적의 max_gap_ms 설정으로 보류한다. 최신 프리뷰에서 받은 두 거리 벡터를 각 카메라 허용 거리로 나눠 동일 비중 평균한다. 최솟값≤1 및 정규화한 최소 차이 조건을 적용한다. 한쪽에서 근소한 차이로 보류한 경우에도 양쪽 정보를 합쳐 후보를 정할 수 있지만 핵심 좌표/추적/기준 자체가 없으면 통합도 보류한다.

이는 수신 시각 허용 범위의 최신 프레임 결합이며, FIFO 일대일 정렬·동일 노출·3D 융합이 아니다. 현재 화면에는 같은 입력 프레임이 반복 사용될 수 있다. 저장 영상 두 개는 공통 미디어 오프셋 미확인으로 통합을 보류한다. 두 시점 결합의 우월성이나 실제 동일인 판별 성공은 검증하지 않았다.

## 기록·재검사

- 입력별 manifest의 reference_posture_profile에 버전·실험 설정·기준 특징·수동 라벨 출처·원본 선택 프레임/시각을 저장한다. posture_classifier에는 프로필 해시를 포함한 ID를 기록한다.
- 프레임의 posture_assessment에 라벨·원인·라벨별 거리와 experimental=true를 기록한다. posture_prediction은 예측 시 experimental/해당 라벨, 나머지는 held/null이다. 기준 미설정 실행은 기존 not_implemented/null 형식으로 유지한다.
- live-inspect는 기준 프로필과 해당 프레임에서 판정과 거리를 재계산한다. 이전 프로필/기록은 계속 지원한다.
- 종료 후 그룹은 원본 검사·FIFO 정렬·fusion_inputs 생성 뒤 **posture_predictions.jsonl**을 추가 생성한다. 이 파일은 저장된 일대일 프레임 쌍과 원본의 시점별 거리/기준·시간별 동일인 지정으로 통합 결과를 재계산한다. 그룹 manifest에 해시·카운터를 기록하고 group-inspect가 다시 계산해 대조한다.
- 실시간 최신 쌍과 종료 후 FIFO 쌍은 선택 방식이 달라 결과가 다를 수 있다. 그룹 저장 파일은 후자의 결과다. 원본/정렬 ID로 추적한다. 둘 다 실제 촬영 동기화는 아니다.
- fusion_inputs의 기존 posture_prediction은 특징 생성 단계의 not_implemented 표시를 유지한다. 실제 통합 예측은 별도 posture_predictions 파일에 있다. 기준 미설정 그룹에서는 이 파일을 만들지 않는다.
- 계획 목표는 모델 특징·거리 비교·동일인 확인 게이트에 넣지 않고, 기준 수동 라벨과도 별도로 관리한다. 검증된 실제 자세 정답이나 외부 센서 값을 만들지 않는다.

## 검증 범위

제어한 합성 관절에서 세 라벨, 정보 부족/모호/거리 초과, 영역 변경, 잘못된 설정, 입력별 판정 기록·재계산, 두 시점 시간/재확인/관측 나이/충돌 보류와 기록 변조 거부를 검사한다. Chromium에서 기준 지우기→세 기준 등록→자세명 전환→거리 표시와 좁은 화면을 확인한다. 실제 사람의 정확도 수치는 없다. 실제 자료에서 오분류/보류·자세별 성능을 확인하고 이후 규칙/학습 모델과 비교해야 한다.

검사 결과: 전체 개발 검사 **140개 통과(67.519초)**. 이후 관련 기준 판정 검사 9개와 Chromium 등록/자세 전환/격자 보기/390px 화면 검사를 추가 확인했다. 합성 관절을 통제한 검사이며 실제 인체 자료의 정확도 측정은 아니다.
