# 관절 추정 실패 대응: 원문 조사·장비 비교·적용

2026-11-01 사용자 요청에 따라 기존 문헌 목록을 출발점으로 9편의 공개 원문과 공식 SDK/구현을 다시 확인했습니다. 전 세계 논문을 빠짐없이 조사했다는 뜻은 아닙니다. 원문에서 확인한 방법, 이 프로젝트의 응용 구현, 이 노트북에서 관찰한 결과를 구분합니다.

## 현재 적용한 변경

`pose/recovery.py`, `pose/browser_gpu.py`, `pose/person_guard.py`, GPU bridge에 반영했습니다.

1. 완전 미검출뿐 아니라 공통 17관절 중 관측 점수가 부족하거나 어깨·골반이 부족해도 재탐색합니다. 초기 기준은 visibility 0.5, 양호 기준 14/17 및 몸통 네 점입니다. 이 기준은 정확도 확률이나 학습으로 최적화한 값이 아닙니다.
2. 정상 추적은 VIDEO 추론 한 번을 유지하되 새 사람 확보와 약 1초마다 독립 IMAGE 검출로 확인합니다. 불량 입력은 입력 시각 기준 500ms마다 최대 한 가지 방향/확대 영역을 추가 검사합니다. **추가 한 번은 MediaPipe의 예산**이며 아래 사람 검증 모델의 실행은 별도입니다. 침대 영역이나 최근 관절 경계는 탐색 후보이며 재실의 증거가 아닙니다.
3. 재탐색은 별도 IMAGE GPU task를 재사용합니다. 실패할 때마다 기존 VIDEO task를 재생성하던 지연과 tracking ROI 오염을 줄입니다. 좌표계 변경·재확보 또는 확인된 추적 소실 때 초기화하며, 이미 거부된 허상 때문에 초기화를 계속 반복하지 않습니다. HTTP와 private pipe는 GPU 실행 순서를 공유합니다.
4. crop XY·폭 기준 상대 Z·회전한 world XY를 원본 카메라 기준으로 되돌립니다. 해부학적 좌우 ID와 원본 frame_id/수신 시각은 유지합니다. 현재 전체 영상에 관절 여섯 점·몸통 세 점의 근거가 있을 때만 crop을 제안하며 crop의 주 추론도 IMAGE입니다. 약 1초 주기로 전체 영상 근거가 사라지면 crop 가설을 만료합니다. 최근 관절은 1초 이내 탐색 영역에만 쓰며 과거 좌표를 현재 관측으로 복사하지 않습니다.
5. 더 멀리 있는 다른 사람으로 갑자기 전환하는 재탐색 후보를 제한합니다. 기존에 몸통 세 점 이상이 있으면 몸통 중심의 영상 정규 좌표 이동이 0.2를 넘는 후보를 거부합니다. 동일인 인증을 제공하는 것은 아닙니다. 다중 인원 모드에서는 crop 보완을 사용하지 않습니다.
6. `WinError 10053` 등 로컬 GPU 통신 오류는 HTTP 재연결 한 번 후, 필요하면 같은 GPU task의 private stdio 경로로 복구합니다. 내부 SDK 시각은 다시 증가시키고 외부 관측은 한 프레임으로 유지합니다. 실제 GPU 추론 오류는 통신 복구 성공으로 숨기지 않습니다.
7. 카메라 패널에 관절 관측 수·부분 관측·영역/방향 보완·추론 연결 복구 이력 및 입력 오류를 표시합니다. 후보의 `inference_recovery`에도 근거를 보존합니다.
8. 이 노트북에는 **명시적으로 설정한** YOLOX-m HumanArt 사람 검증을 추가했습니다. 관절 모델을 교체하지 않고, 별도 프로세스의 ONNX CUDA에서 현재 방향과 반대 방향을 최대 두 번 검사합니다. 최대 500ms 캐시이며 몸통 중심과 관절 경계의 절반 이상을 지지하는 사람 상자가 필요합니다. 현재 침대 근접 촬영에서는 영상 면적의 **8% 이상**인 검출 상자만 허용합니다. 이 값은 논문/학습에서 얻은 보편 임계값이 아니며 작은 사람·멀리 있는 사람·일부 가림도 보류될 수 있습니다. 사람 미확인은 빈 침대/이탈 확정으로 사용하지 않습니다. GPU나 검증 프로세스가 실패하면 오류를 내며 CPU/성공으로 바꾸지 않습니다.

침대 수평 정렬·3D 표시 평활화·기존 MediaPipe/CLIP·6자세 판정·미검증 데이터 저장 차단은 유지합니다. 침대 영역 힌트는 기존 분석 영역을 자동 등록하지 않으며 정답 라벨을 설정하지 않습니다.

### 빈 침대 허상과 실제 GPU 복구 검사

실시간 확인에서 빈 침대의 개 얼굴 이불 무늬가 회전/확대/VIDEO 추적에서 사람으로 출력되는 회귀를 발견했습니다. 독립 IMAGE 확인만 추가한 중간 버전도 흐려진 영상에서 간헐적으로 실패했고, 당시 40회 상태 조회 중 B 18회에 후보가 남았습니다. 이 중간 버전을 해결 완료로 취급하지 않습니다.

최종 사람 검증을 적용한 뒤 육안 확인한 빈 침대 사진 세 장을 각 200회 반복했을 때 사람 후보는 0회였습니다. 실제 두 카메라를 약 50초 동안 0.5초 간격으로 조회한 100회에서도 양쪽 모두 후보 0회였습니다. 그 구간 처리율은 A 약 29.3–30.9, B 약 24.7–30.7 FPS였습니다. 이는 제한된 장면 확인이며 일반 오탐률이나 향후 모든 영상의 성능이 아닙니다. 사진 반복과 실제 프레임/조회 수를 구분합니다.

보이는 사람이 있는 사진에서 GPU 추론을 실제 완료한 뒤 HTTP 응답 한 번, 이어 두 번을 고의로 잃게 했습니다. 각각 재연결 및 같은 GPU의 private pipe로 관절 15점을 반환했고 원본 관측 시각·frame_id와 새 내부 SDK 시각을 유지했습니다. 사람 검증 모델도 단순 provider 설정 외에 시작 시 실제 CUDA 실행 노드를 확인합니다. 이 검사는 실제 관절 좌표 정답/자세 정확도 평가가 아닙니다.

근거: 로컬 `outputs/pose-recovery-gpu-smoke-with-person-guard/report.json`, `outputs/live-pose-recovery-guard-observation.json`. 원본 사진과 카메라 토큰은 Git에 올리지 않습니다. 이 검사로 빈 침대 센서 baseline이나 학습 정답을 저장하지 않았습니다.

### RTMPose GPU 비교

전용 `Majubom/.venv-pose`에서 RTMLIB 0.0.16, ONNX Runtime GPU 1.23.2와 CUDA 12/cuDNN 9 DLL을 사용했습니다. YOLOX-tiny+RTMPose-s, YOLOX-m+RTMPose-m에 0/90/270/180° 입력을 비교했습니다. CUDA provider 설정만 확인한 것이 아니라 초기 s 비교의 실제 실행 노드 로그에서 두 신경망의 CUDA 실행을 확인했습니다. 일부 shape 연산은 CPU에서 실행됩니다.

어려운 옆누움 두 사진에서는 두 크기 모두 신뢰도 초기 기준 0.5에서 관절 10개·몸통 3점의 비교 기준을 충족하지 못했습니다. 정상 사진 일부에서는 m의 관절 수가 늘었지만 새 모델의 실제 관절 오차 개선 근거는 없습니다. SimCC score와 MediaPipe visibility는 같은 확률이 아니므로 단순 관절 수로 정확도 순위를 만들지 않습니다. 이 결과로 기본 MediaPipe를 RTMPose로 자동 교체하지 않았습니다.

근거: 로컬 `outputs/rtmpose-probe.json`, `outputs/rtmpose-rotations.json`, ORT 노드 프로파일. RTMPose는 2D 결과이며 MediaPipe world 좌표나 실제 깊이를 만들지 않습니다.

## 재실행

카메라 실시간 환경과 ToF 학습 환경을 바꾸지 않는 별도 비교 환경입니다.

```powershell
.\training\Setup-PoseBenchmarks.ps1 -PrepareModels
& ..\.venv-pose\Scripts\python.exe tools/pose_candidates.py compare '사진A.jpg' '사진B.jpg' --mode balanced --rotations --out outputs/my-pose-comparison
# 침대 근접 촬영용 사람 검증을 명시적으로 설정(작은 대상 보류 조건):
.\training\Setup-PoseBenchmarks.ps1 -PrepareModels -EnablePersonGuard -MinimumPersonArea 0.08
# 실제 MediaPipe GPU에서 빈 장면과 응답 소실을 검사:
python tools/check_pose_recovery.py --negative-image '빈장면A.jpg' '빈장면B.jpg' --positive-image '사람있는사진.jpg' --out outputs/my-gpu-check
# 같은 카메라의 등장/소실/재등장 정지영상 연결 검사도 할 때:
```
