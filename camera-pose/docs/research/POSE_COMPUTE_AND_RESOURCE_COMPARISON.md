# 스켈레톤 기술의 연산 부담 및 실행 조건 비교

> **작성: 2026-10-26 · 성격: 기술 선정용 비교 참고자료 · 자체 실험 결과 없음**<br>
> MediaPipe Pose Landmarker, Ultralytics YOLO Pose, RTMPose/MMPose의 실행 및 추가 학습 부담을 비교합니다. 이 문서는 **기술의 우열이나 채택 순위를 결정하지 않습니다**.

## 1. 범위와 해석 원칙

- **개발 실행 조건과 프로젝트의 최종 기술 선정은 별개입니다.** 사용자의 현재 컴퓨터 모델이나 부품 사양을 선정 제한으로 두지 않습니다.
- **AI 추론의 실행 위치·방식은 미정**입니다. 특정 실행 위치를 전제하지 않습니다.
- 아래에 표시한 수치는 **제작사 또는 논문의 한정된 벤치마크**입니다. 우리 침대 영상의 관절 정확도·실시간 처리 결과·최소 요구 사양을 뜻하지 않습니다.
- 모델·입력 크기·추론 엔진·검출기 포함 여부·전후처리·동시 실행 수가 다르면 처리 시간이 달라집니다.
- 추론과 **모델 자체의 추가 학습**, 추출 관절을 사용하는 **별도 자세 분류기 학습**은 다른 작업입니다.
- 모델별 미확인 지표는 추정값으로 채우지 않습니다.

## 2. 기술별 처리 구조와 자원 부담 요인

| 기술 | 기본 처리 구조 | 구성별 부담 변화 | 추가 학습·개발 시 고려 |
|---|---|---|---|
| **MediaPipe Pose Landmarker** | 인체 검출 + 랜드마크 추정의 번들, 기본 33점 | Lite / Full / Heavy 모델 종류, 입력 모드, 검출·추적 재실행, 선택적 분할 마스크 | 공식 Pose Landmarker 안내는 기성 모델 추론 중심. 관절 모델 자체의 맞춤 학습 절차는 별도 확인 필요 |
| **Ultralytics YOLO Pose** | 사람 영역과 키포인트를 출력하는 pose 모델 | 모델 계열·크기(n/s/m/l/x 등), 입력 크기, 인물 수, 전·후처리 및 내보내기 런타임 | 사용자 정의 키포인트 데이터셋을 사용한 학습 경로 제공. 학습 시 데이터량·배치 크기·모델 크기·학습 전략 확인 |
| **RTMPose / MMPose** | 일반적인 top-down 구성은 사람 검출기 + 관절 추정기 | 검출기 종류, RTMPose 모델 크기(t/s/m/l 등), 검출 주기, 추적·후처리, 입력 크기 | 모델·데이터셋·학습 설정을 분리해 관리. 검출기 및 관절 모델의 학습 범위를 명시 |
| **MoveNet (비교 대안)** | SinglePose 17점 추정 | Lightning / Thunder 등 모델 변형 | 선택한 버전의 학습·배포 지원을 별도 확인 |

**이 표만으로 어느 모델이 더 빠르거나 정확하다고 결론 내리지 않습니다.** 특히 MediaPipe의 추가 랜드마크 개수와 YOLO/RTMPose의 기본 COCO 17점은 곧바로 계산량 또는 정확도의 비교 척도가 되지 않습니다.

## 3. 공개 처리 시간 자료 — 서로 다른 실험으로 구분

### 3.1 Ultralytics YOLO26 Pose: 공식 모델별 예시

공식 [COCO-Pose 문서](https://docs.ultralytics.com/datasets/pose/coco/)에 게시된 **640픽셀 입력, CPU ONNX 경로**의 값입니다. 단위는 밀리초(ms)이며, 표의 시간은 그 문서에 명시된 벤치마크 조건에서만 해석합니다.

| 모델 | 파라미터 수(백만) | 공개 CPU ONNX 시간(ms) |
|---|---:|---:|
| YOLO26n-pose | 2.9 | 40.3 ± 0.5 |
| YOLO26s-pose | 10.4 | 85.3 ± 0.9 |
| YOLO26m-pose | 21.5 | 218.0 ± 1.5 |
| YOLO26l-pose | 25.9 | 275.4 ± 2.4 |
| YOLO26x-pose | 57.6 | 565.4 ± 3.0 |

- **출처:** [Ultralytics COCO-Pose 모델 표](https://docs.ultralytics.com/datasets/pose/coco/). 표의 모델 버전과 게시 값은 추후 갱신될 수 있으므로 재검토 시 확인 날짜·버전을 기록합니다.
- 이는 **YOLO26 계열의 한 사례**입니다. YOLO Pose 전체 버전의 보편적인 처리 시간이나 현재 프로젝트의 측정값이 아닙니다.

### 3.2 RTMPose: 원 논문의 검출기 포함 파이프라인 예시

[RTMPose 논문](https://arxiv.org/abs/2303.07399) **Table 12**의 RTMDet-nano(검출기) + RTMPose(관절 추정기) 구성에서 발표한 **CPU 추론 시간**입니다. 검출기 입력 320×320, 관절 모델 입력 256×192를 구분합니다.

| 파이프라인 구성 | 논문 보고 시간(ms) |
|---|---:|
| RTMDet-nano + RTMPose-t | 12.403 |
| RTMDet-nano + RTMPose-s | 16.658 |
| RTMDet-nano + RTMPose-m | 26.613 |
| RTMDet-nano + RTMPose-l | 36.311 |

- **출처:** [RTMPose 논문](https://arxiv.org/abs/2303.07399) Table 12 · [공식 MMPose RTMPose 프로젝트](https://github.com/open-mmlab/mmpose/tree/main/projects/rtmpose).
- 검출기를 포함한 **논문 설정의 경로**이며, 다른 검출기·사람 영역 제공 조건과 혼용하지 않습니다.
- **3.1의 YOLO 표와 실행 조건이 다릅니다.** 위 숫자만 비교해 RTMPose가 더 빠르다거나 YOLO가 더 느리다는 결론을 내릴 수 없습니다.

### 3.3 MediaPipe Pose Landmarker

[공식 Pose Landmarker 안내](https://developers.google.com/edge/mediapipe/solutions/vision/pose_landmarker)에서 **Lite / Full / Heavy** 모델 번들과 각 모델의 입력 형식, 33개 랜드마크 출력을 확인할 수 있습니다.

- 위 두 표와 **동일한 입력·측정 경로로 직접 비교 가능한 수치**는 이 문서에 확보하지 않았습니다.
- 따라서 MediaPipe에 임의의 시간 또는 다른 환경의 성능값을 채우지 않습니다.
- VIDEO와 LIVE_STREAM 모드는 호출·결과 수신 방식이 다릅니다. [공식 API](https://ai.google.dev/edge/api/mediapipe/python/mp/tasks/vision/PoseLandmarker)의 LIVE_STREAM 입력은 결과가 프레임마다 보장되지 않을 수 있으므로, 프레임 누락 기록이 필요합니다.

## 4. 추론과 학습의 구분

| 작업 | 실행 자원에 영향을 주는 항목 | 사전 확인 사항 |
|---|---|---|
| 사전학습 모델로 스켈레톤 추정 | 모델·입력 크기, 사람 검출, 추적, 전후처리, 프레임 처리 방식 | 실행 경로, 버전, 지연 및 결과 누락 |
| 관절 기반 자세 분류기 학습·추론 | 특징 개수, 분류기 구조, 학습 샘플 수 | 실제 자세 정답, 관절 누락 처리 |
| 관절 모델 추가 학습 | 가중치·모델 크기, 주석 데이터, 배치·학습 단계, 증강 설정 | 관절 좌표 정답, 검증 분할, 재현 가능성 |
| 영상 기반 별도 자세 분류 | 영상 크기·백본, 입력 빈도, 모델 추가 여부 | 영상별/구간별 자세 정답, 스켈레톤과의 비교 방식 |

**사전학습 모델을 사용하는 것과 관절 추정기를 재학습하는 것은 다릅니다.** 추가 학습의 필요성은 침대 영상에서 관절 실패가 실제 확인된 후 판단합니다.

## 5. 여러 모델을 연결하는 경우

| 구성 | 계산이 수행되는 부분 | 분석할 점 |
|---|---|---|
| YOLO Pose 단독 | 사람·관절 예측 | 전체 처리 시간, 관절 유효율 |
| RTMPose 단독(표준 검출기 포함) | 사람 검출 + 관절 추정 | 검출기와 관절 추정기의 기여를 구분 |
| MediaPipe 단독 | 제공 번들의 검출·추적·관절 추정 | 모델 종류와 실행 모드 기록 |
| YOLO **Detect** → RTMPose | YOLO 사람 검출 + RTMPose 관절 추정 | 검출기 교체 효과; **이중 관절 추정이 아님** |
| YOLO **Pose** + RTMPose | 각각의 관절 추정 경로 | 관절 계산 중복, 모델별 오류 보완 효과, 시간·메모리 누적 |
| 주 모델 실패 시 보조 모델 | 기본 경로 + 조건부 보조 추론 | 실패 판정 기준, 최악 지연, 전환 시 좌표 변화 |
| 스켈레톤 + 영상 자세 분류 | 스켈레톤 경로 + 영상 특징 모델 | 실제 자세 정답 기준 개선 폭과 추가 처리 부담 |

- 모델 둘을 순차 실행하면 일부 처리 시간이 더해질 수 있지만 **항상 개별 공개 시간의 단순 합과 같지는 않습니다**. 입력 공유·전처리 중복·병렬 실행·대기 시간이 영향을 줍니다.
- 검출 박스를 공유하는 구성과 모델별로 전체 검출을 수행하는 구성은 **서로 다른 실험**으로 기록합니다.
- 모델 결합이 단일 모델보다 유리한지는 실제 관절 정답·자세 정답에 대한 개선과 추가 지연을 함께 검증해야 알 수 있습니다.

## 6. 프로젝트에서 동일 조건으로 확인할 지표

기술 선정 시 아래 항목을 **모든 후보에 동일한 정의**로 기록합니다. 구체적인 평가 방법은 [스켈레톤 비교 실험 계획](POSE_BENCHMARK_PLAN.md)을 따릅니다.

| 평가 대상 | 기록 항목 | 비교 시 유의점 |
|---|---|---|
| 스켈레톤 인식 | 사람 미검출, 관절별 결측·좌우 오류·좌표 오차(PCK 등) | 실제 관절 정답이 없으면 정확도 계산 불가 |
| 추론 처리 | 단계별 처리 시간, p50/p95, 처리량, 건너뛴 프레임 | 저장 영상 처리 시간과 실시간 end-to-end 지연 구분 |
| 연속 안정성 | 프레임별 미검출 지속, 정지 구간 좌표 흔들림 | 실제 움직임과 관절 흔들림 구분 |
| 자세·이벤트 결과 | 자세별 F1, 판정 불가율, 이탈·복귀 시점 오차 | 자세·이벤트 정답이 있어야 계산 |
| 재현 정보 | 모델·가중치·라이브러리 버전, 입력·런타임·검출기·추적 설정 | 모델 고유 추론 시간과 전체 파이프라인 구분 |
| 개발 부담 | 설정·의존성, 주석 필요량, 추가 학습 절차, 라이선스 | 개발 난이도는 정량 성능이나 정확도 순위가 아님 |

## 7. 결론 및 미확인 사항

- 세 기술 모두 **실행 설정과 모델 종류에 따라 부담이 달라지며**, 공개된 서로 다른 벤치마크만으로 기술 간 우열을 정할 수 없습니다.
- **최소 컴퓨터 사양, 모델의 최종 크기, 실행 위치, 허용 지연, 최종 기술은 미정**입니다. 이 문서는 이 조건을 대신 결정하지 않습니다.
- **우리 침대 영상으로 측정한 수치가 없으므로** 관절 품질·처리 지연·모델 결합의 효과를 판단하지 않습니다.
- 향후 같은 영상·정답·실행 조건에서 **스켈레톤 품질과 전체 처리 시간**을 모두 측정한 뒤 선택 근거를 작성합니다.
