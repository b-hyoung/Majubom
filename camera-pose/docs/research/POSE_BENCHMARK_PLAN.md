> **작성: 2026-10-26 · 갱신: 2026-10-27 · 상태: 실험 설계·합성 입력/기록 경로 확인 / 실제 모델 비교·실측 전**
>
> 이 문서는 기술 선정을 위한 **실험 계획**이지 결과 보고서가 아닙니다. 아직 자체 영상을 통한 후보 실행·점수 산출·모델 채택은 하지 않았습니다. 초기 자세는 바로 누움·옆으로 누움·걸터앉음으로 합의했습니다. 촬영 배치는 세션마다 변경 가능하되 세션 중 카메라는 고정합니다. 구체적 촬영 장소·배치, 외부 센서 사양·라벨 매핑, 주석 경계, 평가 목표 수치는 미정입니다.

## 0. 이번 단계의 목적과 원칙

- **질문 A:** 우리 침대 환경에서 후보별로 사람과 필수 관절을 얼마나 안정적으로 추출하는가?
- **질문 B:** 누움·옆누움·걸터앉음·일어나는 전환, 이탈·복귀와 화각 경계에서 어떤 실패가 발생하는가?
- **질문 C:** 실제 실시간 측정기의 입력→추론→기록 과정에 필요한 지연·처리량 조건을 충족할 수 있는가?
- **질문 D(다음 단계):** 같은 자세 분류·상태 전이 기준선과 연결했을 때 어떤 추정기가 유리한가? 관절 정확도와 최종 자세·이벤트 성능을 혼동하지 않습니다.

**추론 실행 위치·방식은 아직 미정입니다.** 모델은 동일 영상에서 얻은 인식 품질·실험 결과를 중심으로 비교하며, 효율적인 코드, 모듈 분리, 기록·지연 측정은 처음부터 반영합니다.

카메라의 예측 입력에 외부 ToF·mmWave 결과나 측정 목표 자세를 사용하지 않습니다. 양측 결과 비교는 이후 독립적인 단계입니다.

## 1. 후보와 비교 단위

| 후보 | 실험 역할 | 관절 정의·주의점 |
|---|---|---|
| **MediaPipe Pose Landmarker** | 첫 독립 실행 어댑터 후보; Lite·Full·Heavy는 각각 *서로 다른 설정*으로 구분 | 신체 33점, 원본 visibility/presence·추정 world 좌표를 별도 보존 |
| **Ultralytics YOLO Pose** | 사람 박스와 2D 키포인트 동시 출력 비교 | 지정한 COCO 17점 가중치를 명시; 제품군 이름만으로 실행 모델을 지정하지 않음 |
| **RTMPose (MMPose)** | 추정기+필요한 사람 검출기를 포함한 전체 경로 비교 | 사전 학습 데이터셋·스켈레톤 정의·검출기 구성·가중치를 고정 |
| **MoveNet** | 17점 경량 대안, 주 후보가 조건을 충족하지 못할 때 추가 | Lightning / Thunder 각각 별도 모델로 기록 |

모든 후보를 **같은 영상·같은 프레임 목록·같은 원본 해상도**에서 시험합니다. 각 후보의 **기본 제공 권장 전처리/입력 크기는 그대로 기록**합니다. 모델 내부 입력 크기까지 무조건 같게 만들어 성능을 왜곡하지 않습니다.

최초 비교는 *전체 경로*(실제 검출기/추적/관절 추정 포함)로 진행합니다. 별도로 사람 ROI를 고정 제공하는 진단 실험을 할 수 있으나, 이 결과를 전체 경로 성능과 합치지 않습니다. 라이선스·가중치 사용 조건도 구현 전 확인합니다.

모델별 패키지 버전, 가중치 파일·체크섬, 전처리·추론 설정, 사람 검출기, 임계값, 추적·평활화 사용 여부를 실행마다 고정·기록합니다. 실제 성능 순위는 지금 정하지 않습니다.

## 2. 입력 데이터 준비와 정답

### 2.1 같은 영상으로 비교할 장면 — **수집 계획**

| 장면 ID | 관찰할 행동/상태 | 구분할 실패 |
|---|---|---|
| S01 | 바로 누운 상태 유지 | 몸통·다리 누락, 좌우 혼동, 정지 중 떨림 |
| S02 | 옆으로 누운 상태 유지 | 겹친 관절·사람 검출 실패, 방향 변동 |
| S03 | 침대 가장자리에 걸터앉아 유지 | 상체/다리 위치, 침대 경계 |
| S04 | 누움→앉음→다시 누움 | **일어나는 동작**과 **침대 이탈**의 혼동 |
| S05 | 실제 침대 이탈→침대 밖 유지→복귀 | 화각 이탈을 사람 미검출과 구분, 재검출 |
| S06 | 화각 경계·부분 가림·임시 관절 누락 | 검출 불능 구간·연속 실패 시간 |

- S01–S06은 **계획된 평가 시나리오이지 최종 분류 라벨이 아닙니다.** 초기 자세는 바로 누움·옆으로 누움·걸터앉음이며 좌우 세분화·엎드림은 보류합니다. 이탈 완료는 내려와 완전히 선 시점으로 합의했습니다. 복귀 운영 해석·미정 경계는 [결정 사항](../DECISIONS.md)을 따르며 외부 라벨 매핑은 협의 전입니다.
- 가능한 경우 *동일 참가자·동일 시점의 반복* 외에도 참가자/세션/시점이 달라지는 영상을 준비합니다. 반복 횟수와 최소 표본 수는 실험 규모가 확정되면 정합니다.
- **이불·야간·완전 가림은 초기 필수 시험이 아닙니다.** 포함한 영상은 별도 '탐색/확장' 구간으로 표기하고 기본 결과와 합산하지 않습니다.
- 촬영 전 동의·접근 권한·보관 기간·영상 비식별 처리 방침을 정합니다. 실제 영상, 참가자 개인정보, 주석 파일, 실험별 원본 출력은 공개 GitHub에 올리지 않습니다.

**2026-10-27 추가 시험 제안:** 주변 인물 등장·대상 겹침을 포함해 대상 혼동과 추적 복구를 확인합니다. 세션별 배치 기록 및 개발에 쓰지 않은 카메라 배치의 시험을 준비합니다. 한 명 대상 선택·추적 방식은 설계 제안이며 아직 구현하지 않았습니다.

### 2.2 정답의 단계

1. **영상만 있음:** 검출·출력 비율, 결측/실패 지속시간, 처리량 등을 기술적으로 점검. *관절 위치 정확도(PCK/MPJPE), 자세 정확도, 이벤트 정답 성능은 계산하지 않음.*
2. **사람 위치·관절 주석 있음:** 사람 존재, 2D 공통 관절의 픽셀 좌표와 주석 상태(보임/가림/화면 밖/불확실)를 기록. 이때만 정의한 PCK 등을 계산.
3. **실제 자세·이벤트 정답 있음:** 관찰자 또는 녹화 사후 검토로 실제 자세/이벤트 시작·완료 시각 확인. 이때만 자세 F1 또는 이벤트 지표를 계산. **목표 자세, 버튼 입력, 모델 출력은 정답으로 간주하지 않음.**

권장 주석: 평가할 대표 프레임·전환 구간을 먼저 층화 추출하고, 애매한 가림은 '불확실'로 표시합니다. 평가 주석 작업자는 AI의 예측을 보지 않고 판정하며, 재검토/수정 이력을 보존합니다. 학습/검증/시험 데이터는 **참가자 또는 세션을 단위**로 나누고 같은 녹화의 인접 프레임이나 중복 시간 창이 다른 분할에 섞이지 않도록 합니다. 데이터가 적어 독립 시험 분할이 불가능하면 그 한계를 표시합니다.

## 3. 공통 관절 비교 규칙

- 공통 표현은 **COCO 17점 2D**를 우선 검토합니다: nose, left/right eye, left/right ear, left/right shoulder, elbow, wrist, hip, knee, ankle. 이 집합은 우열을 확정한 것이 아니라 서로 다른 모델의 비교를 위한 공통 부분집합입니다.
- **MediaPipe 33→COCO 17 매핑(검수 대상)**: `[0,2,5,7,8,11,12,13,14,15,16,23,24,25,26,27,28]` 순서. 각 인덱스의 실제 정의는 모델 버전과 공식 자료로 재확인하고 단위 테스트를 작성합니다.
- COCO 17점 가중치를 쓰는 YOLO/RTMPose/MoveNet은 **실제 model metadata**를 확인한 뒤 명시적 매핑으로 변환합니다. 모델별 키포인트 정의가 다르면 이름만 보고 같은 점으로 취급하지 않습니다.
- **원본**: 각 모델의 원본 좌표·차원·좌표계·confidence/visibility/presence·검출 박스·결측 상태를 손실 없이 저장.
- **공통값**: `x_px, y_px`(원본 영상 픽셀), `x_norm, y_norm`(원본 W/H로 정규화), `joint_status`(predicted/missing/not_applicable), `score_raw` 및 `score_type`; 관측 불가능 또는 미검출은 `null`로 기록하며 `(0,0)`으로 대체하지 않음.
- **임계값**: 모델별 점수의 의미가 다를 수 있으므로 같은 '0.5'를 같은 품질로 해석하지 않습니다. 원본은 언제나 저장하며 판단용 임계값은 검증 분할에서 따로 정합니다.
- MediaPipe world 좌표는 **단안 모델 추정**이며 외부 센서가 실측한 절대 거리로 취급하지 않습니다. 원본 공간 위치와 침대 기준 위치도 신체 중심 정규화로 덮어쓰지 않습니다.

## 4. 실험 프로토콜

1. **입력 매니페스트 확정:** 각 영상에 `video_id`, `session_id`, 비식별 `participant_id`, 촬영 조건, 해상도, FPS 또는 PTS, 시간 기준, 영상 SHA-256, 사용 허가/접근 권한을 기록합니다. 저장 영상은 하나의 복호화 프레임 목록(`frame_id` + `video_pts_ms`)으로 고정합니다.
2. **버전과 경로 고정:** 각 후보에서 모델/가중치/전처리/검출/추적·평활화/실행 장치를 명시. 자동 다운로드 또는 기본 최신 버전으로 바뀌지 않게 실행 시 매니페스트를 남깁니다.
3. **관절 추출:** 같은 프레임 순서를 공급합니다. 미검출 및 건너뛴 프레임을 삭제하지 않고 출력 행에 상태로 표시합니다. 좌표 변환 전 원본 값을 먼저 저장합니다.
4. **공정성 비교 ①** 각 후보의 권장 전체 파이프라인(실제 검출·추적 포함)을 원본 영상에서 비교. 설정별 시퀀스·신뢰도·누락을 기록.
5. **공정성 비교 ②(선택)** 같은 사람이 있다고 알려진 ROI를 주는 관절 추정기 진단. 전체 파이프라인과 별도 표로 보고.
6. **정답 확보 시 평가:** 동일 주석, 동일 유효/제외 규칙, 동일 참가자·세션 분할로 지표 계산. 모델별 고유 관절 33점 등을 활용한 추가 실험은 **공통 17점 시험과 분리**합니다.
7. **실시간 독립 시험:** 실제 카메라→프레임 수신→추론→출력/저장 경로를 별도 실험. 디코딩이 미리 끝난 저장 영상의 벤치마크를 실시간 end-to-end 지연으로 표현하지 않습니다.
8. **반복과 분석:** warm-up을 본 측정에서 분리하고 동일 설정을 반복합니다. 실행 순서·부하·장비·환경을 기록하고 실패 사례를 시각/원인별로 검토합니다.

추후 자세 분류/이벤트 단계에서는 각 모델의 관절 출력을 **동일한 기준선 분류기(SVM/RF/MLP 등)와 동일한 검증 절차**로 시험하고, 모델 고유 특징 활용 결과는 별도 보고합니다. 시간 평활화·미래 프레임 접근을 사용한 오프라인 성능과 실시간 인과적 예측은 구분합니다.

## 5. 지표 및 분모/해석

| 지표 | 계산/보고 원칙 | 전제 |
|---|---|---|
| **사람 미검출률** | 실제 사람이 보이는 정답 프레임 중 사람을 못 찾은 비율. 해당 구간의 오검출도 따로 기록 | 사람 존재 정답 |
| **관절 출력 유효율·누락률** | 선택한 관절별 `유효 예측수/평가 대상 프레임수`; 사람 미검출을 분모에서 임의 제외하지 않음. 출력과 정확도 구분 | 공통 키포인트·유효 정의 |
| **연속 실패** | 연속 미검출 또는 필수 관절 누락의 횟수·최대 길이·초 단위 지속시간; 원인 코드별 분리 | 전체 프레임/PTS |
| **정지 구간 떨림** | 정지 주석 구간의 신체/화면 기준 좌표 변동(예: px 또는 몸통 길이 정규화); 실제 움직임과 분리 | 고정 카메라·정지 구간 |
| **관절 정확도(PCK)** | 실제 관절 2D GT와의 거리 ≤ 사전 정의한 `α × 정규화 길이`; α, 신체 크기 기준, 가림·불확실 제외, GT 수 명시 | 검증된 관절 좌표 GT |
| **자세 분류 macro-F1** | 클래스별 precision/recall/F1 및 혼동행렬; 유효 구간 성능 **+ 판정 불가 비율** 병기 | 확정 라벨·실제 정답 |
| **이탈/복귀 이벤트** | 실제 정답과 1:1 매칭, 사전 정한 허용 창에서 precision/recall, 오경보/시간, 시작·완료 시각 오차 | 실제 이벤트 정답·시점 정의 |
| **프레임 처리량** | 입력/디코드/추론/결과 기록 FPS 각각과 프레임 건너뜀 비율 | 입력 장치·방식 기록 |
| **지연** | 디코드/전처리/검출/추론/후처리/출력 시간과 end-to-end p50/p95, 측정 구간과 시계 명시 | 동일 실행 환경의 단조시계 기준 |
| **연속 실행 안정성** | 장시간 실행 중 중단·오류 및 처리 지연 변화 | 동일 조건 반복 실행 |

**서로 다른 목적의 지표를 섞지 않습니다.** 예를 들어 관절 GT 없이 출력 유효율만 높아도 정확도가 높다고 하지 않습니다. 좌표가 없는 영상은 PCK 대상에서 제외하되 제외 비율을 적고, 미검출·판정 불가가 많은 모델의 남은 구간 점수만 비교해 우수하다고 판단하지 않습니다.

특정 FPS·허용 지연·PCK/F1 합격 수치는 **아직 확정하지 않습니다**. 외부 센서의 측정 주기·실제 현장의 요구, GT 규모를 확인한 후 목표치를 정합니다.

### 시간 측정 원칙

- **저장 영상:** `video_pts_ms`는 영상 내 시각이며 실제 촬영 세계시각이라고 가정하지 않습니다. 디코딩·추론 구간은 동일 실행 환경의 monotonic clock으로 재고, 단순 FPS의 역수를 '센서 감지 지연'으로 표현하지 않습니다.
- **실시간 카메라:** 촬영 하드웨어 timestamp가 있으면 기록하고, 없으면 수신 시각을 *대체값*이라고 표시합니다. 추론 입력/종료/결과 출력 시각, 프레임 버림·버퍼링도 함께 기록합니다.
- **외부 센서 동기화:** 추후 장비별 시계 오프셋/드리프트 및 timestamp 정의를 협의합니다. 시계가 맞지 않는 상태에서 이벤트의 절대 시간차를 정확도 수치로 사용하지 않습니다.

## 6. 결과 저장 형식 — 구현을 위한 제안

> 아래는 **제안 스키마**이며 실제 생성된 결과 파일이 아닙니다. 실제 구현 시 schema_version을 정하고 호환성 검사를 추가합니다.

첫 구현의 draft 버전·필드·기록 순서와 평가별 디렉터리는 [세부 설계](../development/BENCHMARK_DETAIL_SPEC.md)로 구체화했습니다. 아래는 초기 개요 예시이며 구현 시 세부 계약을 적용합니다. 이는 실행 코드나 실제 실험 결과 생성 완료를 뜻하지 않습니다.

```text
runs/<run_id>/                  # .gitignore로 Git 추적 제외
  manifest.json                 # 영상 ID/해시, 모델·버전·가중치·설정·장치·시각 기준
  frame_results.jsonl           # 1 입력 프레임 = 1행, dropped/미검출도 포함
  keypoints.jsonl               # 공통 17점 + 원본 별도 구조, 결측과 score type
  aggregate_metrics.json        # 지표·분모·GT 이용 가능 여부·미계산 사유
  failure_cases.csv             # video_id, frame_id, 원인, 관찰 메모
  report.md                     # 자세별 표/한계/선정 보류 또는 근거
```

`frame_results.jsonl` 주요 필드:

| 필드 | 의미 |
|---|---|
| `schema_version, run_id, video_id, frame_id` | 재현 가능한 프레임 식별 |
| `video_pts_ms, capture_wall_utc_ns, timestamp_source` | 영상 내부 시각 / 실제 촬영 시각(없으면 null) / 근거 |
| `receive_mono_ns, infer_start_mono_ns, infer_end_mono_ns, output_mono_ns` | 존재하는 경우 **같은 단조 시계 기준** 단계별 시각; 다른 프로세스/호스트 시계 혼합 금지 |
| `person_detected, pose_status, failure_reason` | `valid / no_person / bad_pose / skipped / uncertain / error` 등; 처리하지 않은 프레임은 별도 표시 |
| `bed_roi_id, keypoints_ref, settings_ref` | 침대 영역(있는 경우)·상세 좌표·설정 연결 |
| `planned_pose, predicted_pose, sensor_pose, verified_gt_pose` | 이후 단계에서 각각 분리; 이 **기술 비교 단계의 관절 추정 입력으로는 사용하지 않음** |

`keypoints.jsonl`에는 모델 원본 데이터와 공통 관절을 구분한 객체를 저장하며, 좌표 단위·관절 배열 정의·결측 사유를 명시합니다. CSV만으로 임의의 가변 관절 배열을 섞지 않습니다. 예시 숫자를 실제 결과처럼 저장하지 않습니다.

## 8. 후보 압축·선정 판단과 완료 기준

**2026-10-27 검수 후 제안:** 이 단계는 관절 후보 압축·잠정 선택까지 수행하고 최종 채택은 후속 자세·이벤트 기준선 평가와 연결합니다. 단순히 관절 지표가 높다는 이유로 최종 분류 성능을 보장하지 않습니다.

1. **필수 관찰 가능성:** 핵심 장면별 사람·관절 확보 및 실패 원인이 제시되어야 합니다.
2. **정답 기반 품질:** 관절 위치 정확도는 관절 GT를 확보한 범위에서만 주장합니다. 정답이 없는 경우 후보 확정 대신 '잠정/추가 검증'으로 둡니다.
3. **실시간 적합성:** 실제 측정 흐름의 end-to-end 지연과 안정성, 미검출/판정 불가 구간을 함께 확인합니다. 운영 목표 수치는 협의 뒤 설정합니다.
4. **확장/유지보수:** 버전 고정, 라이선스, 재학습 가능성, 설치·교체·출력 형식과 디버깅 용이성을 검토합니다.
5. **결정 기록:** 비교할 수 있는 지표의 범위와 결측/제외 분모를 명시하고 [결정 사항](../DECISIONS.md)에 근거·날짜·한계를 기록합니다. 단순 합산 점수나 문헌 보고값만으로 선정하지 않습니다.

**이 계획 문서의 완료 조건**은 같은 영상·프레임 기준, 관절 매핑/원본 보존, GT 여부별 가능한 지표, 실패·지연 기록, 반복·비교표·선정 보류 조건이 적혀 있는 것입니다.

**현재:** 저장 영상·합성 어댑터·정식 결과 기록·무결성 검사 경로는 연결했습니다. **아직 안 된 일:** 실제 동의·촬영, 침대 영상 수집, 관절 주석·GT 기반 평가, MediaPipe 유효 자산 추론·가중치 사용 조건 검토·추가 어댑터 연결, 실제 후보의 FPS/정확도 측정, 외부 센서 출력 형식 협의.

## 9. 다음 Codex 구현 작업 범위(제안)

최초 구현은 **관절 추정 후보 비교용 최소 러너**로 제한합니다.

- `VideoSource`: 동일 영상에서 `frame_id`, 원본 `PTS`, 프레임 전달. 프레임 유실·디코딩 실패 기록.
- `PoseEstimatorAdapter`: 입력 프레임→모델 원본 결과; 모델별 추론과 전처리를 격리.
- `KeypointMapper`: 원본 보존 + COCO17 변환, 결측/좌표계/신뢰도 의미 명시.
- `Recorder`: 누락 프레임 포함 1프레임 1기록, 매니페스트·JSONL, 입력·추론 단계의 실행 시간.
- `Evaluator`: 사람 검출 출력 비율·관절 출력 유효율·연속 출력 누락·FPS·분포. 사람 미검출률은 사람 존재 GT가 있을 때만 계산하며, 관절 정확도·자세 F1·이벤트 지표도 각각 필요한 GT가 없으면 '계산 불가'와 사유를 반환. 정지 구간 흔들림은 실제 정지 구간이 확인된 경우에만 계산.
- **테스트:** 관절 순서·좌우, PTS 보존, (0,0)과 누락 구분, 디코딩/추론 실패 행 생성, 미실행 지표 0 오기 방지. 인위적 모의 입력에 대한 테스트는 *자체 영상 실험과 구별*.

UI, 자세 분류/이탈 판정, 외부 센서 비교, 모바일 원격 제어, 대규모 학습은 **이 첫 러너의 범위 밖**입니다. 첫 버전에서는 모델 하나씩 연결해 동작 확인 후 동일 인터페이스로 나머지 후보를 붙입니다.
