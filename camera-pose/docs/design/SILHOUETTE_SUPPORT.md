## 범위와 사용법

사용자가 추가 보조 근거 구현을 요청했다. HTML 작업실에서 기존 MediaPipe Pose Landmarker의 인물 분할 마스크 출력을 켜고, **선택된 같은 프레임·같은 후보의 몸통 관절 주변이 추정 인물 영역에 포함되는지** 별도로 검사한다. 추가 모델·가중치 파일·학습은 도입하지 않았다.

기존처럼 작업실을 실행해 카메라나 저장 영상을 연결한다.

```powershell
& .\.venv\Scripts\python.exe -m bed_pose live
```

오른쪽 **영상 보조 근거**에 일치·충돌·확인 불가를 표시하고, ‘검사 지점’을 펼치면 7지점의 영역 안/밖/경계와 주변 최대 출력값을 확인할 수 있다. 이 값은 정답 확률이 아니다. 합성 데모·마스크 미지원 입력은 확인 불가로 표시한다.

**최종 자세·적합도·가중치·0.65 기준·보류 조건은 변경하지 않는다.** 보조 검사에 충돌이 있어도 기존 자세 판정은 유지한다. 이것은 별도 경고/진단 결과이며 오류를 자동 수정하는 분류기는 아니다. 기존 독립 ToF/mmWave 결과나 목표·실제 정답을 입력으로 사용하지 않는다.

## 영상 위 실루엣 표시 · 2026-10-28

- 상단 **실루엣 표시**와 **관절 표시**는 독립 체크박스이며 기본은 켜짐이다. 개별 영상·복수 입력 격자에 적용한다. 인물 영역은 반투명 보라색, 관절은 기존 색상, 침대 영역은 파란색으로 구분한다.
- 현재 처리한 같은 프레임/같은 후보의 MediaPipe 분할 출력만 사용한다. 대상이 한 명이거나 추적 대상이 선택돼야 하며, 추적 보류·대상 불명확·마스크 없음/유효성 실패에는 표시하지 않는다. 주요 관절 부족으로 자세 또는 지점별 검사를 보류하는 경우에도, 유효한 같은 대상의 마스크는 표시할 수 있다. 후보 자체가 없는 경우는 복구하지 않는다.
- 표시 영역은 기존 전경 기준 0.5에서 이진화한다. 보조 검사에서 사용하는 0.6/0.4의 지점 주변 판정과 별개인 **시각화**이며, 보라색 영역이 정확하거나 그 자세가 확정됐다는 뜻이 아니다. 마스크의 전경 비율·자료형·크기·유한값 검사는 기존 설정을 따른다.
- `silhouette_overlay.capture_preview`는 SDK 마스크가 유효할 때 최대 긴 변 640px로 축소한 투명 PNG를 만든다. 축소는 최근접 보간, 색상은 RGB(170,110,245), 전경 alpha 105/255다. 이 값은 표시 설정이며 자세 가중치/임계값에 반영하지 않는다. 아주 가는 영역은 축소로 빠질 수 있다.
- `PoseOutput.silhouette_preview` → live 처리 결과의 별도 필드 → `/api/view`로 일시 전달한다. 프레임/SDK 시각/크기/선택 대상의 일치를 확인하며 전체 PNG를 JSONL·manifest·CSV·기록 조회에 추가하지 않는다. 기존 `silhouette-support-0.1` 희소 표본과 보조 상태의 저장·재검사는 유지한다. 이전 기록에서 실루엣을 복원하는 기능은 없다.
- 브라우저는 같은 응답의 영상/마스크를 준비한 뒤 함께 그린다. 마스크 디코딩 실패는 영상 표시를 중단하지 않으며 이전 마스크를 재사용하지 않는다. 관절·침대 영역은 실루엣 위에 그린다. 영역 수정으로 화면을 고정하면 실루엣도 그 프레임과 함께 고정한다. 입력 전환·영상 처리 실패·입력 제거 시 다른 입력의 이전 마스크가 남지 않게 한다. 파일 일시정지/정상 종료 후 마지막 화면은 기존처럼 마지막 분석 프레임이다.
- 표시를 끄는 것은 화면 렌더링만 끈다. 보조 검사를 위한 SDK 분할 추론과 희소 표본 기록은 계속된다. PNG 생성/전송/브라우저 디코딩이 추가되므로 표시를 끄는 것만으로 추론 속도가 빨라진다고 보장하지 않는다. 실제 PC/복수 카메라 지연 측정은 남아 있다.

## 검사 내용과 초기 설정

1. MediaPipe의 `output_segmentation_masks=True`로 받은 후보별 인물 영역을 사용한다. SDK 결과의 후보 순서로 연결하되, 이후 선택·재검사에서는 `candidate_id`로 같은 후보를 찾는다. 후보 수가 다르면 확인 불가다.
2. 어깨·골반 4관절과 어깨 중점·골반 중점·몸통 중점, 총 7지점을 정한다. 원본 MP33의 11/12/23/24와 공통 COCO17의 5/6/11/12가 대응하며, 원본/실제 표시 관절의 좌표도 대조한다.
3. 각 지점 주변 최대 3×3 위치를 표본화한다. 간격은 영상 짧은 변의 0.005배를 반올림해 1~8px로 제한한다. 영상 가장자리에서는 중복 표본을 제거한다. **지점 한 픽셀 자체가 아니라 주변 영역과의 겹침 검사**다.
4. 주변 최대 인물 영역 출력값이 0.6 이상이면 ‘영역 안’, 0.4 이하이면 ‘영역 밖’, 중간이면 ‘경계 불확실’로 분류한다.
5. 7지점 모두 ‘영역 안’이면 **일치**, 절반 이상이 ‘영역 밖’이면 **충돌**, 나머지는 **확인 불가**로 표시한다. 일치는 검사한 주변 영역이 겹친다는 뜻이며 관절·자세 전체가 올바르다는 뜻이 아니다.

추가 유효성 조건: 마스크는 원본 입력과 같은 크기의 float 확률 배열이어야 한다. `[H,W]`와 `[H,W,1]`을 지원하며 임의 확대·축소로 좌표계를 맞추지 않는다. 비유한 값·범위 밖 값·크기 불일치는 확인 불가다. 0.5로 이진화한 전경이 전체의 0.1% 미만이거나 98%를 넘으면, 비어 있거나 화면을 거의 덮는 정보로 보고 확인 불가로 처리한다.

위 값은 **실측으로 보정하지 않은 보조 검사의 초기 설정**이다. `silhouette-support-0.1` 프로필에 모두 기록한다. 이불·옷·경계 부근의 분할 오류로 충돌하거나 확인 불가가 나올 수 있으며, 임계값을 검증된 품질 기준으로 취급하지 않는다.

프레임/입력 ID·SDK 시각·크기·후보·관절 대응이 어긋나거나, 대상 추적 보류·주요 관절 부족·영상 처리 실패가 있으면 다른 후보나 이전 마스크를 대신 사용하지 않는다. 마스크를 못 읽어도 기존 관절 추론과 자세 분류를 실패로 바꾸지 않는다.

## 기록과 재검사

- `PoseOutput.silhouette_observation`은 선택적 보조 경로다. 기본 MediaPipe 어댑터와 오프라인 benchmark는 기존처럼 마스크 출력을 끄고, HTML 작업실 팩토리에서만 켠다. 분할 옵션과 추가 처리로 실제 지연/자원 사용은 달라질 수 있으며 장치별 측정은 남아 있다.
- 새 live manifest의 `silhouette_profile`, 프레임의 `silhouette_observation`과 `silhouette_assessment`에 출처·설정·같은 프레임/후보·7지점 주변 표본·영역 안/밖/경계 수와 보조 상태를 저장한다. 원본 관절과 최종 자세는 보존한다.
- 전체 마스크 이미지나 원본 영상을 매 프레임 저장하지 않는다. 원본 배열의 크기·자료형·SHA-256과 희소 확률 표본만 남긴다. 인체 형태 관련 파생 정보이므로 이 파일도 측정 데이터로 취급하며 GitHub에 올리지 않는다.
- `live-inspect`는 저장된 원본 관절·표시 관절·표본 좌표/값에서 보조 상태를 재계산해 비교한다. **전체 마스크가 없어 표본의 원래 SDK 생성 자체를 재현 검증하는 것은 아니다.** 전체 마스크 SHA는 나중에 원본 배열이 있을 때 대응하는 식별 정보이고, 저장되지 않은 전체 마스크를 복원하거나 검사했다는 뜻이 아니다.
- 기록 조회의 ‘영상 보조 근거’ 열과 CSV 보고서 0.4에 상태·사유·안/밖/경계 수·포함 비율을 제공한다. 이전 기록에 없던 보조 결과는 새로 만들어 채우지 않는다. 필드/프로필이 없는 이전 기록은 계속 검사하고, 새 형식의 일부 누락이나 저장 결과 불일치는 거부한다.

## 해석의 한계

분할과 관절은 **같은 모델·같은 영상에서 나온 추정**이다. 서로 다른 표현을 대조하는 보완 근거이며 독립적인 정답이나 실측 센서가 아니다. 두 출력이 함께 틀리면 일치로 보일 수 있고, 충돌해도 어느 쪽이 틀렸는지는 알 수 없다. 사람 자체를 놓쳐 후보가 없을 때 복구하는 탐지기는 아니다.

바로 누움/옆누움을 실루엣만으로 새로 분류하거나 침대 기준 높이를 측정하지 않는다. 얼굴 방향·시간적 안정화·다중 시점 보정도 이번 범위에 포함하지 않았다. 실제 촬영에서 잘못된 고득점 판정을 얼마나 찾아내는지, 정상 관절을 얼마나 충돌로 표시하는지는 별도 정답이 있는 영상으로 확인해야 한다.

## 구현 근거와 검사 범위

설치된 MediaPipe 0.10.35의 `PoseLandmarkerOptions.output_segmentation_masks`, `PoseLandmarkerResult.segmentation_masks`와 `Image.numpy_view()` 구현을 확인했다. [공식 Python API 안내](https://developers.google.com/edge/mediapipe/solutions/vision/pose_landmarker/python)의 선택적 분할 출력에 대응한다.

제어한 SDK/마스크로 일치·충돌·경계/미지원, 다인 선택·프레임/좌표 대응, 비정상/비정보성 마스크, 보조 실패 시 기존 관절 보존, 기록/CSV/이전 형식과 변조 거부를 검사한다. 브라우저의 현재 프레임 표시·입력 전환·다중 보기·기록 조회와 작은 화면도 확인한다. 실제 학습 모델의 침대 영상 분할 품질·오판정 탐지 성능 검증과 구분한다.

전체 221개 개발 검사와 Chromium의 일치/충돌/확인 불가·동일 최종 라벨/점수·7지점·기록 조회·입력 전환·다중 보기·390/1440/2560px 표시·입력 종료, JavaScript 오류 없음을 확인했다. 실제 MediaPipe 0.10.35의 float32 `Image`에서 `[H,W,1]` numpy_view를 받아 표본 추출하는 네이티브 자료형 경계도 확인했다. 이 환경의 누락된 libGLESv2는 /tmp에 임시 추출한 공개 Debian 패키지로 보완했으며 앱 의존성·사용자 설정을 바꾸지 않았다. 실제 Pose Landmarker 모델의 영상 분할 추론/성능 재현은 수행하지 않았다.

오버레이 추가 검사는 제어한 마스크의 전경 색/alpha·배경 투명도·640px 제한·SDK 배열에서 분리·프레임/대상 대응·잘못된 표시 데이터 격리·같은 자세 유지·미검출 후 제거·전체 PNG 미기록/기록 검사 호환을 확인한다. Chromium 캔버스 픽셀을 직접 비교해 표시/숨김·원본 배경 유지·관절과 독립 전환·영역 수정·입력 전환·여러 화면·390/1440/2560px·잘못된 마스크 디코딩·JavaScript 오류 없음도 확인했다. 실제 MediaPipe float32 Image의 `[H,W,1]` 배열을 투명 PNG로 변환하는 자료형 경계를 검사했다. 모의 인물 영역으로 표시 경로를 검사했으며 실제 모델의 침대 영상 분할 성능이나 실제 카메라 지연 검증은 아니다.

현재 오버레이를 포함한 전체 227개 개발 검사를 통과했다. 배포 wheel의 새 표시 모듈·어댑터·엔진·웹·HTML 내용이 소스와 같은 것도 확인했다.
