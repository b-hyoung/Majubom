# 관절 품질과 사람 입력 영역 분리

[진행 현황](../PROJECT_STATUS.md) · [다중 카메라 구조](MULTI_CAMERA_DESIGN.md)

**2026-10-31 · 선택적 실험 구현.** 기본 관절 영역·CLIP 문장/점수/임계값·최종 판정은 유지합니다. 검출 기반 영역 확보는 별도 경로이며 실제 누운 사람의 검출/분류 개선은 미검증입니다. 시간적 안정화(5번)는 이번 범위가 아닙니다.

## 사용

기존 CLIP 환경에서 사람 검출 모델을 한 번 준비합니다. 실행 중에는 인터넷에서 모델을 받지 않습니다.

```powershell
& .\.venv\Scripts\python.exe -m bed_pose person-setup
& .\.venv\Scripts\python.exe -m bed_pose live
```

다운로드가 불가능하면 신뢰할 수 있는 YOLOS-tiny Hugging Face 형식 폴더를 가져와 준비할 수 있습니다.

```powershell
& .\.venv\Scripts\python.exe -m bed_pose person-setup --source "D:\models\yolos-tiny"
```

기본 저장 폴더는 `checkpoints/person-yolos-tiny`입니다. 기존 폴더를 덮어쓰지 않습니다. `--output`을 달리 지정한 경우 작업실이 찾는 기본 폴더에 배치해야 합니다. 모델은 GitHub에 올리지 않습니다. 다운로드는 고정 snapshot revision과 파일 SHA-256을 기록하며, 로컬 가져오기는 revision 미확인과 파일 해시를 남깁니다.

작업실 재시작 → 입력 추가 → CLIP과 **사람 검출로 입력 영역 보완** 선택 → 영상 아래 **측정 대상 지정** 순서입니다. 기본값은 꺼짐입니다. 기존 입력은 제거 후 다시 연결해야 설정이 바뀝니다. 두 카메라는 입력별로 선택합니다.

## 처리 순서와 제한

1. `image_quality.joint_points`가 관측·신뢰도 조건을 만족한 관절만 추출합니다. `inspect_crop`은 기존 그룹 조건과 10% 여백 영역 정책을 유지합니다.
2. 관절 영역이 사용 가능하면 검출기를 실행하지 않습니다. 영역 부족 시에도 현재 대상이 잠정 추적되고 어깨와 골반의 대응 관절이 있어야 검출을 시도합니다.
3. 현재 프레임 전체에서 검출한 사람 상자 중 몸통 관절을 포함하는 영역이 정확히 하나여야 합니다. 다른 검출 영역과의 중첩·다른 사람의 관절 포함은 거부합니다. 이는 자동 동일인 검증이 아니라 현재 관절과의 보수적 대응입니다.
4. 화면 경계 접촉·작은 영역·모호한 대응은 보류합니다. 검출 상자가 전신 포함·가림 없음·올바른 관절을 증명하지는 않습니다.
5. 통과한 영역만 기존 CLIP 전처리·판정에 전달합니다. 관절이 부족하다는 사실은 그대로 기록합니다. 침대·목표 자세·외부 센서·정답은 검출/대응 입력으로 사용하지 않습니다.

사람 자체가 미검출되거나 몸통 관절까지 없어지면 복구하지 못합니다. 이전 상자 재사용·새 추적기·재식별은 구현하지 않았습니다. 겹친 사람을 보수적으로 거부하므로 보류가 늘 수 있습니다.

## 첫 검출 제공자

[YOLOS-tiny 모델 카드](https://huggingface.co/hustvl/yolos-tiny)는 COCO 객체 검출 모델이며 Apache-2.0으로 표시됩니다. [Transformers YOLOS 공식 문서](https://huggingface.co/docs/transformers/v4.57.1/en/model_doc/yolos)의 `YolosForObjectDetection`·`YolosImageProcessor`로 연결합니다. 기존 CLIP의 PyTorch/Transformers 의존성을 재사용하는 첫 실험 제공자이며 최종 기술 선정이 아닙니다. 모델 카드의 일반 객체 검출 수치를 침대 사람 검출 성능으로 전용하지 않습니다.

`person_detector.PersonDetector`는 첫 대체 경로 호출 때만 로컬 가중치를 읽습니다. CPU/CUDA/MPS 중 기존 CLIP 실행 장치를 사용하며 FP32입니다. 선택된 입력마다 별도 검출 모델을 소유합니다. 초기 로딩과 검출이 추가 지연·메모리를 사용하므로 저사양·다중 입력에서 무비용 개선으로 설명하지 않습니다. 초기 로딩 실패는 입력을 다시 연결할 때까지 반복 로딩하지 않습니다.

`person-detector-0.1`과 `person-crop-policy-0.1`에 신뢰도 0.7·입력 긴 변 최대 640px·최소 영역 변 16px·경계 여유 1px를 기록합니다. 모두 미검증 초기값이며 검증된 정확도 기준이 아닙니다. 검출 점수와 관절 신뢰도를 같은 척도로 비교하지 않습니다.

## 화면·기록·검증

- 분석 영상의 주황색 점선은 CLIP 입력 영역입니다. 관절 기반/사람 검출 기반을 구분하고 CLIP 근거 창에서 실제 224px 입력도 확인합니다. 격자 보기에서도 표시합니다. 수신 원본을 별도로 보여주는 라이브 화면에는 다른 시각의 영역을 겹치지 않으며 분석 화면에서 확인합니다.
- manifest의 `person_crop_profile`과 프레임의 `person_crop_observation`에 모델/설정·프레임/시계/대상·원시 상자/점수·선택 영역·품질/실패·검출 소요 시간을 보존합니다. 이미지 품질은 `person-crop-quality-0.1`, 관절 부족 사유는 `joint_reasons`로 구분합니다.
- 읽을 때 원래 관절·기록된 상자에서 대응과 품질을 다시 계산합니다. 해시를 다시 만든 뒤에도 영역/품질 변조는 거부합니다. 이는 저장된 추론의 일관성 검사이며 원본 영상에서 검출 모델을 재실행한 정확도 검증은 아닙니다.
- 이전 기록에는 새 필드를 요구하지 않습니다. 단일·그룹 판정은 사용 가능한 이미지 근거를 기존 방식으로 처리하며 시간/대상 게이트를 완화하지 않습니다.

개발 환경에서는 지정 상자·지정 CLIP 점수로 복구/실패/그룹 기록·변조 검사를 수행하고, 작은 무작위 YOLOS 가중치로 실제 Transformers 처리·추론·후처리 연결을 확인했습니다. 사전학습 가중치 다운로드는 환경 프록시 403으로 실패했습니다. 실제 사람 검출률·잘못된 영역 수락·자세 정확도·장치별 지연은 미검증이며, 같은 영상에서 기존 경로와 비교한 뒤 기본 적용을 판단해야 합니다.
