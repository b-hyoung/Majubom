## 실행과 자원 경계

기존 입력별 LiveWorker가 수신·추론·판정·기록을 소유한다. WebWorkspace 모니터는 메시지와 최신 처리 결과를 수집하고 기록 수/경과·처리 FPS를 갱신한 뒤 입력별 PreviewWorker에 표시 작업을 제출한다. 인코더는 공통 작업실 잠금을 잡지 않고 JPEG를 만든다. 각 입력은 변환 중인 한 작업과 교체 가능한 최신 대기 작업 하나만 유지한다. 화면용으로 건너뛴 결과를 원본 기록에서 누락시키지 않는다.

뷰는 변환에 사용한 프레임의 시각·관절·대상·자세·실루엣과 함께 한 묶음으로 공개한다. 변환이 느리면 해당 입력의 화면 관측은 늦을 수 있으며 이를 새로운 관측으로 바꾸거나 이전 마스크를 새 영상에 결합하지 않는다. 화면용 세대가 역행하는 결과는 버린다. 기록 수와 처리 FPS는 표시 변환과 별도로 갱신하고, 자세/대상 화면은 공개된 영상 관측과 대응한다. 두 시점 결합의 기존 시간/대상 게이트와 기준은 유지한다.

## 화질 전환·실패·종료

화질 명령끼리는 전용 잠금으로 직렬화한다. 현재 프레임 스냅샷을 얻고 공통 잠금 밖에서 모두 변환한 후 설정을 적용한다. 준비 실패 시 기존 설정을 유지한다. 움직이는 입력이 준비 중 전진한 경우 이전 세대의 뷰를 덮어쓰지 않고 최신 프레임을 새 화질로 다시 제출한다. 정지 입력은 같은 프레임을 전환한다. 이전 화질의 비동기 결과는 화질 버전으로 거부한다.

JPEG 실패는 기존 preview_error로 분리하며 측정/추론을 종료하지 않는다. 입력 자체 오류는 표시 캐시·대기 작업을 폐기하고 입력 유효 버전을 바꿔 진행 중 결과도 거부한다. 삭제된 입력의 결과는 재등록하지 않는다. 종료 시 대기 작업을 비우고 표시 스레드를 종료 요청한다. 이미 실행 중인 네이티브 인코딩은 강제 중단할 수 없어 제한 시간만 기다리는 daemon 스레드를 사용하며 늦은 결과를 반영하지 않는다.

RAM에는 현재 입력 캐시 외에 변환 중 프레임과 화질 전환 스냅샷이 일시 유지될 수 있다. 입력 수/해상도에 따른 메모리와 CPU·전송 부담은 남는다. 이 변경이 물리 카메라 FPS나 촬영 동기화를 보장하지 않는다.

## 검증

`test_preview_concurrency.py`는 한 인코더를 Event로 멈춘 동안 다른 입력 갱신·상태 조회·기록 진행·입력 제거가 가능한지 검사한다. 대기 작업의 최신 값 교체와 화질 명령 중 관측 전진·설정 반영·프레임 대응도 확인한다. 기존 화질·오류 복구·실루엣·카메라 설정 브라우저 회귀 검사를 함께 사용한다. 실제 다중 카메라 처리율·종단 지연·장시간 자원 측정은 별도 검증이다.

## 카메라 수신·분석 분리 · 2026-10-30

실제 CameraSource는 LatestCameraSource의 전용 스레드가 열기·읽기·닫기를 소유합니다. 메모리에 최신 RGB 한 장을 교체하며 분석 작업은 이전 분석을 마친 뒤 최신 관측을 가져옵니다. 카메라 수신 대기·오류·종료를 전달하고, 종료가 지연되는 장치는 제한 시간 후 오류로 알립니다. 저장 영상과 합성 데모의 기존 순차 처리는 유지합니다.

분석 stream_frame_id는 처리 관측의 연속 번호입니다. camera_capture.capture_frame_id는 수신 순서, skipped_before는 직전 분석 이후 건너뛴 수신 프레임 수입니다. 첫 값은 스트림 수신 시작 이후의 건너뜀을 포함할 수 있습니다. 장치 내부 유실은 측정하지 않습니다. 시각은 실제 수신 작업에서 채집하며 노출 시각은 여전히 미제공입니다. 처리 시간 전체에는 수신 후 분석 선택까지의 대기가 포함될 수 있습니다. 기록에는 분석한 프레임만 남기고 전체 원본 영상 수신 기록을 주장하지 않습니다.

개별 카메라 화면은 기본 분석 프레임 보기이며 관절과 침대 영역을 함께 표시합니다. 별도 PreviewWorker가 최신 수신 프레임을 JPEG로 인코딩하며 대기 작업은 하나입니다. 관절·실루엣을 최신 영상에 겹치지 않고 자세 결과가 어느 수신 시점에 해당하는지 표시합니다. `관절·침대 영역 확인` 버튼으로 기존 분석 프레임과 대응하는 관절·근거를 확인합니다. 영역 지정은 분석 프레임을 사용합니다. 여러 화면 격자는 기존 분석 프레임 표시를 유지합니다. 최신 영상도 인코딩·전송·장치 성능의 영향을 받으며 30 FPS를 보장하지 않습니다.

CLIP 입력 확인 PNG는 브라우저의 근거 창 사용 여부에 따라 생성합니다. 정지한 저장 영상은 캐시한 실제 입력을 요청 시 변환합니다. 입력 RGB·문장·점수 기준은 동일합니다.

지정된 침대 영역은 최신 수신 영상에도 계속 표시합니다. 수신 영상의 원본 크기로 좌표를 변환하고 여백을 반영합니다. 입력 전환·영역 해제·영상 크기 불일치·표시 중단에서는 이전 영역을 겹치지 않습니다. 스켈레톤과 실루엣은 해당 분석 프레임에서만 표시합니다.

## 표시 비용 절감 · 2026-10-30

최신 수신 영상의 JPEG 인코딩은 /api/live-view 요청이 있을 때만 실행합니다. 마지막 요청 후 1초 동안만 관심을 유지하며, 요청이 끊기면 추가 제출을 멈춥니다. 이미 실행 중인 인코딩은 완료될 수 있습니다. 여러 브라우저 중 하나가 계속 최신 영상을 요청하면 인코딩을 유지합니다. 카메라 수신·분석·기록은 이 관심 상태와 독립적으로 계속됩니다. 분석 프레임 JPEG는 관절/대상/영역 확인에 사용하므로 기존 대응을 유지합니다.

브라우저는 compact 상태 API에서 고정된 자동 판정/영상 모델/비교 설정을 해시 키별로 한 번 받아 재사용합니다. 설정 객체를 교체하면 새 해시와 설정 묶음을 공개합니다. 고정 설정은 내부에서 제자리 수정하지 않고 교체해야 합니다. 기존 전체 상태 API와 기록의 모델 출처 정보는 유지합니다. 상태 스냅샷의 JSON 왕복 복사를 deepcopy 한 번으로 바꾸고 HTTP에서 직렬화합니다.

상태 응답의 ETag가 같으면 304로 본문을 생략하고 브라우저는 재렌더링을 생략합니다. 새 프레임·오류·진행 상태·모드·설정은 응답이 달라져 즉시 반영됩니다. canvas는 프레임/영상 객체/표시 크기/배율/영역/표시 설정이 같으면 다시 그리지 않습니다. 모델 입력·분석 주기·최종 판정·기록 형식은 동일합니다. 실제 PC의 CPU/GPU 사용률과 종단 지연은 별도 측정합니다.
