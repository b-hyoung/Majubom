## 네 점 침대 영역 · 2026-10-28

침대 모서리를 순서대로 네 번 클릭해 지정하고 점 이동·마지막 점 취소·지정 취소를 지원합니다. 볼록 영역 검사, 실제 다각형 내부 여부, 단위 사각형 대응 상대 좌표와 자동 자세 판정/원본·그룹 기록 검사를 연결했습니다. 기존 사각형 기록은 유지하며 네 점을 포함한 통합 입력은 0.3 형식입니다. [사용법과 좌표 의미](../guides/BED_REGION.md).

계획 목표와 예측을 실제 정답으로 자동 대체하지 않습니다. 정답 상태는 미확인·임시 기록·검증 완료·불확실 등을 구분할 수 있어야 합니다.

## 판정 기록 보완 제안 · 2026-10-27

- 자세 예측과 안정/변화 후보/판정 보류를 분리하고 마지막 확인 자세·시각을 현재 결과와 구별합니다. 관측 공백·대상 혼동·관절 부족·침대 영역 오류의 사유와 구간을 보존합니다.
- 이벤트별 완료 추정 시각, 판정 확정 시각, 결과 출력 시각을 각각 기록합니다. 추정 시각은 정답이 아니며 실제 정답 시각·주석 불확실성과 따로 비교합니다. 시간 필드·시계 식별·저장 형식은 아직 제안 단계입니다.
- 참가자·세션 분할과 함께 카메라 배치별 결과 및 개발에 쓰지 않은 배치의 시험을 계획합니다. 배치가 바뀌어도 같은 영상의 인접 프레임이 분할을 넘지 않게 합니다.
- 주변 인물 등장·겹침에서 대상 전환 오류, 판정 보류 비율과 복구 여부를 확인하는 시험을 추가 제안합니다. 대상 식별 정답과 관측 공백 처리 지침이 필요합니다.
- 최종 평가 전에 주석 경계·애매한 구간·주석 불일치 해결 절차, 이벤트 매칭·허용 오차·합격 기준을 정합니다. 파일럿·검증 자료에서 조정한 설정은 독립 시험 자료 평가 전에 고정합니다.

## 평가 A · 두 시스템의 결과 비교

같은 실험·시간대·공통 라벨로 정렬해 다음을 집계합니다.

- 양쪽 결과가 모두 유효한 구간의 일치율과 라벨별 불일치
- 자세 변화·이탈·복귀 이벤트의 감지 시점 차이
- 양측 유효 구간 비율, 누락·판정 불가 구간과 시계 오차

**일치도는 정확도가 아닙니다.** 두 시스템이 같은 오답을 낼 수 있습니다. 최종 비교 범위와 시간 기준은 외부 개발자와 합의해야 합니다.

## 평가 B · 실제 정답 기준 성능

실제 수행을 별도로 확인한 구간에서 카메라와 센서를 각각 평가합니다. 계획 라벨만 있는 구간은 검증된 정답 평가에 포함하지 않습니다.

| 대상 | 제안 지표 | 함께 명시할 조건 |
|---|---|---|
| 사람 검출 | 사람이 보이는 프레임의 미검출률 | 사람 존재 정답·평가 대상 프레임 |
| 관절 위치 정확도 | PCK 또는 MPJPE | 관절 정답, 차원·단위·정규화·임계값 |
| 자세 분류 | 클래스별 precision/recall/F1, macro-F1, 혼동행렬 | 실제 자세 정답·라벨 정의·표본 수·분할 |
| 이탈·복귀 | 이벤트 precision/recall, 오경보/시간, 누락 | 실제 이벤트 정답·1:1 매칭·허용 시간창·중복 경보 처리 |
| 이벤트 시각 | 기준 시점 대비 시간차·분포 | 실제 이벤트 시각·시작/완료/사전 경고 구분·부호·기준 시각 |

각 지표에 필요한 정답이 없으면 해당 지표는 계산하지 않고 사유를 기록합니다. 유효 구간 성능에는 아래의 판정 불가 비율을 함께 보고합니다.

## 기술 점검 · 출력과 처리 성능

관절 위치·자세·이벤트 정답 없이도 출력과 처리 기록을 점검할 수 있습니다. 다만 정지 구간 흔들림은 실제 정지 구간 확인이 필요하며, 자세·가림별로 나누어 보고하려면 해당 조건을 별도로 확인해야 합니다.

| 대상 | 제안 지표 | 함께 명시할 조건 |
|---|---|---|
| 관절 출력 안정성 | 출력 누락률·연속 출력 누락·정지 구간 흔들림 | 공통 관절·유효 출력 정의·전체 평가 프레임·확인된 정지 구간 |
| 판정 불가 | 유효 비율·누락 비율·지속 시간 | 전체 적용 범위·판정 기준 |
| 실시간 처리 | 처리량·프레임 드롭·전체 지연 p50/p95 | 장비·입력·전송·추론·출력 조건 |
| 운영 안정성 | 장시간 처리 중단·지연 변화, 오류 발생 | 실행 조건·반복 실험·재현성 기록 |

사람 존재 정답이 없으면 사람 검출 출력 비율만 기록하며, 이를 사람 미검출률로 해석하지 않습니다. 관절이 출력됐다는 사실과 좌표가 정확하다는 것은 다릅니다. 정답 인물 박스를 준 시험과 실제 사람 검출기부터 실행한 시험, 촬영 FPS와 추론 속도도 구분합니다.

## 분할과 시간 정렬

1. 참가자·세션 단위로 학습/검증/시험을 분리하는 계획을 우선 검토합니다.
2. 같은 녹화의 인접 프레임이나 겹치는 시간 창이 분할을 넘지 않도록 관리합니다.
3. 새 참가자 평가와 같은 참가자의 다른 세션 평가를 구분하고 분할 목록을 보관합니다.
4. 촬영·센서 측정 시각과 결과 도착·출력 시각을 구분합니다.
5. 영역 보정·미검출·불확실 구간의 포함/제외 기준과 비율을 보고합니다.

이벤트의 시작·완료 정의와 시간 정렬 오차를 정하기 전에는 감지 지연을 확정하지 않습니다.

## 단독 동작 진단 필드 · 2026-10-30

새 프레임의 `previous_processing_ns`는 직전 프레임을 수신한 뒤 엔진 반환 직전까지 측정한 처리 시간입니다. 현재 프레임 처리 시간·촬영 간격과 구분하며 첫 프레임은 0입니다. CLIP 0.2 관측의 `input_quality`는 입력 검사 결과, 선택적 `error`는 실행 오류 코드/예외 종류입니다. 원문 예외 메시지는 저장하지 않습니다. 관절 `processing_status`와 CLIP 관측 상태는 독립적이며 이미지 실패가 관절 ok를 failed로 바꾸지는 않습니다. 실루엣 실행 여부는 어댑터 프로필의 segmentation_masks에 남습니다. 과거 기록은 당시 필드/정책으로 읽습니다.

## 재계산 수치와 카메라 수신 번호 · 2026-10-30

파일 SHA-256은 정확히 비교합니다. 자세·CLIP 재계산 결과의 구조·라벨·정수·문자열은 정확히 비교하고 float는 유한한 값에 한해 상대/절대 오차 각 1e-12를 허용합니다. Windows/Linux 수학 라이브러리의 극미세 반올림 차이 대응이며 임계값을 넘어 라벨이 달라지는 경우는 허용하지 않습니다.

source_profile.capture_policy가 latest_camera_frame_v1인 기록은 camera_capture.capture_frame_id와 skipped_before(비음수 정수의 문자열)를 보존합니다. 연속 분석 행 사이의 수신 번호 증가와 건너뜀 수가 일치해야 합니다. stream_frame_id는 분석한 프레임 순서이므로 수신 전체의 완전성을 뜻하지 않습니다.

### 카메라 동시 수신의 시간 검증

latest_camera_frame_v1인 카메라 기록은 다음 수신이 이전 분석·기록과 겹칠 수 있습니다. 프레임 내부의 읽기 시작→수신→추론→매핑→기록 순서는 검사하고, 프레임 사이에는 각 단계 시각의 역행, 수신 작업끼리의 겹침, 단일 분석 작업끼리의 겹침을 거부합니다. 저장 영상과 기존 순차 카메라 기록은 종전의 전체 순차 검사를 유지합니다. 파일 해시·수신 번호·건너뜀 수·판정 재계산 검증은 동일합니다.

이전 버전에서 종료 검증에 실패해 ledger_complete=false로 남은 파일은 자동으로 성공 처리하지 않습니다. 별도 복구 없이 기존 원본을 그대로 보존하며 내용 검사 통과와 완료/해시 검증을 구분합니다.
