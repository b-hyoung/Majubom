# 정확도 개선: 실제 비교와 반영 범위

후속 요청의 [관절 실패 복구·문헌 대조·GPU 비교](../research/POSE_RECOVERY_REVIEW_2026-11-01.md)를 추가했습니다. 최종 자동 경로의 옆누움 관절 수 증가를 확인하지 못했으며, 미검출 재시도 지연과 GPU 연결 복구를 개선했습니다. 아래의 초기 변환 탐색 결과를 최종 정확도 향상으로 해석하지 않습니다.

2026-11-01 사용자 요청으로 현재 장비에서 관절 검출/3D 선택/분류 일관성을 개선했습니다. 실제 3D 거리 보정이 검증되지 않았다는 기존 한계는 유지합니다.

## 현재 자세 확인

변경 전 바로 누운 실제 입력을 약 3초간 확인한 15개 응답 모두 `supine/stable`이었습니다. 필요한 관절의 최소 신뢰도는 약 0.75~0.76, 표시 관절은 14~15개였습니다. 변경 후 사용자가 침대 위에 앉아 있는 영상에서 15개 응답 중 13개 `sitting`, 2개는 경계 발목 근거 부족으로 보류했습니다. 이는 서로 다른 자세/시점의 짧은 작동 확인이며 전체 정확도나 동일 장면의 전후 정확도 비교가 아닙니다. 사용자의 말은 모델 입력이나 강제 라벨로 사용하지 않았습니다.

## Full/Heavy를 직접 비교한 결과

[Google 공식 모델 안내](https://developers.google.com/edge/mediapipe/solutions/vision/pose_landmarker?hl=en)와 [공식 Web 샘플의 모델 URL](https://github.com/google-ai-edge/mediapipe-samples-web/blob/main/src/tasks/pose-landmarker.ts)을 확인했습니다. 공식 배포 Heavy 파일을 로컬에 내려받아 RTX 5070 Laptop GPU에서 기존 Full과 같은 설정으로 비교했습니다.

자료는 현재 환경의 **저장된 정지영상 6장**(바로 누움 두 시점×두 카메라, 과거 미검출 옆누움×두 카메라)이며, 각 영상에서 추론기를 재설정하고 8회 반복했습니다. 처음 3회를 제외한 중앙 처리 시간을 기록했습니다. 이 반복은 48개의 서로 다른 실제 프레임이나 독립 정답 평가가 아닙니다.

| 항목 | Full | Heavy |
|---|---|---|
| A 바로 누움의 가시 관절 중앙값 | 17 | 17 |
| B 바로 누움의 가시 관절 중앙값: 현재/이전 영상 | 15 / 15 | 13 / 12 |
| 과거 옆누움 미검출 두 영상 | 모두 미검출 | 모두 미검출 |
| 누움 영상의 GPU 추론 중앙 시간 범위 | 약 13.6~16.2ms | 약 16.5~18.3ms |

**현재 자료에서 Heavy가 낫다는 근거가 없어 Full을 유지**했습니다. 관절 수/모델 신뢰도는 좌표 정답 오차가 아니므로 이 표로 절대 정확도 순위를 정하지 않습니다. 로컬 `outputs/pose-model-comparison.json`에 원시 결과를 보존했습니다.

Heavy 파일: 공식 `pose_landmarker_heavy/float16/1`, 30,664,242 bytes, SHA256 `64437af838a65d18e5ba7a0d39b465540069bc8aae8308de3e318aad31fcbc7b`. 모델/카메라 영상은 커밋하지 않습니다.

## 미검출 방향 재시도

옆누움 미검출 영상에 90/180/270도 입력 회전을 비교했습니다. A는 전부 실패했고 B는 90도에서만 8회 모두 몸통 관절이 출력됐습니다. B의 가시 관절 중앙값은 10개, 무릎은 미검출이었습니다. 원본 영상에 점을 다시 겹쳐 좌표 방향을 확인했습니다. 이 결과는 **몸통 검출 복구**이지 해당 자세의 분류 정확도 보장은 아닙니다.

실제 `BrowserGPUAdapter`에 다음을 반영했습니다.

- 정상 검출 중에는 추가 추론을 하지 않습니다.
- 미검출일 때만 최대 500ms마다 한 방향을 추가 시도합니다. 후보 순서는 정방향/90/270/180도이며 현재 방향은 제외합니다.
- 방향 전환 시 tracking ROI를 재설정하고, 성공한 방향은 이후 프레임에도 유지합니다. 모든 방향 실패면 사람/관절을 생성하지 않습니다.
- 이미지 XY·폭 기준 상대 Z와 world XYZ를 원래 카메라 좌표로 역변환합니다. 해부학적 좌우 ID는 교환하지 않습니다.
- SDK 내부 호출 시각은 증가시키되 외부 관측의 frame_id/수신 시각/model_timestamp는 원래 프레임 기준을 유지합니다. 다른 시각의 프레임을 한 쌍으로 꾸미지 않습니다.
- 각 원본 관절 관측에 `inference_rotation_ccw_degrees`를 기록하고 모니터에 카메라별 검출 방향 보완 상태를 제공합니다.

단일 회전 재시도는 미검출 구간에서 추가 지연을 만들 수 있습니다. 표시 평활화는 이 지연/좌표 정확도를 해결하는 대체물이 아닙니다.

## 카메라별 기하 근거 충돌 처리

삼각측량과 단일 A/B 3D를 각각 같은 침대 평면에 대해 분류한 결과를 `view_evidence`에 남깁니다. 이 결과들은 같은 SDK/영상을 공유하는 **상관된 근거**이므로 독립 확률이나 다수결로 해석하지 않습니다.

선택된 관측과 다른 자세를 가리키는 후보가 있으면 경고/최소 1.2초 안정화를 적용합니다. 반대 후보가 충분한 관절 품질(초기 기준 0.65 이상)을 가진 경우에는 `conflicting_pose_evidence`로 보류합니다. 이 수치는 정답 확률이 아니며 실제 평가를 거친 최적 임계값도 아닙니다.

## 확인과 남은 제약

방향 복원/반복 실패/재시도 빈도/추적 초기화 신규 검사 5개와 다중 기하 근거 충돌 신규 검사를 포함해 관련 Python 검사 72개 및 TypeScript/Vite 빌드가 통과했습니다. 실제 GPU에서 실패했던 B 정지영상의 자동 방향 재시도/원본 좌표 복원을 실행했습니다. 실제 서버 재시작 후 입력·침대·서 있음/누움 축 복원을 확인했습니다. 화면 제목도 내부 좌표계 이름 대신 `침상 3D 모니터`로 수정했습니다.

전체 6자세의 독립 정답·사람별/세션별 평가자료가 없어 정확도 %·혼동행렬·일반화 성능은 아직 제시할 수 없습니다. 가림·이불·매트리스 변형·잘못된 보정·다른 사람 선택·물리적 카메라 이동은 남은 실제 검증 항목입니다. 기존 MediaPipe/CLIP 경로를 제거하거나 ToF/학습 정답 저장을 시작하지 않았습니다.
