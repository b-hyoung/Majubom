# 자동 카메라 보정 · 정적 배경과 10초 대기

[프로젝트 홈](../../README.md) · [3D 모니터 기본 사용법](ROOM_MONITOR.md) · [선택 보정 방식](SCREEN_CALIBRATION.md)

2026-11-01 최신 요청으로 **마커 없는 자동 정적 배경 보정**을 기본으로 변경했습니다. 체커보드/ArUco/화면 패턴은 필수가 아닙니다. 기존 선택 방식은 유지하고 MediaPipe·CLIP·자세 판정·기록 규칙을 변경하지 않습니다.

**이번 구현 작업 중에는 실제 자동 보정을 시작하지 않았습니다.** 사용자가 “보정 시작”이라고 지시하거나 화면에서 시작 버튼을 누른 경우에만 10초 카운트다운을 시작합니다. 서버 재시작, 카메라 연결, 입력 저장, 페이지 열기, 저장값 불러오기는 촬영을 시작하지 않습니다.

## 시작 절차

기존 `python -m bed_pose live`와 작업실 상단 **3D 공간 모니터**를 사용합니다. GPU 실행은 기존 `--pose-device browser_gpu --pose-max-people 1` 옵션을 유지합니다.

1. 두 카메라를 같은 방의 **서로 겹치는 정적 배경**이 보이도록 고정합니다. 카메라를 움직이지 않습니다. 사람·화면 동영상·커튼처럼 움직이는 물체를 가능한 한 시야에서 제외합니다.
2. 기본 방식 **자동 · 정적 배경 특징점**에서 SIFT(기본) 또는 ORB를 선택합니다.
3. 알려진 A/B 내부 행렬 K·왜곡 계수·원본 해상도가 있으면 입력합니다. 적용된 기존 보정에서 내부값을 가져올 수도 있습니다. 임의의 기본 초점거리나 왜곡 0을 실제 내부값으로 자동 채우지 않습니다.
4. 실제 거리 척도가 필요하면 **두 렌즈의 광학 중심 사이 거리(m)**를 재서 입력합니다. 외장 케이스 모서리 간 거리나 방 길이를 기준선으로 대신 쓰면 안 됩니다.
5. **입력만 저장**은 설정만 저장합니다. “시작” 지시 전에는 실제 보정을 수행하지 않습니다.
6. **자동 보정 시작 · 10초 후 촬영**을 누르거나 이 대화에서 “보정 시작”이라고 지시합니다. 모두 시야에서 비켜 주세요. 시작 요청 시점의 PC 단조 시각에서 정확히 10초 이상 기다린 뒤 새 프레임을 수집합니다. 대기 전에 찍힌 프레임은 사용하지 않습니다.
7. 350ms 이상 떨어진 새 동기화 프레임 쌍 세 개를 수집하고 별도 스레드에서 계산합니다. 10초 이후 8초 안에 충분히 신선한 실제 카메라 프레임을 확보하지 못하면 실패입니다. UI에서 대기/수집/계산/실패를 구분하고 취소할 수 있습니다.

카메라 연결/해상도/방 설정이 진행 중 바뀌면 취소합니다. 대기나 계산을 취소한 뒤 늦게 끝난 작업은 결과를 저장하거나 현재 상태를 덮어쓰지 않습니다. 계산 시작은 기존 보정의 설치/동일 대상 확인도 해제하므로 새 보정이 실패했을 때 예전 보정을 무심코 현재 3D에 쓰지 않습니다.

## 내부값과 기준 길이에 따른 가능 범위

| 입력 | 가능한 결과 | 불가능하거나 차단되는 것 |
|---|---|---|
| 영상 두 개만 | 정적 특징점, 상호 대응, F RANSAC, 인라이어/에피폴라 진단 | 정확한 상대 R/t·미터 3D·방 좌표를 확정하지 않음 |
| 알려진 두 내부값/왜곡/해상도 | E·recoverPose 상대 회전과 이동 방향 | 기준선 없으면 실제 거리 미확정 |
| 위 값 + 실제 렌즈 중심 간 거리 | 카메라 A 기준 미터 상대 배치 | 방 원점/위쪽/침대 좌표는 자동으로 생기지 않음 |
| 위 값 + 실측 카메라 A→방 변환 | 품질 검사를 통과한 방 좌표 보정 후보 | 실제 정확도 인증·노출 동기화·동일인 인증은 아님 |

내부값이 없으면 F와 영상 대응 품질까지만 계산하며 `needs_input / fundamental_only`로 표시합니다. 이것을 보정 성공이나 실제 3D 추적 가능 상태로 표시하지 않습니다. 최소 입력은 각 카메라의 **K(fx/fy/cx/cy), 왜곡 계수, 그 값이 유효한 원본 해상도**입니다. 두 영상으로 이 모든 값과 실제 척도를 일반적으로 유일하게 정할 수 있다고 주장하지 않습니다.

거리 없이 얻은 이동 방향은 `baseline_units`(기준선=1 상대 단위), 실측 거리를 넣은 상대 배치는 `m`입니다. 해당 결과는 **camera_a 좌표계**이며 OpenCV의 X 오른쪽/Y 아래/Z 앞쪽입니다. Three.js의 별도 상대 배치 미리보기에 A 청록·B 주황의 위치/광축/알려진 K의 시야와 연결선을 표시합니다. 이는 방/침대 속 실제 위치가 아닙니다.

방 배치에 연결하려면 `room_transform`의 `rotation`(3×3 오른손 정규 회전), `translation`(카메라 A 중심의 방 XYZ m), `measured:true`를 실제 측정 자료로 입력합니다. `X_room = R_cameraA_to_room X_cameraA + t_cameraA_to_room`입니다. 기존 관절 복원은 `room_world`만 받으므로 임의의 중력 방향/침대 위치를 만들어 쓰지 않습니다.

## 사람과 움직임 제외

세 프레임에 걸쳐 다음 제외 영역을 합칩니다.

- MediaPipe가 반환한 **모든 후보**의 원본 관절 및 공통 관절에서 몸 전체 사각형을 만들고 여백을 확장합니다. 최종 추적 대상만 제외하는 방식이 아닙니다. 원본 후보의 관절이 심하게 불완전하면 그 영상 전체를 제외하는 보수적 경로를 사용합니다.
- 별도의 OpenCV HOG 사람 검출기를 보정 작업 스레드에서 실행하고 검출 사각형을 확대해 제외합니다. 새로운 사람 모델 다운로드는 필요하지 않습니다. GPU 단일 대상 모드의 추가 인물 누락을 보완하는 진단이며 완전 검출을 보장하지 않습니다.
- 시간에 따른 영상 변화 영역을 구합니다. 균일 노출 오프셋을 제거한 뒤 변화량이 큰 부분을 팽창시켜 제외합니다. 카메라 이동/큰 배경 변화/정적 영역 부족은 실패 처리합니다.

제외 마스크를 SIFT/ORB의 `detectAndCompute`에 직접 전달합니다. 양방향 ratio test와 상호 최근접 검사를 통과한 대응만 RANSAC으로 넘깁니다. 추론 실패 프레임을 ‘사람 없음’으로 취급하지 않습니다. **미검출된 정지 인물까지 전부 제외한다고 보장할 수 없으므로 빈 방에서 보정하는 것이 우선**입니다. CLIP 점수나 자세 라벨로 사람 부재를 단정하지 않습니다.

## 품질과 실패 처리

현재 정책은 실제 정확도 평가 전 초기값입니다. 값과 버전은 결과에 보존합니다.

| 검사 | 초기 정책 |
|---|---|
| 상호 대응 수 | 40개 이상 |
| F/pose 인라이어 | 30개 이상, 비율 0.55 이상 |
| 인라이어 공간 범위 | 양쪽 볼록껍질 면적이 영상의 8% 이상 |
| 단일 평면/순수 회전 우세 | 호모그래피 비율 0.85 초과 거부 |
| 시차 | 유효 관절이 아니라 배경 복원점의 중앙값 1.5° 이상 |
| 재투영 | 알려진 K·왜곡 제거 픽셀에서 RMS 2px 이하, p95 3px 이하 |
| 프레임 간 일관성 | 회전 차이 최대 2°, 이동 방향 차이 최대 5° |
| 움직임/마스킹 | 변화 영역 35% 초과 또는 사용 가능한 정적 영역 20% 미만 거부 |

각 프레임에서 F RANSAC과 알려진 K가 있을 때 E RANSAC/recoverPose를 수행합니다. 앞쪽에 놓이는 배경점·시차·재투영·분포를 검사하고 세 시점의 R/t 방향 일관성을 비교합니다. 지표에는 특징점 수, 대응 수, F/pose 인라이어 수·비율, 호모그래피 비율, 영역 범위, 재투영 RMS/p95, 시차, 시간적 자세 편차, 사람/움직임 제외 비율을 남깁니다. 내부값이 없으면 재투영 오차는 null이며, 대신 F의 에피폴라 거리 진단을 제공합니다. 둘을 같은 오차로 취급하지 않습니다.

가려진 공통 시야, 텍스처 부족, 반복 무늬, 평면 장면, 작은 시차, 높은 재투영 오차, 움직임 또는 내부값 불일치가 있으면 이유와 계산 가능한 지표를 표시합니다. 품질 실패 결과는 현재 후보로 승격하거나 적용하지 않습니다. `triangulation_eligible`이 false이면 적용 버튼과 백엔드 검증 모두 차단합니다. 기존 MediaPipe 단안 상대 z나 데모 관절로 대체하지 않습니다.

재투영 오차는 검출 대응의 기하 일치도이며 실제 신체 관절의 오차/정답 확률이 아닙니다. 비슷하게 틀린 반복 무늬 대응이나 잘못된 내부값이 모든 검사를 통과할 수 있습니다. 별도 실측 타깃/좌표로 실제 정확도를 확인해야 합니다.

## 저장과 재사용

로컬 `<output-root>/.monitor/`에 다음 파일을 보관합니다.

- `automatic-inputs.json`: 알려진 내부값·해상도, detector, 실측 기준선, 선택 방 변환. 저장/복원만으로 실행되지 않습니다.
- `automatic-result.json`: 추정 결과·시각·세 프레임 ID/수신 시각·바인딩·정책·지표·내부값 해시와 결과 SHA256. RGB는 여기에 저장하지 않습니다.
- 기존 `calibration-candidate.json`, 적용 시 `calibration.json`: 기존 호환 경로 유지.

**저장된 자동 보정 재사용**은 이전 후보를 불러오며 촬영하지 않습니다. 내부값/실제 배치/렌즈·초점/해상도·자르기·회전이 같아야 합니다. 카메라의 물리 이동을 자동 인증하지 못하며 운영자가 확인해야 합니다. 새 프로세스에서는 설치/동일 대상 확인을 다시 요구합니다. 약한 후보·무척도 후보·방 정렬 없는 후보는 불러와도 실제 방 삼각측량에 사용하지 않습니다. 파일 해시는 우발적 변조/손상 확인이며 측정 출처 인증은 아닙니다.

## API와 다음 대화의 실행 규칙

모든 API는 기존 로컬 작업실 토큰/동일 출처 검사를 유지합니다.

| POST 경로 | 역할 |
|---|---|
| `/api/room/automatic-inputs` | 입력만 저장 |
| `/api/room/automatic-start` | 현재 입력으로 10초 카운트다운 시작 |
| `/api/room/automatic-cancel` | 대기/수집/계산 취소; 늦은 결과 폐기 |
| `/api/room/automatic-restore` | 저장된 이전 후보 복원 |
| `/api/room/apply-candidate` | 검사 통과·실측 척도·방 정렬이 있는 후보만 적용 |

`GET /api/room/status` 또는 `/api/room/live`에 `automatic_inputs`, `automatic_saved`, `calibration_job`을 제공합니다. 시작 요청 본문은 `{detector:"SIFT",baseline_m:null,cameras:null,room_transform:null}` 형식이며 저장된 입력을 사용할 때는 현재 `automatic_inputs`를 그대로 보냅니다. 카메라 내부값을 추측해서 넣지 않습니다.

**사용자가 이후 “보정 시작”이라고 하면** 현재 저장된 입력과 카메라 상태를 확인하고 이 시작 API를 한 번 호출합니다. 10초 대기는 서버에서 진행하며, 10초가 지나기 전 촬영/추정을 별도 실행하지 않습니다. 이후 상태를 확인해 결과 또는 실패 원인을 알립니다. 사용자 시작 지시가 없으면 API를 호출하지 않습니다. 현재 빈 입력이면 F 진단만 가능한 상태임을 알리고 임의의 K/기준선/방 변환으로 성공 처리하지 않습니다.

## 변경과 검증 범위

새 모듈 `automatic_calibration.py`와 자동 UI `AutomaticCalibration.tsx`, 상대 배치 뷰 `RelativeRig.tsx`를 추가했습니다. `room_monitor.py`의 대기·수집·취소·저장, `live_web.py`의 tick/API, `calibration.py`의 자동 품질/척도 적용 검사를 확장했습니다. 기본 방식 선택·타입·정적 프론트 빌드와 관련 문서를 갱신했습니다. 기존 MediaPipe/CLIP 분류기와 기록 형식은 유지합니다.

새 자동 검사 11개는 합성 카메라의 이상치/RANSAC/척도/재투영/방 변환, K 누락/무척도/평면 실패, 실제 SIFT·ORB 마스크 전달, 사람/움직임 제외, 가짜 단조 시계의 정확한 10초 경계·오래된 영상 거부·세 쌍 수집·취소 경쟁·저장/복원을 확인합니다. 테스트에서 실제 사용자 카메라 자동 보정을 실행하지 않습니다.

프론트엔드 TypeScript/Vite 빌드, Python wheel, 토큰 차단/카운트다운/취소 API를 확인했습니다. 실제 서버는 두 GPU 입력이 preview인 상태와 자동 보정 idle을 HTTP로 확인했습니다. 이번에는 Work 설정에서 브라우저 제어가 비활성화되어 **새 UI/상대 카메라 미리보기의 브라우저 육안 검사는 미수행**입니다. 실제 빈 방 촬영·내부값/기준선 입력·보정 품질·실측 3D 정확도는 사용자 시작 지시 이후의 작업입니다.
