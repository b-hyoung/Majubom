# 카메라 자세 표시와 95% 검증

## 2026-11-02 여섯 자세 첫 실측 점검

후속0.3: 단일 대상의 사람 확인이 기존 두 방향에서 실패하면 직교 두 방향도 확인한다(성공하면 즉시 종료, 최대4방향/500ms 주기). 왼쪽 누움B 정지영상15회에서 이전0회→수정15회 검출을 확인했으나 A는0회이며 실시간 성능·정답 좌표 개선으로 확대 해석하지 않는다. 양반다리는 영상상 골반·양 무릎이 침대 안에 있고 추정 몸통이 수직, 양 허벅지가 수직이 아닐 때 앉음 후보를 보완한다. 발목·실측3D 접촉을 만들어내지 않는다. 관절14개 미만의 기하 판정은 CLIP 방향을 덮어쓰지 않고, 현재 자세와 다른 후보는0.5초·3개 새 관측을 요구한다. 미검출이면 기존 자세를 즉시 비운다. 첫 추정은 즉시 표시한다. 모든 기준은 실험값이며 새 장면 재확인이 필요하다.

검사: 관련 소프트웨어90개 통과. 이전에 사람이 없는 것을 육안 확인한 두 카메라 정지영상 각20회 GPU 반복에서 사람 오검출0회, 응답 소실/동일GPU 대체 통신 검사가 통과했다. 저장 양반다리B의 실제 관절 재추론과 의도적으로 강한 기타 CLIP 입력을 결합한 개발 검사에서 앉음 보완 경로가 작동했다. 이는 새 실제 영상 정확도 평가가 아니다.

사용자의 각 준비 완료 응답 직후 실제 두 영상을 확인했다. 바로 누움은 왼쪽 누움으로 오분류, 왼쪽 누움은 순간 일치 후 검출 소실, 오른쪽 누움은 조회6회 일치, 엎드림은 왼쪽 누움 후 검출 소실, 침대 위 앉음과 걸터앉음은 기타로 오분류했다. 이는 자세당 한 구간의 개발 점검이며95% 평가가 아니다. 로컬 `outputs/camera-posture-guided-20261102/`에 영상 표본과 판정 근거를 보존하고 Git에는 올리지 않는다.

0.2는 등록된 침대 영상 영역 안/가장자리의 동일 관측에서 클래스별 엄격 기하 판정이 성립할 때 그 결과80%와 CLIP20%를 결합한다. 이전에는 기하가 바로 누움·엎드림·걸터앉음을 맞혀도 CLIP이 무조건 덮어썼다. 이 비율은 개발용 초기 정책이며 실측 최적값이 아니다. 충돌은 경고로 기록하고 정확도/학습 승인은 여전히 false이다. 새 코드의 실제 재촬영 검증, 왼쪽 누움의 사람 검출 소실, 양반다리 앉음의 분류 실패는 해결 확인 전이다.

2026-11-02 사용자 요청: 관절이 관측되면 현재 자세를 바로 표시하고, **카메라 여섯 자세 정확도 95% 이상을 확인한 뒤 ToF를 재학습**한다. 현재 실제 여섯 자세 평가는 하지 않았으며, 사용자가 지금 실측을 진행하지 말라고 요청하여 촬영·검증·ToF 학습을 대기한다.

## 실행과 현재 확인 범위

Majubom의 CUDA 학습 환경을 재사용하는 실행기:

```powershell
.\Start-CameraGPU.ps1
```

첫 설치에서는 `training/Setup-Training.ps1`로 CUDA PyTorch 환경을 준비한 후 다음을 실행한다. 설치·가중치 준비는 명시적이며 추론 중 다운로드하지 않는다.

```powershell
& ..\.venv-training\Scripts\python.exe -m pip install -e '.[clip,live,stereo]'
& ..\.venv-training\Scripts\python.exe -m bed_pose clip-setup
```

이 노트북에서 PyTorch2.11.0+cu128, Transformers4.57.6, CLIP ViT-B/16 고정 리비전 `57c216476eefef5ab752ec549e440a49ae4ae5f3`을 준비했다. RTX5070에서 CUDA FP16 이미지 추론과 FP32 점수 계산을 확인했다. 첫 호출 후 단일 반복 호출은 약8.7ms였으며 지속 처리량이나 자세 정확도 측정은 아니다. 실제 서버의 빈 침대 입력에서 두 카메라 약29–30FPS, MediaPipe browser_gpu와 공유 CUDA CLIP을 확인했다. 사람 자세에서의 추가 부하와 정확도는 아직 미검증이다.

실행기는 물리 역할을 이름으로 연결한다(A=C920, B=USB2.0 PC CAMERA). 640×480/30FPS를 요청하고 기존 보정 후보와 침대 모서리를 읽는다. 동일 해상도의 저장 모서리는 각 입력의 2D 침대 영역에도 복원한다. 이는 현재 카메라를 옮기지 않았다는 가정이며, 카메라 이동 시 기존 영역/보정과 검증 결과를 재사용하면 안 된다. 현재 API 주소와 토큰은 Git 제외 `outputs/live-connection.json`에만 둔다.

## 주 화면과 엄격한 3D 판정

`/api/room/status`와 `/api/room/live`의 `camera_posture`가 현재 화면용 추정이다. 현재 프레임의 CLIP 상태·누운 방향 점수, 등록된 2D 침대 경계, 선택적인 단안 관절 기하를 사용한다. 외부 ToF 값·목표 자세·정답 주석은 예측 입력에 사용하지 않는다.

- CLIP 앉음 + 골반/다리의 영상상 침대 가장자리 관계로 걸터앉음을 표시한다. 미검증 3D 높이 때문에 이 영상 판정을 막지 않는다.
- 한 카메라만 유효해도 그 시점을 사용한다. 두 시점에서 침대 안 사람이 관측되면 해당 근거를 우선하고, 충돌은 경고로 남긴다. 자동 동일인 인증은 아니다.
- 첫 관측부터 추정을 표시하고 약120ms 시정수의 인과적 점수 평활화를 적용한다. 같은 프레임을 여러 번 조회한 것은 안정화 표본으로 세지 않는다.
- 사람 소실, 입력 만료(350ms), 다인 모호성, 대상 변경 때 이전 자세를 계속 표시하지 않는다.
- CLIP은 옆누움의 좌우를 직접 구분하지 않는다. 관절 기하로 좌우를 보완하며 근거가 없으면 ‘옆으로 누움·좌우 확인 중’으로 표시한다. 임의로 왼쪽을 선택하지 않는다.
- 유효한 영상 점수와 복원 가능한 관절이 모두 없으면 ‘관절 추적 중·자세 분석 중’이다. 관절 한 점만으로 여섯 자세의 정확성을 보장하지 않는다.

화면 점수는 상대 적합도이며 정답 확률·실측 정확도가 아니다. `accuracy_verified=false`, `eligible_for_recording=false`를 유지한다. 기존 `posture_3d`와 ToF 엄격 수집 조건은 그대로 적용하고, 화면의 즉시 추정을 자동 정답으로 승격하지 않는다. 기본 `python -m bed_pose live`와 과거 기록의0.7/0.12 재계산 계약도 유지한다.

## 실제 평가를 재개할 때

사용자가 준비됐다고 할 때만 촬영을 시작한다. 고정 설치에서 바로 누움·엎드림·왼쪽 누움·오른쪽 누움·침대 위 앉음·걸터앉음을 각각 여러 번 확인한다. 조정에 쓴 장면과 최종 평가 장면은 분리한다. 빈 침대·서 있음·주변인·가림도 별도 부정 사례로 점검한다. 한 사람·한 설치의 결과를 모든 사람/환경 정확도로 확대하지 않는다.

예측만 수집하는 도구(원본 RGB나 정답을 자동 생성하지 않음):

```powershell
& ..\.venv-training\Scripts\python.exe tools/camera_posture_check.py capture --seconds 10 --out outputs/camera-validation/trial01.jsonl
```

관측 ID별 실제 자세를 독립 검토한 별도 JSONL을 작성한다. `label`은 `supine, prone, left_side, right_side, sitting, edge_sitting` 중 하나이다. 아래는 형식 예시이며 실제 검토가 아니다.

```json
{"observation_id":"수집된 ID","label":"edge_sitting","reviewed":true,"reviewer":"검토자","evidence":"실제 관찰/영상 위치","subject_id":"S01","session_id":"S01-test1","episode_id":"edge-repeat1"}
```

```powershell
& ..\.venv-training\Scripts\python.exe tools/camera_posture_check.py evaluate --predictions outputs/camera-validation/all-predictions.jsonl --reviews outputs/camera-validation/reviews.jsonl --out outputs/camera-validation/result.json
```

통과 정책은 전체 정확도≥95%, **각 자세 재현율≥95%**, 여섯 클래스 출력 coverage100%, 자세별 검토 표본30개 이상 및 별도 수행3회 이상이다. 관절 누락/미분류/좌우 미확정은 오답·누락에 포함한다. 미검토 예측을 숨겨 통과시키지 않으며 중복 관측, 검토 출처 누락, 카메라/모델/침대 설정 서명 혼합은 거부한다. 예측·검토 파일의 SHA256과 평가 범위를 결과에 보존한다. 검토 선언 자체의 진실성까지 소프트웨어가 인증하는 것은 아니다.

**현재95% 통과 결과는 없다.** 실제 평가 후에도 해당 설치·자료 범위의 결과이며 임상 성능이나 일반적인 관절 좌표 정확도를 뜻하지 않는다. ToF 재학습은 이 검증과 라벨 검토가 끝난 뒤 별도로 시작한다.
