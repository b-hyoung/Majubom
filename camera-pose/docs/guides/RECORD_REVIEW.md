## 측정 기록 조회 · 2026-10-28

<a id="browse-저장-영상과-기록-프레임-대조--2026-10-29"></a>
### 저장 영상과 기록 프레임 대조 · 2026-10-29

완료 기록에서 원본 영상 파일을 선택하고 표의 프레임 번호 또는 시간축 이동으로 원본 프레임·저장 관절·침대 영역·판정 근거를 함께 확인합니다. 전체 파일 SHA-256·원본 프레임 번호·PTS/시간축·픽셀 해시·크기를 확인하며 새 추론·정답 생성·기록 변경은 수행하지 않습니다. 원본 없는 카메라/합성 기록과 이전 기록은 기존 조회를 유지합니다. 순차 디코딩으로 긴 영상 뒷부분의 준비 시간은 남습니다. [사용법과 검증 계약](RECORD_REVIEW.md#image).

<a id="browse-사용법"></a>
### 사용법

기존 실행 명령은 같다.

```powershell
& .\.venv\Scripts\python.exe -m bed_pose live
```

1. 왼쪽 **측정 기록 보기**를 누른다. 카메라 연결 없이도 열 수 있다.
2. 목록에서 완료된 측정을 선택한다. 처음에는 목록 정보만 읽고, 선택할 때 원본 기록을 검사한다. 프레임 수에 따라 검사에 시간이 걸릴 수 있다.
3. 시간축에서 저장 자세·점수 범위·보류/충돌 구간을 확인하고 그래프 클릭 또는 슬라이더/버튼으로 해당 프레임을 연다. 아래 표에서 당시 자세·적합도·보류/참고 사유를 확인한다. 목록과 프레임은 기본 50개 단위로 이전/다음 페이지를 지원한다. [시간축 상세](RECORD_REVIEW.md#timeline).
4. 닫기를 누르거나 Escape로 실시간 작업실로 돌아간다. **조회 중에도 기존 입력 분석·진행 중 측정은 계속된다.**

목록은 기본 `recordings/live/<measurement_id>/`에서 읽는다. `--output-root`로 실행했다면 그 위치를 사용한다. 같은 위치로 다시 실행하면 지난 측정도 조회할 수 있다. 현재는 작업실이 생성한 UUID 형식 폴더의 개별 입력 측정을 지원한다. 그룹 측정의 개별 입력 기록도 이 위치에 저장되면 조회할 수 있지만, 그룹 전체 통합 결과 화면과 오프라인 benchmark `runs/` 형식은 이번 범위에 포함하지 않았다.

<a id="browse-영상-보조-근거-추가--2026-10-28"></a>
### 영상 보조 근거 추가 · 2026-10-28

새 기록에는 실루엣과 몸통 검사 지점 주변의 일치·충돌·확인 불가를 별도 열로 표시합니다. 보조 결과가 기존 자세 판정을 바꾸지는 않습니다. 이전 기록에 없으면 ‘당시 기록 없음’이며 새로 계산해 채우지 않습니다. [보조 검사와 한계](../design/SILHOUETTE_SUPPORT.md).

<a id="browse-표시-항목과-의미"></a>
### 표시 항목과 의미

| 항목 | 표시하는 내용 |
|---|---|
| 측정 목록 | 시작 시각(KST), 카메라/영상/합성 입력, 실행 완료/실패·미완료 상태, 기록 프레임 수와 ID |
| 기록 검사 | 열기 시 원본 해시·계약·당시 규칙의 결과 재계산 대조. 검사 전과 통과를 구분 |
| 실행 상태 | 기록 검사가 통과해도 실행 실패는 그대로 ‘실행 실패’로 표시 |
| 프레임 | 측정 안의 기록 순서와 입력 연결의 프레임 번호를 함께 표시 |
| 수신 경과 | `received_ns − manifest.started_ns`. 측정 시작 이후 처리·수신 시각이며 노출 시각이 아님 |
| 영상 상대시각 | 저장 영상의 원본 PTS 기반 상대 시각. 카메라/합성 입력에는 없는 값이며 `—` 표시 |
| 저장된 판정 | 당시 라벨, 보류, 판정 미사용, 처리 실패 또는 판정 필드 미기록을 구분 |
| 자세별 적합도 | 저장된 0.5의 독립 규칙 점수. 확률이 아니며 현재 가중치로 재분류하지 않음 |
| 결측 | 당시 적합도 계산 필드가 없으면 ‘계산 기록 없음’, 해당 프레임에서 비교 대상이 아니면 ‘조건 불충족’ |
| 보류·참고 | 당시 보류 사유, 가까운 점수 안내와 근거 충돌 경고, 처리 오류 코드 |
| 당시 설정 | 분류기 ID와 기록에 있는 최소 적합도 기준. 읽기 전용 |

‘기록 검사 통과’는 기록 내용의 일치 확인이며 **실제 자세의 정답·정확도 검증이 아니다.** 저장된 AI 판정을 실제 정답으로 바꾸거나 새 정답을 입력하는 기능은 추가하지 않았다. 프레임별 시각은 원본 ns를 유지하고 화면에서 초 단위 소수 셋째 자리로 표시한다.

<a id="browse-보존과-실패-처리"></a>
### 보존과 실패 처리

- `RecordLibrary`는 파일·모델 설정을 읽기만 한다. 기존 판정 모듈·가중치·0.65 기준·최종 라벨 선택을 변경하지 않는다.
- 열기 시 `verify_live`가 당시 프로필로 순수 계산을 대조한다. SDK 추론·카메라/원본 영상 읽기는 하지 않으며, 저장된 판정이나 점수 필드를 채우거나 덮어쓰지 않는다. 당시 필드가 없는 이전 기록은 없는 상태로 보여준다.
- 기록 중/미완료 자료는 목록에서 구분하고 열기를 비활성화한다. 손상된 목록 항목 때문에 다른 정상 기록을 숨기지 않는다. 완료 표시는 검사 통과 전까지 무결성 보장이 아니다.
- 열어 둔 원본이 바뀌면 페이지 요청에서 해시를 확인해 읽기를 거부하고 이전 내용을 숨긴다. 원본이 변경된 채 새로 열면 검사 실패를 표시한다.
- 인증된 로컬 작업실 API만 사용한다. 임의 경로 대신 목록의 측정 ID를 전달하며, 저장 루트 밖 경로·심볼릭 링크를 따라가지 않는다. 텍스트는 HTML로 해석하지 않는다.
- 메모리는 열린 기록 최대 4개의 프레임 위치 색인과 각 기록당 최대 4개의 제한된 시간축 요약을 보관하고, 원본 관절 전체를 누적 적재하지 않는다. 각 페이지에서 원본 변경을 확인하므로 큰 기록의 조회 속도는 디스크와 파일 크기에 영향을 받는다.

카메라는 선택적으로 분석 프레임을 녹화하고 대응 로그 행의 단일 프레임을 대조할 수 있다. 기록 화면의 연속 동영상 재생은 미구현이다. 저장 영상 측정은 원본 파일을 다시 선택해 정확한 단일 프레임을 대조할 수 있다. 시간축은 저장된 프레임 수와 점수 범위를 요약한다. 실제 자세 유지 시간 계산·화면에서 CSV 내보내기·기록 삭제/수정은 후속 작업이다. 기존 CLI CSV 내보내기는 그대로 사용할 수 있다.

<a id="browse-검사-범위"></a>
### 검사 범위

전체 210개 개발 검사 통과. 합성 입력으로 실제 측정 파일을 만들어 원본 라벨/점수 일치·조회 전후 파일 해시 보존, 목록/프레임 페이지, 인증·경로 제한, 기록 중·손상·파일 변경·실행 실패, 0프레임 및 필드가 없던 이전 기록을 검사했다. Chromium에서 빈 목록, 완료/미완료 구분, 점수·근접 안내, 50프레임 페이지 이동, 조회 중 다른 측정의 진행, HTML 문자열의 안전한 표시, 390/1440/2560px 배치와 JavaScript 오류 없음을 확인했다. wheel의 현재 읽기 모듈·HTML과 문서 링크를 확인했다. 실제 Windows 장치·사람 영상의 인식 성능 검증을 뜻하지 않는다.

시간축 추가 후 전체 234개 개발 검사를 통과했다. 시간 기준 분리·집계/결측·단일 보류/충돌 유지·프레임 이동·원본 보존·이전 기록·빈 기록과 브라우저 동작의 범위는 [시간축 검사](RECORD_REVIEW.md#timeline-검사-범위)를 따른다.

## 측정 기록 시간축 요약 · 2026-10-28

<a id="timeline-사용법"></a>
### 사용법

1. 작업실 왼쪽 **측정 기록 보기**에서 완료된 측정을 선택한다. 카메라를 연결하지 않아도 조회할 수 있다.
2. **시간축 요약**에서 기록 프레임 수, 자세 출력/보류/실루엣 충돌 프레임 수와 세 가지 차트를 확인한다.
   - 저장 자세: 구간 안 프레임의 자세/보류/미사용/미기록/처리 실패 분포다. 보류가 한 번이라도 있는 구간은 위쪽에도 표시한다.
   - 자세별 적합도: 점은 구간 평균, 세로선은 최소~최대다. 색상은 바로 누움·옆누움·걸터앉음에 대응한다. 점을 잇는 선은 구간 평균의 시각적 추세이며 원본 프레임 점수의 보간/재생성이 아니다. 점선은 기록 당시의 최소 기준이 있을 때 표시한다.
   - 실루엣: 일치·충돌·확인 불가·당시 미기록을 구분한다. 충돌이 한 번이라도 있는 구간은 아래쪽에도 표시한다.
3. 그래프 구간을 클릭하면 그 구간의 **첫 보류 → 첫 실루엣 충돌 → 첫 프레임** 순서로 검토할 원본 프레임을 고르고, 해당 50프레임 페이지로 이동해 행을 강조한다. 슬라이더/방향키로 구간을 선택한 뒤 **선택 구간 프레임 보기**, **이 구간 첫 보류/충돌** 버튼을 사용할 수도 있다. **전체 첫 보류/충돌 보기**로 문제 구간을 바로 찾는다.
4. 선택 구간의 실제 관측 시각 범위·프레임 번호·자세별 프레임 수·점수 평균/최소/최대와 점수 가용 프레임 수·상위 보류 사유를 확인한다. 이동한 프레임의 상세 표와 선택 요약을 함께 본다.

긴 표와 차트는 기록 창 안에서 스크롤한다. 작은 화면에서는 차트를 가로로 스크롤하거나 구간 슬라이더로 이동한다. 이 화면에서 원본 영상·전체 실루엣을 재생하지 않는다. **기록 조회 중에도 기존 실시간 분석과 진행 중 측정은 계속된다.**

<a id="timeline-시간집계의-의미"></a>
### 시간·집계의 의미

- 카메라/합성 입력의 기본은 **측정 수신 경과**: `received_ns − manifest.started_ns`다. 카메라 노출 시각이나 실제 자세 변화 시각이 아니다.
- 저장 영상의 기본은 **영상 상대시각 · 원본 PTS**: `source_media.relative_time_ns`이며 측정 시작부터 다시 0으로 맞추지 않는다. 수신 경과로 전환해 볼 수 있고 두 시각을 섞지 않는다.
- 모든 시각 계산은 서버에서 원본 정수 ns로 수행한다. 응답의 ns는 문자열로 보존하고 화면은 초 단위 소수 셋째 자리로 표시한다. 목록의 절대 시작 시각은 기존처럼 KST다.
- 전체 관측 시각 범위를 기본 최대 240개, API 최대 600개의 동일 시간 폭 구간으로 나눈다. 프레임 수가 더 작으면 구간 수를 줄인다. 관측이 1개이거나 모든 관측 시각이 같으면 1구간, 0프레임이면 차트 없이 빈 기록 안내를 표시한다. 마지막 시각의 프레임도 마지막 구간에 포함한다.
- 각 구간은 **저장된 프레임 수**를 집계한다. 가변 FPS·일시정지·결측이 있으므로 색상 비율이나 프레임 수를 자세 유지 시간·점유율·정확도로 해석하지 않는다. 프레임 사이의 자세나 사건 시점을 새로 판정하지 않는다. 관측 없는 구간에는 프레임 이동을 제공하지 않는다.
- 점수 평균/최소/최대는 실제 저장된 유효 값만 사용한다. `null`인 비교 불가 점수나 당시 점수 필드가 없는 프레임을 0으로 채우지 않는다. 구간에 가용 점수가 없으면 점/선을 그리지 않으며, 구간 내부 일부 결측은 선택 구간의 점수 가용 프레임 수로 구분한다. 최소~최대는 신뢰구간이 아니고 독립 적합도는 확률이 아니다.
- 한 구간에 짧은 보류/충돌이 섞여도 집계에서 제거하거나 다수 자세로 덮지 않는다. 상단/하단 존재 표시와 직접 이동을 제공한다. 픽셀 수가 제한된 전체 차트가 모든 개별 프레임을 구분하는 것은 아니다.
- 보류 사유는 같은 프레임 내 중복을 제거해 사유별 프레임 수로 집계한다. 여러 사유가 있으면 각각 집계하므로 합계가 보류 프레임 수보다 클 수 있다. 상위 8개를 표시하며 매우 다양한 이전 형식은 최대 63개 사유 코드와 ‘기타 사유’로 묶어 요약 크기를 제한한다.
- 실루엣 충돌은 저장된 보조 상태다. 관절·자세 오답의 확정이나 별도 정답이 아니다. 목표 자세·외부 센서·실제 정답은 집계 입력으로 사용하지 않는다.

<a id="timeline-구현-경계와-보존"></a>
### 구현 경계와 보존

`record_timeline.summarize(rows, manifest, basis, bins)`는 원본을 두 번 순회해 시각 범위와 제한된 구간 요약을 만든다. 원본 관절·영상·전체 마스크를 누적 적재하지 않는다. 분류기/SDK를 호출하지 않고 원본 자세와 점수를 새로 생성하거나 저장하지 않는다. 기존 `RecordLibrary.open`의 기록 검사는 그대로 수행한다.

인증된 로컬 `GET /api/records/timeline?record_id=<ID>&basis=receive|media&bins=240`을 제공한다. 먼저 기존 기록 열기로 검사를 통과해야 한다. 지원하지 않는 시간 기준·구간 수·경로·미개방 기록은 거부한다. 생략한 시간 기준은 입력 종류에 맞춰 정한다. 반환 형식은 `record-timeline-0.1`, 원본 기록 스키마·classifier 프로필·0.65 기준은 바꾸지 않는다.

기록당 최대 4개의 요약을 메모리에 재사용하며 열린 기록은 기존처럼 최대 4개다. 캐시를 사용할 때도 원본 해시를 검사하고 처음 요약할 때는 순회 전후에 검사한다. 원본이 달라지면 조회를 거부하고 이전 내용을 숨긴다. 새 조회는 작업실의 실시간 측정 잠금과 분리한다. 큰 기록은 초기 검사/요약과 이후 파일 해시 확인에 시간이 걸릴 수 있다. 대규모/실제 PC 지연 측정은 별도다.

기존 프레임 표 API, 기록 파일·가중치·판정 기준·보류 조건은 유지한다. 이전 기록에 없던 자세/점수/실루엣을 소급해서 채우지 않는다. 읽기 전용이며 정답 편집·영상 재생·시간 유지율 계산·시간적 안정화·외부 센서 융합은 추가하지 않았다.

<a id="timeline-검사-범위"></a>
### 검사 범위

전체 **234개 개발 검사**를 통과했다. 구간 집계의 단일 보류/충돌·마지막 프레임·정확한 점수 범위/평균·중복 사유·시간 공백·동일/0프레임 시각·두 시간 기준·점수/판정/실루엣 결측·사유 수 제한을 검사했다. 실제 생성 영상의 PTS와 수신 시간 분리, 인증·경로/구간 수 제한·열기 선행 조건·캐시 후 원본 변경 거부·조회 전후 파일 해시 보존·이전 기록 호환도 검사했다.

Chromium에서 제어한 SDK 출력으로 자세/보류/실루엣 충돌이 섞인 실제 기록 파일을 열어 차트·집계·그래프 클릭/슬라이더/방향키·첫 문제 프레임 이동·50프레임 경계 이동과 정확한 행 강조를 확인했다. 다른 실시간 측정의 지속, 저장 영상의 시간 기준 전환, 0프레임/이전 형식, 텍스트의 HTML 비해석, 390/1440/2560px 배치, 원본 변경 시 숨김과 JavaScript 오류 없음을 확인했다. 기록 조회/실루엣 표시의 기존 브라우저 경로도 재확인했다. 이 검사는 실제 사람의 자세 정확도나 모델 개선 효과를 측정한 것이 아니다.

배포 wheel의 시간축 모듈·기록 조회·웹 API·HTML이 현재 소스와 같은 것도 확인했다.

<a id="image-원본-프레임과-저장-결과-대조--2026-10-29"></a>
## 원본 프레임과 저장 결과 대조 · 2026-10-29

<a id="image-사용법과-지원-범위"></a>
### 사용법과 지원 범위

측정 기록 보기 → 완료된 영상 파일 기록 선택 → 원본 프레임 대조에서 측정에 사용한 영상 선택 → 표의 프레임 번호 버튼. 시간축의 프레임 이동도 대조 패널에 연결한다. 선택 영상은 기존 업로드 API로 로컬 임시 복사하고 작업실 종료 시 정리한다. 기록에 저장된 경로로 임의 파일을 자동으로 열지 않는다. 카메라 없이 조회할 수 있으며 라이브 측정은 별도로 계속된다.

기록 프레임 번호와 입력 스트림 프레임 번호, 원본 디코딩 프레임 번호는 구분한다. 첫 프레임 미리보기 뒤 측정을 시작하면 첫 기록 프레임은 원본 0번이 아닐 수 있다. 수신 경과로 영상 시점을 추정하거나 FPS로 프레임을 역산하지 않는다.

<a id="image-대응-검증"></a>
### 대응 검증

인증된 POST `/api/records/image`는 `record_id`, 정수 `frame_id`, 기존 영상 업로드의 `video_asset`을 받는다. 먼저 열린 검증 기록만 지원하고 자산 ID를 통해서만 원본을 읽는다. API가 받은 경로나 기록 속 원본 경로를 파일 접근에 사용하지 않는다.

기록 원본 해시를 전후 검사한다. 같은 VideoFileSource의 정규 RGB/회전/PTS 정책으로 원본 파일을 순차 디코딩한다. 전체 영상 SHA-256이 측정 당시와 같고, 해당 원본 프레임의 PTS·time base·상대 PTS 시각·픽셀 해시·원본 번호와 실제 크기가 저장값과 일치할 때만 표시한다. 디코더 차이로 픽셀이 달라도 대조를 보류한다. 잘린 영상이나 재인코딩본은 같은 장면이어도 원본으로 인정하지 않는다. 디코딩 종료 시 영상 파일 변경도 검사한다.

영상은 기존 고화질 JPEG 설정으로 전달한다. 픽셀 해시는 JPEG 압축 전 정규 RGB에 대한 확인이며 브라우저 영상이 무손실이라는 의미는 아니다. 저장된 관절과 그 프레임의 영역 revision에 대응하는 침대 경계를 같은 좌표 변환으로 그린다. 저장된 자세/가중 근거·실루엣 보조 상태는 접이식 상세에 그대로 표시한다. 전체 실루엣 마스크는 기록되지 않아 복원하거나 새 추론으로 채우지 않는다.

<a id="image-실패와-자원"></a>
### 실패와 자원

원본이 없어도 목록·표·시간축 조회를 유지한다. 카메라/합성 입력, 원본 정보 없는 이전 기록, 빈 기록에서는 원본 대조를 제공하지 않는다. 선택 변경·페이지 이동·기록 전환·창 닫기 뒤 도착한 이전 응답은 UI 세대로 거부하며, 영상 준비 오류는 기록 조회나 라이브 연결 종료로 처리하지 않는다.

같은 열린 기록의 디코딩은 직렬화하고 전체 프레임 배열은 보관하지 않는다. 매 요청은 파일 해시와 시작부터의 순차 디코딩을 수행하므로 큰 영상의 뒷부분은 느릴 수 있다. 빠른 임의 탐색·전체 카메라 프레임 녹화·연속 재생·정답 주석·유지 시간/정확도 계산은 후속 범위이다. 프레임 대응 검증은 저장된 관절/자세의 정확도 검증과 별개이다.

<a id="image-개발-검사"></a>
### 개발 검사

생성 FFV1 영상과 SDK 대역으로 측정 시작 전 프레임과 기록 프레임의 번호 차이, 첫/끝 프레임의 PTS/픽셀 대응, 저장 근거 보존, 무추론·기록 해시 불변, 잘못된 원본/번호/자산/인증/변경 기록 거부를 확인한다. 원본 없는 기록은 조회가 계속되는지 검사한다. Chromium에서 원본 선택·프레임 선택·근거 상세·좁은/넓은 화면·창 닫기를 확인한다. 실제 사람의 자세 성능을 검증한 결과는 아니다.


<a id="posture-accuracy"></a>
## 자세 정확도 평가 · 별도 검토 주석이 있을 때

`posture-evaluate`는 저장 당시 예측을 재분류하지 않고 별도 주석과 비교합니다. **목표 자세·센서 결과·신체 형태 후보를 정답으로 사용하지 않습니다.** CLIP 실행 제공자는 별도로 구현했으며 사전학습 가중치와 정답 영상은 이 평가 도구에 포함하지 않습니다.

```powershell
# 정답 주석이 없으면 미평가 상태와 기록 수만 보고합니다.
& .\.venv\Scripts\python.exe -m bed_pose posture-evaluate --run "recordings/live/<measurement_id>" --output "reports/posture_check"

# 실제 수행을 따로 검토한 주석이 있는 경우
& .\.venv\Scripts\python.exe -m bed_pose posture-evaluate --run "recordings/live/<measurement_id>" --annotations "annotations/reviewed.json" --output "reports/posture_accuracy"
```

출력 폴더는 새 경로여야 하고 원본 측정 폴더 내부는 허용하지 않습니다. 원본 무결성을 검사하고 원본·주석의 SHA-256을 보고서에 기록합니다. 명령 성공은 보고서 작성 성공이며 실제 정확도 검증 완료를 뜻하지 않습니다.

주석 파일 구조는 다음과 같습니다. 아래는 **빈 형식 예시이며 실제 정답 자료가 아닙니다.** `measurement_id`를 해당 기록의 ID로 바꾸고, 검토한 입력 프레임만 추가합니다.

```json
{
  "version": "posture-annotations-0.1",
  "measurement_id": "해당 측정 ID",
  "label_source": "reviewed_video",
  "review_protocol_id": "사용한 검토 절차 ID",
  "frames": []
}
```

`frames`의 각 항목은 `stream_frame_id`(정수), `label`, `annotation_id`(검토 이력 ID), `uncertainty_reason`을 갖습니다. **입력 프레임 번호**를 사용하며 기록 행 번호·원본 파일 프레임 번호와 혼동하지 않습니다. 중복 번호·측정 ID 불일치·기록에 없는 프레임은 거부합니다.

- `label`: `supine`, `side`, `edge_sitting`, `sitting`, `standing`, `other`, `uncertain` 중 하나.
- 확실한 라벨의 `uncertainty_reason`은 null입니다. `uncertain`은 구체적인 불확실 사유 문자열이 필요하며 평가에서 제외하고 제외 수를 보고합니다.
- `reviewed_video`는 작성자의 검토 절차 선언입니다. 프로그램이 검토자의 판단이나 실제 정답성을 인증하지 않습니다. 가능하면 AI 예측을 보지 않고 먼저 검토합니다.

보고서는 초기 세 자세의 confusion·클래스별 precision/recall/F1, 판정 보류를 누락에 포함한 recall과 전체 정답 비율, 출력한 구간만의 정확도와 coverage를 구분합니다. 서 있음·일반 앉음 등 범위 밖에 세 라벨을 출력한 비율도 별도 보고합니다. 0.8 신체 상태의 confusion은 최종 세 자세와 별도입니다. 참가자/세션/시점별 분리는 자료 준비 단계에서 수행하며 이 명령이 임의로 분할하지 않습니다.

검토 주석이 없거나 전부 불확실하면 `metrics=null`, `evaluation_status=not_evaluated_no_reviewed_labels`입니다. 세 자세 중 일부 정답만 있으면 `full_three_class_macro_f1`은 null이고, 관측된 클래스의 평균과 대상 목록을 따로 제공합니다. 합성 입력 결과는 합성 검사로 표시하며 실제 사람 성능으로 보고하지 않습니다.
