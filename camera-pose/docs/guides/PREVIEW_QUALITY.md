## 현재 기준과 사용법

상단 **화질** 선택은 작업실 전체 입력의 브라우저 표시를 바꾼다. 카메라를 연결하기 전에도 선택할 수 있다. 새 작업실 실행 시 기본은 고화질이며 설정을 파일에 저장하지 않는다.

| 모드 | 표시 영상 긴 변 제한 | 16:9 가로 입력의 최대 전달 크기 | JPEG 인코더 설정 |
|---|---|---|---|
| 고화질 · 기본 | 1920px | 1920×1080 · 1080p | 95 |
| 표준 | 1280px | 1280×720 · 720p | 85 |

표준은 이전의 크기/압축 설정이다. JPEG 설정은 화질 비율·정확도·비트레이트가 아니며, ‘원본 화질 85%/95%’로 해석하지 않는다. JPEG는 계속 손실 압축이다. 축소할 때는 OpenCV `INTER_AREA`를 사용한다.

실제 입력이 640×480이면 두 모드 모두 640×480을 전달하고 압축 설정만 다르다. 1920×1080 입력은 고화질에서 그대로, 표준에서 1280×720으로 전달한다. 3840×2160 입력도 고화질에서는 1920×1080으로 축소한다. 4:3/세로 영상은 비율을 유지해 긴 변으로 제한하므로 위의 1080p/720p 표기를 그대로 적용하지 않는다.

개별 영상 아래 **입력 W×H → 전달 W×H · JPEG Q**에서 실제 수신 크기와 브라우저가 받은 JPEG 크기를 확인한다. 캔버스의 화면 표시 크기는 브라우저 창·디스플레이 확대 배율에 따라 다시 달라지며 이 표기가 화면의 물리 픽셀 수를 의미하지 않는다.

## 변경한 처리 경로

- `preview_quality.encode_preview`는 수신 RGB에서 표시용 JPEG와 실제 크기 메타데이터를 만든다. 원본을 확대하거나 수정하지 않는다.
- `WebWorkspace`는 현재 프레임 RGB를 입력별 최신 프레임을 RAM에 보관한다. 화질을 바꿀 때 같은 프레임을 다시 인코딩해 일시정지 파일/정상 종료 후 마지막 화면도 전환한다. 표시 순번만 갱신하고 원본 프레임 번호·시각·관절·실루엣·판정 결과는 유지한다. 입력·추론 자체 오류로 표시를 없애면 해당 RGB 참조도 지운다. 표시 변환만 실패하면 같은 프레임 재시도를 위해 RGB와 관측 메타데이터를 유지한다. 입력을 삭제하면 이 캐시도 사라진다.
- 인증된 로컬 `POST /api/preview-quality`의 `quality=high|standard`로 전환한다. 각 입력의 표시 JPEG를 공통 잠금 밖에서 먼저 만든 뒤 설정을 적용하므로 인코딩 실패로 일부 입력만 바뀌지 않는다. 준비 중 전진한 입력은 최신 프레임의 새 화질 결과를 비동기로 반영하고 정지 입력은 같은 프레임을 즉시 전환한다. 새 입력에도 선택한 모드를 적용한다.
- 여러 화면 보기의 고화질 캔버스는 화면 크기×픽셀 밀도에 맞춰 긴 가로 크기 최대 1920px로 그린다. 표준은 최대 640px로 제한한다. 원본과 화면의 비율이 다르면 여백을 두며, 영상·관절·실루엣·침대 좌표를 같은 변환으로 표시한다. 화면 크기가 바뀌면 다시 그린다. 관절/침대 선의 두께도 화면 기준으로 유지한다.
- 침대 영역을 편집하며 화면을 고정한 동안은 해당 영상/실루엣을 유지한다. 화질 선택 후 편집을 마치면 새 표시 화질을 받는다.

## 유지한 범위와 한계

카메라 해상도/FPS를 강제 설정하지 않는다. 장치가 기본으로 제공하는 영상을 계속 사용하며, 원본 해상도보다 많은 세부 정보를 만들어내지 않는다. 카메라 초점·노출·휴대폰/가상 카메라 전송 압축 등의 문제를 표시 설정으로 해결한 것으로 취급하지 않는다.

AI에는 기존 수신 프레임을 계속 전달하고 모델 내부 전처리는 그대로다. 가중치·0.65 기준·보류 조건·기록 시각/형식·기록 검사와 외부 센서 독립성을 바꾸지 않는다. 표시용 JPEG/RGB 캐시와 설정은 측정 파일/CSV에 추가 저장하지 않는다. 고화질 화면이 모델의 자세 정확도를 높였다는 뜻이 아니다. 실루엣 표시용 PNG는 기존 최대 긴 변 640px를 유지한다.

고화질은 JPEG 크기·인코딩·전송·브라우저 디코딩 부담을 늘릴 수 있다. 복수 입력과 큰 화면에서는 표시 FPS/지연이 달라질 수 있으므로 속도가 필요하면 표준을 선택한다. 실제 PC/카메라의 화질·처리 속도 비교는 별도로 확인해야 한다. 여러 화면의 작은 타일이 항상 1080p로 렌더링되는 것은 아니다.

## 검사 범위

전체 **240개 개발 검사**를 통과했다. 4K 배열에서 1920×1080/1280×720 전달·JPEG 설정·색상 순서·원본 보존, 저해상도 비확대·4:3/세로 비율, 잘못된 선택과 인코딩 실패를 확인했다. 실제 생성 파일의 일시정지 프레임 재인코딩 시 추가 추론/프레임 진행이 없는지, 여러 입력 설정 적용·실패 시 일괄 보존·인증·측정 중 판정/기록 형식 유지·완료 기록 해시 보존·입력 오류 후 RGB 참조 해제를 검사했다.

Chromium에서 생성한 1920×1080 파일로 실제 JPEG 디코딩 크기와 해상도 표시, 일시정지의 같은 프레임/시각/판정 유지, 두 입력의 동시 전환, 픽셀 밀도 2의 고화질 격자와 표준 제한, 창 크기 변경·390/1440/2560px 배치와 JavaScript 오류 없음을 확인했다. 기존 실루엣/관절/침대 영역 표시·입력 전환·측정 기록 검사도 재확인했다. 실제 물리 카메라의 기본 해상도나 화질·지연·AI 성능을 측정한 검증과 구분한다.

현재 배포 wheel의 표시 인코더·웹 API·HTML이 소스와 같은 것도 확인했다. 시간축 기록 조회의 기존 브라우저 동작도 재확인했다.

## 미리보기 오류와 측정 분리 · 2026-10-28

미리보기 JPEG 변환 실패는 별도의 `preview_error`로 표시하고 입력·추론·진행 중인 기록을 종료하지 않습니다. 실패 프레임의 이전 영상/오버레이를 재사용하지 않으며 자세와 기록 상태는 계속 갱신합니다. 다음 프레임에서 자동 재시도하고 일시정지 파일은 화질 전환으로 같은 프레임을 재인코딩합니다. 실패 화면에서는 침대 영역 편집과 대상 이미지 선택을 막고 측정 종료/재생 조작은 유지합니다. 입력·추론·기록 자체 오류의 기존 종료 정책과 판정 기준은 유지합니다.


## 브라우저 미리보기 복구 보완 · 2026-10-29

손상된 JPEG의 브라우저 해독 실패를 표시 오류로 처리하고 상태 조회·측정 조작을 유지합니다. 해당 영상·오버레이를 숨긴 뒤 같은 순번도 1초 간격으로 다시 받아 정지 영상에서 복구합니다. 상태 응답보다 새롭거나 같은 순번의 영상 응답은 자체 해독 결과를 사용하여 이전 `preview_error`가 복구 영상을 지우지 않게 했습니다. 단일/격자 화면에 적용하며 실제 연결 실패 처리는 유지합니다.

재현 가능한 Chromium 검사는 `python tests/browser_preview_recovery.py`로 실행합니다(개발용 Playwright와 Chromium 필요). 생성 영상·SDK 대역을 사용하며 이미지 손상, 같은 프레임 재시도, 지연 상태 응답, 단일/격자 표시와 JavaScript 오류를 검사합니다. GitHub Actions의 Linux 작업에도 연결합니다. 자세 규칙·가중치·0.65 기준·기록 형식은 유지합니다.


## 다중 입력 미리보기 처리 분리 · 2026-10-29

입력별 독립 인코더와 최신 대기 프레임 한 장으로 JPEG 변환을 공통 잠금 밖에서 수행합니다. 느린 입력의 표시 대기가 다른 입력·상태 조회·조작·원본 기록을 막지 않으며, 같은 작업 묶음의 영상/관절/실루엣만 함께 공개합니다. 화질 전환도 잠금 밖에서 준비하고 세대·화질 버전·입력 유효성을 확인해 늦은 결과를 거부합니다. 측정 기록과 판정 기준은 유지합니다. 제어된 변환 지연과 브라우저 회귀 검사는 실제 장치 FPS/지연 향상 측정과 구분합니다. [처리 계약](../design/PREVIEW_CONCURRENCY.md).
