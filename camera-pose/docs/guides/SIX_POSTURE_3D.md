# 4단계 · 3D 관절과 침대 위치로 6개 자세 분류

2026-11-01 사용자 확인으로 클래스는 **바로 누움, 엎드림, 왼쪽 누움, 오른쪽 누움, 침대 위 앉음, 걸터앉음**입니다. 좌우는 대상자의 해부학적 좌우입니다. 침대 밖·서 있음·전환·관측 실패는 이 6개 중 하나로 강제하지 않고 별도의 판정 보류 사유로 표시합니다.

별도 사용자 요청으로 한쪽 관절만 있을 때의 모델 기반 3D 표시와 서 있음/누움 축 기준 등록도 추가했습니다. [현재 입력 전환·좌표축 계약](EXPERIMENTAL_3D_PREVIEW.md#단일-카메라-전환과-좌표축-기준--2026-11-01). 이 기준 자세는 학습용 정답이 아닙니다.

최신 보완은 [침대 수평 표시·가림/전환 예외 처리](PREVIEW_EXCEPTION_HANDLING.md)입니다. 한쪽 무릎 가림은 제한 후보로 처리하고 필요한 유지 시간은 화면에 표시합니다.

[정확도 개선 실험과 현재 입력 보완](ACCURACY_IMPROVEMENTS.md): 실제 영상 Full/Heavy 비교, 실패 시 방향 재시도, 카메라별 기하 충돌 보류를 추가했습니다.

## 실행

1. 기존 3D 공간 모니터에서 실시간 임시 3D를 켜고 DEMO는 끕니다.
2. 상단 **침대 등록 · 자세 보기**를 누릅니다.
3. 사람이 매트리스 모서리를 가리지 않는 상태에서 **침대 모서리 지정 · 현재 영상 고정**을 누릅니다. 각 영상에서 매트리스 윗면의 같은 실제 네 모서리를 같은 순서로 클릭합니다. 현재 방의 안내 순서는 머리쪽 벽측 → 머리쪽 통로측 → 발쪽 통로측 → 발쪽 벽측입니다. 영상에서 왼쪽/오른쪽을 그대로 대응시키면 안 됩니다. 난간의 높은 끝과 매트리스 윗면을 섞지 않습니다.
4. **침대 위치 등록**을 누릅니다. 모서리 대응/삼각측량/평면 검사가 실패하면 원인을 표시하며 저장하지 않습니다. 가려진 모서리는 추측하지 않습니다.
5. 양쪽에 동일한 한 사람이 보이면 실제 3D 관절로 후보를 계산합니다. 같은 후보가 충분한 근거에서는 0.6초 이상, 일부 가림에서는 1.2초 이상이며 최소 3프레임 유지되면 안정된 후보로 표시합니다. 관측이 사라지면 이전 자세를 계속 표시하지 않습니다.

임시 3D의 침대는 해당 카메라 A 상대 좌표에 직접 등록되며 Three.js에 반투명 면으로 표시합니다. 방 좌표가 검증됐다고 표시하지 않습니다. `preview-bed.json`은 후보 카메라 행렬 해시와 묶여 저장됩니다. 후보가 바뀌면 등록을 재사용하지 않습니다. 카메라 또는 침대가 실제로 이동하면 다시 등록해야 합니다. 물리 이동을 자동으로 인증하지는 못합니다.

검증된 `room_world` 복원 경로는 실측 치수로 지정한 기존 방 침대의 상단 평면을 사용합니다. 데모 침대를 실제 카메라 관절에 그대로 적용하지 않습니다. 현재 실제 장비에는 검증된 방 정렬이 없어 임시 경로를 사용합니다.

## 분류 근거와 보류

`bed_posture_3d.py`는 NumPy 기반의 초기 규칙이며 학습된 모델이 아닙니다. 어깨·골반의 3D 축, 몸통과 침대 법선의 각도, 골반의 침대 영역/높이, 무릎·발목 위치와 얼굴 방향을 사용합니다.

- 몸통과 침대가 대체로 평행할 때 누운 방향을 검사합니다. 어깨의 해부학적 좌우 및 몸통 축으로 앞쪽 법선을 구하며, 바로 누움/엎드림은 코 위치와도 방향이 일치해야 합니다. 측면은 어느 어깨가 침대 쪽인지로 구분합니다.
- 몸통이 침대에서 위로 향하고 허벅지가 수직으로 내려가지 않을 때 앉음 후보입니다. 골반이 침대 가장자리에 가깝고 발목이 침대 밖·평면 아래에 있을 때만 걸터앉음으로 분리합니다.
- 어깨/골반 누락, 몸통 근거와 관측 다리로 보완할 수 없는 무릎 부족, 경계의 발목 부족, 뒤틀린 축, 애매한 각도, 침대 밖, 얼굴 방향 충돌, 좌표계 불일치는 각각 보류합니다.

초기 몸통 각도 구간은 `upright_cos >= 0.65`(앉음), `abs(upright_cos) <= 0.4`(누움)입니다. 그 사이와 방향 코사인 0.65 미만의 애매한 누운 방향은 보류합니다. 거리 조건은 몸통 길이에 대한 비율로 계산합니다. 수치는 합성 사례의 초기 규칙이며 실제 정확도를 보장하는 기준이 아닙니다.

품질 점수는 필요한 관절들의 최소 관측 신뢰도이며 **자세 정답 확률이 아닙니다.** 모든 결과에 `accuracy_verified=false`, `eligible_for_recording=false`, `score_is_probability=false`를 유지합니다. 사람 미검출을 빈 침대/이탈 정답으로 처리하지 않습니다.

## 연결과 검증

별도 `posture_3d` API 필드에 `held/candidate/stable`, 한글/영문 클래스, 사유, 기하 특징, 품질 점수를 제공합니다. 매칭된 새 프레임마다 계산하며 HTTP 폴링 때 안정화 시간을 중복 누적하지 않습니다. 오래된 영상·연결 해제 때 출력 라벨을 비웁니다. 침대 등록은 기존 토큰 검사를 사용하는 `POST /api/room/preview-bed`로 처리합니다.

기존 MediaPipe, CLIP, 기존 자세 판정과 녹화 경로는 유지합니다. 새 분류는 기존 예측이나 실제 정답을 덮어쓰지 않습니다. 이번 단계는 ToF 동기 저장·자동 정답 라벨 생성·CNN/LightGBM/Random Forest/XGBoost 학습을 수행하지 않습니다.

새 합성 검사 7개(6개 클래스/해부학적 좌우, 누락, 침대 밖·불일치·저신뢰, 좌표 변환, 시간 안정화·결측 복구, 잘못된 침대, 두 영상 모서리 삼각측량)와 관련 기존 검사 31개를 통과했습니다. TypeScript/Vite 빌드와 실제 GPU 두 카메라의 새 API/미등록 보류/잘못된 침대 입력 거부, 브라우저 표시를 확인했습니다. **현재 실제 침대 등록 및 실제 사람의 6자세 정답 대조는 미수행**이며 정확도·혼동행렬·확률 보정은 아직 보고할 수 없습니다.
