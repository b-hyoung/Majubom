# 실제 입력을 사용하는 임시 3D 표시

후속 사용자 요청으로 [실험적 6자세 분류](SIX_POSTURE_3D.md)를 별도 연결했습니다. 침대를 같은 임시 좌표에 등록한 경우만 후보를 계산하며 학습/ToF 정답 저장 차단은 유지합니다.

2026-11-01 사용자가 추가 수동 보정 촬영을 중단하고 현재 입력으로 우선 표시하도록 요청했습니다.

모니터 상단 **실시간 임시 3D · 정확도 미검증**을 켭니다. DEMO는 꺼 둡니다. 서버에 로컬 `guided-calibration-candidate-20.json` 후보가 있어야 합니다. 이번 실행에서는 요청에 따라 켜 두었습니다. 일반 서버 시작 시 자동으로 켜지지는 않습니다.

두 실제 카메라의 동기화된 MediaPipe COCO17 관절이 충분하면 저장된 후보의 K/왜곡/R/t로 삼각측량합니다. 한쪽만 관측되거나 삼각측량 관절이 부족하면, 같은 대상의 실제 SDK world 관절과 2D 관측을 solvePnP로 등록한 단일 카메라 추정 3D를 표시합니다. 모델 3D가 없을 때 임의의 깊이/신체를 생성하지 않습니다. 결과는 `experimental_preview.skeleton`에만 반환하며 기존 `skeleton`, 검증된 `calibration`, CLIP/자세 판정 및 기록 경로와 별개입니다. 실제 사람 입력이 없으면 데모나 결측 관절을 생성하지 않습니다.

침대 등록 전에는 카메라 A 기준으로 축을 Three.js 방향에 맞춰 표시합니다. 침대 등록 후 기본 표시는 [침대 수평 기준](PREVIEW_EXCEPTION_HANDLING.md)으로 전체를 함께 회전·이동합니다. `coordinateSystem=camera_a_preview`, `unit=unverified_candidate_units`, `accuracy_verified=false`, `eligible_for_recording=false`입니다. 실제 방/침대 정렬과 거리·신체 크기가 검증된 것은 아닙니다. 실제 방 정렬은 표시하지 않으며, 등록한 임시 침대와 카메라·격자·관절을 표시합니다. 초기에 관절이 5개 이상 관측되면 시점을 맞추고, 표시는 적응형 60~160ms 평활화와 입력 전환 완충을 사용합니다.

삼각측량은 양쪽 추론 성공/단일 대상 출력, 실시간 카메라, 해상도 일치, 기존 시간 차이 조건을 유지합니다. 단일 카메라는 한쪽의 새 프레임만으로 동작하며 다른 카메라의 연결/동기화 쌍을 기다리지 않습니다. 최대 300ms 또는 설정 만료 시간 중 짧은 값을 넘긴 관측은 표시하지 않습니다. 2도 미만 시차, 카메라 뒤쪽, 비정상 거리, 재투영 오차 20px 초과인 관절은 제외합니다. **20px는 임시 표시를 위한 완화된 조건이며 검증된 복원의 품질 기준이 아닙니다.** 단일 대상 GPU 모드는 주변의 다른 사람을 모두 검출하지 못하므로 양쪽에 동일인 한 명만 있도록 해야 합니다. 끊김/미검출/불량 대응은 표시를 비우며 측정 데이터로 내보내지 않습니다.

`POST /api/room/experimental-preview` 본문 `{ "enabled": true }`로 켜고 false로 끕니다. 기존 로컬 토큰/출처 검사를 사용합니다. 후보의 구조/유한 행렬/회전/카메라 간격만 검사하며 `calibration.install`을 호출하거나 `calibration.json`에 쓰지 않습니다. 연결 순서가 바뀌면 다시 켜야 합니다.

검증: 합성 기하/결측/큰 재투영 오차/잘못된 후보/독립 상태/오래된 영상/연결 끊김/명시적 활성화의 새 검사 4개, 기존 room monitor 9개 및 자동 보정 11개 통과. TypeScript/Vite 빌드 통과. 실제 RTX 5070 GPU 두 카메라의 새 프레임에서 실시간 임시 삼각측량과 5~12개 유효 관절을 확인했고 대시보드에서 LIVE/임시 표시·DEMO 꺼짐·WebGL 렌더링 약 164FPS를 확인했습니다. 실제 3D 좌표의 정확도와 자세별 추적 안정성은 미검증입니다.

## 단일 카메라 전환과 좌표축 기준 · 2026-11-01

삼각측량은 몸통 관측이 있고 유효 관절 8개 이상이며 다리 관측을 가중한 점수가 가장 좋은 단일 카메라 결과의 90% 이상일 때 우선합니다. 그렇지 않으면 단일 카메라 결과 중 유효 관절이 많은 쪽을 사용합니다. 서로 다른 근거의 관절을 임의로 혼합하지 않습니다. 현재 방식에도 관절 8개 이상이 남아 있으면 600ms 동안 전환 후보를 확인하면서 **현재 방식의 새 관측**을 표시합니다. 현재 방식이 불가능해지면 즉시 전환합니다. 이전 좌표를 유지하는 방식으로 누락을 숨기지 않습니다.

단일 카메라는 실제 SDK의 `monocular_estimate_meters_hip_origin` 의미와 COCO 매핑이 확인된 3D 몸 형태를 사용합니다. 어깨/골반 및 최소 6개 2D 관절이 있어야 합니다. SQPnP+LM으로 현재 카메라의 K/왜곡에 등록하고, 양의 깊이 및 재투영 중앙값 15px/p90 35px 조건을 검사합니다. 실제 관측이 없는 관절은 복구하지 않습니다. `source=single_camera_mediapipe_pnp`, `source_camera=A/B`, `depth_is_model_estimate=true`로 표시하고 주황색을 사용합니다. 삼각측량은 녹색입니다. PnP 깊이는 학습 모델의 신체 크기에 의존하는 추정값이며 검증된 거리 측정이 아닙니다.

사용자가 나중에 서 있다고 알리거나 버튼을 누르면 `POST /api/room/preview-axis`의 `{reference:"standing"}`으로 위쪽 축을 등록합니다. **미리 실행하지 않습니다.** 최근 1.5초의 몸통 관절에서 5개 이상/0.3초 이상 안정된 방향을 요구합니다. 이후 침대 길이 방향으로 누운 상태에서 `{reference:"lying"}`을 보내면 길이 축을 맞춥니다. 어깨→골반 방향을 사용하며 앞서 등록한 위쪽 축에 충분히 수평이어야 합니다. `{reference:"reset"}`으로 초기화합니다.

공통 회전은 스켈레톤·카메라·침대에 동일하게 적용하고 좌표계를 `camera_a_preview_aligned`로 표시합니다. 실제 분류는 공통 회전 전 같은 기준의 관절·침대를 사용하므로 표시 정렬 때문에 판정 기하가 달라지지 않습니다. 기준은 카메라 후보 행렬 해시와 묶어 저장하고 같은 후보일 때 복원합니다. 실제 카메라/침대가 움직였으면 재등록합니다. 이 동작은 녹화, 자세 분류기 학습, 카메라 재보정이 아니며 `used_for_training=false`입니다. 축 방향 정렬은 개별 관절 비틀림/보정 오차/신체 크기/실제 거리 정확도를 보장하지 않습니다.

관련 검사 44개와 빌드 통과. 실제 GPU 입력에서 삼각측량 12개 및 단일 B 14개 전환, A 입력 종료 중 B만으로 14~15개 관절 표시, A 재연결 복구를 확인했습니다. 실제 사용자의 서 있음/누움 축 기준 등록은 요청 대기 상태이며 실행하지 않았습니다.

## 표시 떨림 억제
표시 평활화는 35ms에서 적응형 60~160ms로 변경했습니다. 작은 흔들림은 몸통 길이의 1.2% deadband로 억제하고 실제 이동은 빠르게 추종합니다. 입력 방식 전환 후 500ms 동안 300ms 시간 상수로 완만하게 연결합니다. 몸통 길이의 65%를 넘는 점프는 다음 새 프레임에서 인접 위치가 반복되는지 확인하며, 반복 실패시 이전 위치 표시는 최대 250ms까지만 허용합니다. 결측 관절은 표시에서 즉시 제외합니다. 원본 관절/분류 입력은 수정하지 않습니다. 6개 합성 표시 검사와 빌드를 통과했지만 실제 좌표 정확도 개선이나 실제 떨림 감소율을 의미하지 않습니다.
