## 사용법

입력 추가 → 이름으로 카메라 선택 → 입력 해상도 요청/FPS 요청 → 연결. 기본 선택은 장치 기본값이며 OpenCV 속성을 변경하지 않는다. 해상도와 FPS는 각각 독립 선택할 수 있다. 해상도 선택지는 640×480·1280×720·1920×1080, FPS는 15·30·60이다. 장치 지원 모드 목록을 탐색한 결과가 아니라 요청 후보이다. 4K·사용자 지정 모드는 이번 범위에 포함하지 않는다.

입력별로 설정하며 다른 카메라에는 영향을 주지 않는다. 연결 중 설정을 바꾸지 않으며 입력을 제거한 뒤 새 설정으로 연결한다. 새 연결은 새 스트림·침대 영역·대상 지정이 필요하다. 저장 영상은 기존 원본 크기와 PTS 경로를 사용한다.

## 요청·관측의 구분

- `CameraSource`는 연결 후 선택된 width→height→FPS를 OpenCV에 요청한다. `.set()`의 False/예외는 미지원으로 기록하고 수신을 시도한다. True도 실제 지원·적용을 보장하지 않는다.
- `source_profile.requested_capture`는 요청값, `capture_set_results`는 속성 설정 반환값, `driver_reported_resolution`과 `driver_reported_fps`는 장치 보고값이다. 보고 불가·0·비유한 값은 null이다. 장치 보고 FPS는 노출 수를 실측한 값이 아니다.
- 화면의 실제 수신 해상도는 디코딩된 RGB 배열에서 얻는다. 기존 manifest geometry가 측정의 실제 크기를 남긴다. 입력 크기가 실행 중 바뀌면 기존 오류 정책대로 재연결과 영역 재지정이 필요하다.
- 최근 처리 FPS는 엔진이 최근 완료한 최대 30개 프레임의 완료 간격으로 계산한다. 2개 미만이면 미표시하며 입력 읽기·추론·판정·기록과 프레임 사이 작업의 영향을 받는다. 카메라 노출 FPS·브라우저 표시 FPS·종단 지연을 의미하지 않는다. 파일 재생 조작과 자동 측정 재생에서 표본을 초기화한다. 이 값은 화면 진단용이며 기록 행에는 추가하지 않는다.

브라우저의 고화질/표준 선택은 별도의 표시 설정이다. 카메라 입력 요청은 AI에 전달되는 수신 RGB에 영향을 줄 수 있으므로 해상도/FPS 변경의 속도·정확도 효과는 직접 검증해야 한다. 모델 내부 전처리와 기존 가중치·판정 기준은 유지한다.

## 검증 범위

카메라 대역으로 기본값의 속성 미변경, 잘못된 요청 거부, 미지원 반환/예외, 장치 보고와 실제 배열 크기의 불일치, RGB 변환·해제, API 설정·처리율·기록 재검사를 확인한다. 생성 파일과 대역 SDK는 실제 카메라 지원·처리 속도·자세 정확도를 증명하지 않는다. 브라우저에서 이름 선택·요청 전달·정보 구분과 390/1440/2560px 배치를 검사한다. 실제 Windows 카메라/휴대폰별 적용값과 지연 확인은 후속이다.
