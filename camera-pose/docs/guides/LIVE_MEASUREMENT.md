## 설치와 실행

Windows에서 Python 3.12를 권장합니다. 패키지 최소 요구는 3.11이며 모든 Python 버전·장치 조합의 동작을 검증한 것은 아닙니다. 프로젝트 폴더에서 실행합니다.

```powershell
# 처음 설치할 때
py -3.12 -m venv .venv
& .\.venv\Scripts\python.exe -m pip install -e ".[live]"

# 작업실 실행
& .\.venv\Scripts\python.exe -m bed_pose live
```

MediaPipe 모델 파일 `checkpoints/pose_landmarker_full.task`가 없으면 입력 추가 창에서 `.task` 파일을 선택합니다. SDK와 모델 자산은 별개입니다. [어댑터·모델 안내](../development/MEDIAPIPE_ADAPTER.md)를 확인하세요.

**모델 변경**으로 선택한 관절 추정 모델은 사용자 설정 폴더에 복사되어 다음 작업실 실행에도 유지됩니다. 이후 입력부터 선택된 모델을 사용하며 이미 연결된 입력은 기존 모델을 유지합니다. 저장된 모델을 찾을 수 없거나 내용이 바뀌면 다시 선택해야 합니다. 저장된 선택이 있으면 실행 명령의 `--model`보다 우선하며, `--model`은 저장된 선택이 없을 때 초기 모델을 지정합니다. 모델 파일은 사용자 홈의 `.config/bed-pose/pose-model/`에 보관됩니다.

실행 후 열린 브라우저와 Python 터미널을 유지합니다. 업데이트할 때는 작업실 종료 → GitHub Desktop Pull → 재실행 순서입니다.

작업실 오른쪽의 **추론 실행 장치**에서 선택한 입력의 MediaPipe와 CLIP 실행 장치를 각각 확인할 수 있습니다. CLIP의 **대기**는 모델은 준비됐지만 해당 프레임에서 추론하지 않은 상태입니다. 입력이 중단되면 장치 대신 중단 상태를 표시합니다.

### Windows MediaPipe GPU 실험 모드

Windows의 공식 MediaPipe Python GPU delegate는 지원되지 않아, 선택적으로 로컬 Chrome/Edge와 WebGL GPU 추론 프로세스를 사용합니다. Node.js 18 이상과 Chrome 또는 Edge, 위 Python 작업실 환경 및 로컬 모델이 필요합니다. 저장소 폴더에서 실행합니다.

```powershell
npm.cmd ci --prefix tools/gpu-preview
& .\.venv\Scripts\python.exe -m bed_pose live --pose-device browser_gpu --model .\pose_landmarker_full.task
```

모델 경로는 실제 보유한 파일에 맞게 바꿉니다. 기존과 같이 작업실 화면에서 카메라를 추가합니다. 이 옵션은 명시적 GPU 요청이며 GPU 렌더러를 확인하지 못하면 오류로 종료하고 CPU로 자동 전환하지 않습니다. 고성능 GPU 선택은 요청하지만 실제 선택된 장치는 작업실의 처리 정보 또는 측정 기록의 `adapter_profile.gpu_renderer`에서 확인합니다. 기본 옵션 `cpu`는 기존 동작입니다. 브라우저 추론 프로세스와 프레임 전달은 이 컴퓨터 내부에서만 실행됩니다.

GPU 실험 모드에서는 실루엣 마스크 옵션을 지원하지 않으며 함께 선택하면 오류로 거부합니다. Web SDK는 이 경로에서 landmark `presence` 값을 제공하지 않아 기록에는 `null`로 남습니다. FPS·정확도·다중 카메라 성능과 CPU 결과의 차이는 아직 실험이 필요합니다. 소스 저장소의 `tools/gpu-preview` 폴더가 필요하며 독립 wheel만으로는 실행할 수 없습니다. 별도 [GPU 검증 화면](../../tools/gpu-preview/README.md)도 사용할 수 있습니다.

## 화면에서 다중 카메라 사용 · 2026-10-31

**카메라 수에 따라 실행 명령을 바꿀 필요가 없습니다.** 기존 `python -m bed_pose live`로 작업실을 열고 화면에서 연결합니다.

1. 상단 **다중 카메라** → **카메라 추가**를 누릅니다. 왼쪽의 **카메라 추가**에서도 시작할 수 있습니다.
2. 이름으로 장치를 선택합니다. **연결 후 다음 카메라 추가**를 누르면 입력 창을 유지하고 다음 장치를 연결합니다. 사용 중인 장치는 선택할 수 없으며 다른 입력은 유지합니다.
3. 마지막 장치는 **카메라 연결**로 마칩니다. 여러 화면이 함께 나타납니다. 화면을 누르면 해당 입력의 개별 설정으로 이동하고 **연결 화면 모두 보기**로 돌아옵니다.
4. 같은 사람의 통합 자세를 측정하려면 **두 카메라 통합 판정 설정**에서 두 입력을 선택하고, 각 카메라의 침대 영역을 지정·확인하고 시각 차이를 설정한 뒤 그룹 측정을 시작합니다. 침대가 비어 있어도 시작할 수 있습니다. 카메라 추가/모드 선택만으로 통합 측정을 시작하지 않습니다.

다중 카메라 모드는 연결·보기·통합 설정을 쉽게 찾게 하는 UI입니다. 개별 입력 보기로 전환해도 연결이나 진행 중 측정을 자동 종료하지 않습니다. 3대 이상도 동시에 표시할 수 있지만 현재 통합 판정은 선택한 2대 기준입니다. 각 화면에 침대 안 사람이 한 명씩 관측될 때 CLIP 통합을 시도하며, 자동 대응은 동일인 인증이 아닙니다. 시간·입력 품질 조건도 적용합니다. 실제 장치의 동시 연결·대역폭·지연은 환경별 검증이 필요합니다.

`--clip-batch-size 2`는 선택적인 **추론 묶음 최적화**이며, 두 카메라를 연결하기 위한 필수 옵션이 아닙니다. 기본 실행에서도 여러 카메라 연결과 기존 통합 판정을 사용할 수 있습니다. FP16·묶음 최적화 설정은 아래 별도 항목을 참조하세요.

## CLIP 이미지 자세 분석 준비

기존 MediaPipe는 관절·실루엣, CLIP은 사람 RGB의 신체 상태/누운 방향을 예측합니다. 아래 명령 블록은 프로젝트 폴더의 PowerShell에서 실행합니다. GPU는 필수가 아니며 기본은 실행 가능한 장치를 자동 선택합니다.

```powershell
& .\.venv\Scripts\python.exe -m pip install -e ".[live,clip]"
& .\.venv\Scripts\python.exe -m bed_pose clip-setup
& .\.venv\Scripts\python.exe -m bed_pose live
```

- `clip-setup`은 인터넷으로 `openai/clip-vit-base-patch16`의 약 600MB PyTorch 가중치와 토크나이저/구성을 `checkpoints/clip-vit-base-patch16`에 준비합니다. 요청 revision을 고정 commit으로 해석하고 각 파일 SHA-256을 저장합니다. 준비 중 실패하면 미완성 폴더를 정리하고 기존 모델 폴더는 덮어쓰지 않습니다. 새 모델 준비 후 작업실을 재실행하세요.
- 인터넷 연결이 제한됐고 HF 형식의 원본 파일 폴더를 이미 가지고 있다면 `python -m bed_pose clip-setup --source "D:\models\clip-vit-base-patch16" --output checkpoints/clip-vit-base-patch16`으로 반입할 수 있습니다. 로컬 반입은 공식 revision을 확인했다고 표시하지 않습니다. `--source`는 CLIP 가중치/구성 폴더이며 마네킹 사진 폴더가 아닙니다.
- **입력 추가 → CLIP 이미지 자세 분석**을 선택하고 카메라/영상을 엽니다. 준비됐으면 기본 체크, 준비되지 않으면 비활성 및 준비 명령을 표시합니다. 체크를 끄면 기존 관절 기반 0.7입니다. `.task` 모델 변경 버튼은 MediaPipe용이며 CLIP 폴더를 선택하는 버튼이 아닙니다.
- CLIP은 입력 연결 중 해당 작업 스레드에서 로딩합니다. 누락·손상·라이브러리 오류는 입력 오류로 표시하고 모의 결과로 대체하지 않습니다. 일반 분석 중에는 모델을 다운로드하지 않으며 이미지를 외부 추론 API에 보내지 않습니다.
- **CLIP 이미지 판단 근거**를 펼치면 상태·방향의 상대점수와 실제 224×224 입력을 봅니다. 세로/가로 비율은 유지하고 여백을 넣습니다. 관절 crop에서 이미 잘린 팔다리는 복원하지 않습니다. 이 미리보기는 일시 표시이며 측정 파일에 이미지 자체를 저장하지 않습니다.
- 누움/방향은 침대 영역 없이 예측합니다. 앉음만 확인됐을 때는 ‘앉음’을 표시하고, 침대 가장자리 관계까지 있을 때 걸터앉음을 예측합니다. 서 있음·기타·엎드림을 초기 세 자세에 강제 배정하지 않습니다. 사람 후보가 없으면 CLIP도 호출하지 않습니다.
- 상태·방향 각각 상대점수 0.5 이상은 **미검증 초기값**입니다. 필요하면 `live --clip-state-min 0.5 --clip-direction-min 0.5`로 지정합니다. 기존 관절 점수 0.65를 재사용하지 않으며 상대점수는 정답 확률이 아닙니다. 가까운 2위 점수 때문에 추가로 보류하지 않고 동점은 보류합니다.
- 다른 모델 폴더는 `live --clip-model "D:\models\prepared-clip"`, CUDA 사용 가능 환경은 `live --clip-device cuda`로 명시합니다. CUDA 실패 시 CPU로 조용히 전환하지 않습니다. 여러 입력은 각각 모델을 유지하므로 실제 메모리·처리 지연을 확인해야 합니다.

**검증 한계:** 개발 환경의 사전학습 모델 다운로드는 프록시 403으로 차단됐습니다. 작은 무작위 CLIP 모델로 실제 로딩/추론 API를 검사하고 대역으로 UI·기록을 검사했습니다. 사전학습 가중치의 마네킹/실제 사람 자세 정확도·카메라 FPS·자유 시점 성능은 미검증입니다. [상세 정책과 기록](../design/AUTOMATIC_POSTURE.md).

## 카메라로 측정

1. **입력 추가 → 카메라**에서 장치 이름을 선택합니다. 휴대폰은 PC에서 웹캠으로 인식되어야 합니다.
2. 필요하면 해상도/FPS를 요청합니다. 기본은 장치 기본값입니다. 요청값과 실제 프레임 크기는 다를 수 있습니다. [입력 설정](CAMERA_CAPTURE.md).
3. 침대 관계도 확인하려면 **침대 영역 지정**을 누르고 침대 모서리 네 곳을 둘레 순서대로 클릭합니다. 점 위치 수정·영역 지우기·Esc 취소를 지원합니다. [영역 계약](BED_REGION.md).
4. 기본 분리 모드에서는 영역 없이도 **측정 시작 → 측정 종료**로 신체 형태를 기록할 수 있습니다. 종료 전에 기록 완료 상태를 확인합니다.

CLIP 이미지 자세 분석을 사용하는 새 입력은 걸터앉음 판정에 골반·양쪽 무릎과 발목의 침대 경계 관계를 함께 사용합니다. 침대의 실제 모서리를 지정하고 골반·양쪽 무릎과 발목이 화면 안에 보이게 하세요. 발목 근거를 사용하면 **침대 관계**에 `골반·무릎·발목 근거`가 표시됩니다. 발목이 가려져도 기존 무릎 근거는 사용할 수 있습니다. 영상상 겹침을 이용하는 미검증 실험 규칙이므로 실제 자세를 확인하고, 가림이나 다른 촬영 각도에서의 오류를 따로 검증해야 합니다.

연결 중 해상도 변경은 지원하지 않습니다. 입력을 제거한 뒤 재연결하고 영역/대상을 다시 지정하세요. 같은 크기로 카메라가 움직인 경우 자동으로 감지하지 못하므로 세션 중 고정합니다.

### 라즈베리파이 USB 카메라

이 PC와 Pi가 같은 네트워크에 있고 Pi 카메라 서비스가 실행 중이면, 카메라 목록에서 **라즈베리파이 · USB 카메라**를 선택합니다. Pi에서 640×480, 15 FPS로 전송하며 Windows의 일반 웹캠 목록에 별도로 등록되는 방식은 아닙니다. 작업실의 기존 MediaPipe·CLIP 설정과 기록을 사용할 수 있습니다. 노트북에 도착한 시각을 사용하므로 실제 카메라 노출 시각이나 네트워크 지연은 확인할 수 없습니다.

Pi에서는 사용자 서비스 `bed-pose-camera.service`가 `tools/pi_camera_stream.py`를 실행합니다. 설치된 파일은 `~/.local/share/bed-pose-camera/stream.py`, 비밀 토큰은 같은 폴더의 `token`입니다. PC의 연결 설정은 사용자 홈의 `.config/bed-pose/pi-camera-url.txt`에 있으며 토큰을 포함하므로 공유하거나 기록에 넣지 않습니다. 영상은 토큰으로 접근을 제한하지만 HTTP 전송 자체는 암호화되지 않으므로 신뢰할 수 있는 네트워크에서만 사용합니다.

Pi에서 상태를 확인하거나 다시 시작할 때는 `systemctl --user status bed-pose-camera.service` 또는 `systemctl --user restart bed-pose-camera.service`를 사용합니다. 현재 Pi 사용자의 linger와 서비스 자동 시작을 켰으나 실제 재부팅 후 자동 시작은 아직 확인하지 않았습니다. Pi 주소가 바뀌면 PC의 연결 설정 주소도 바꿔야 합니다.

## 촬영해 둔 영상 분석

입력 추가 → 영상 파일 → 원본 선택. 첫 프레임에서 일시정지하므로 필요 시 침대 영역을 지정한 뒤 측정을 시작합니다. 기본 분리 모드는 영역 없이도 기록합니다. 처리 가능한 속도로 순차 분석하며 원본 재생 FPS를 보장하지 않습니다. 파일 재생/일시정지는 분석 진행에도 영향을 줍니다. 끝에 도달하면 정상 종료하고, 디코딩 오류는 실패로 구분합니다. 처음부터 다시 분석하려면 새 입력으로 엽니다.

원본 PTS·time base·원본 프레임 번호·픽셀 해시를 남깁니다. 수신 경과 시각과 원본 동작 시각을 혼동하지 마세요. PTS 누락/역행·SDK ms 시각 중복은 임의 보정하지 않습니다.

## 단독 사용의 입력 품질과 오류 표시

실루엣은 기본으로 계산하지 않습니다. 필요한 입력만 추가 창에서 **실루엣 진단 사용**을 선택하세요. 연결 후의 실루엣 표시 체크는 화면 표시만 바꾸며, 분석 설정을 변경하려면 입력을 다시 연결합니다.

CLIP 입력 부족은 어깨/골반/하체 관측 부족을 표시합니다. 입력 검사는 전신 정확도의 인증이 아니며 부분 가림에서 보류될 수 있습니다. **이미지 분석 오류**는 불확실한 자세와 달리 모델 실행 실패입니다. 관절 분석과 기록은 계속되며 오류 코드/예외 종류를 남깁니다. 기록의 processing_status/ok는 관절 처리 상태이므로 CLIP 성공률로 해석하지 마세요.

대상 지정 후 느린 처리로 관측 간격이 벌어져도, 측정된 직전 처리 시간과 공간 대응 조건을 충족하면 잠정 추적을 유지합니다. 화면의 **처리 지연** 표시는 동일인 검증이나 실시간 성능 보장이 아닙니다. 사람 소실·후보 혼동·입력 공백은 여전히 재지정이 필요합니다. 파일 입력은 영상 PTS 기준을 유지합니다.


## 처리 속도 확인과 실행 장치

기본 실행은 준비된 CLIP에 대해 CUDA → MPS → CPU 순서로 사용 가능한 장치를 선택합니다. Windows에서는 CUDA 또는 CPU, 지원되는 Mac에서는 MPS 또는 CPU를 사용합니다. MediaPipe는 기본 CPU이며 Windows에서 위 GPU 실험 모드를 별도로 선택할 수 있습니다. NVIDIA GPU가 있어도 CPU 전용 PyTorch 설치에서는 CLIP이 CPU로 동작합니다. GPU 로딩 실패를 성공이나 CPU 전환으로 숨기지 않습니다.

CPU CLIP의 PyTorch 연산 스레드는 최초 로딩 때 기본 최대 4개(기존 설정·논리 CPU 수가 더 작으면 그 수)로 제한합니다. 여러 입력·MediaPipe·미리보기와의 CPU 경쟁을 줄이기 위한 초기 설정이며, 모든 PC에서 가장 빠른 값은 아닙니다. 프로세스 공통 설정이므로 변경 후 작업실을 다시 실행합니다.

```powershell
# CPU로 고정하고 2개 연산 스레드로 비교할 때
$env:BEDPOSE_CLIP_CPU_THREADS = "2"
& .\.venv\Scripts\python.exe -m bed_pose live --clip-device cpu
# 기본 자동 설정으로 되돌릴 때
Remove-Item Env:BEDPOSE_CLIP_CPU_THREADS -ErrorAction SilentlyContinue
& .\.venv\Scripts\python.exe -m bed_pose live
```

AI 자세 판정 카드의 `최근 처리`에서 읽기·관절·이미지·전체 시간을 ms로 확인합니다. FPS는 최근 처리율, 시간은 마지막 처리 프레임 기준이며 카메라 노출 FPS·브라우저 표시 FPS와 다릅니다. 이미지 시간에는 입력 품질 검사와 표시용 입력 이미지 준비도 포함됩니다. 전체 시간은 읽기부터 기록/진단까지이며 별도 브라우저 인코딩·전송 시간은 제외합니다. 측정 메타데이터의 `image_runtime`은 실제 CLIP 장치·스레드 설정을 보존합니다.

이번 최적화는 프레임 생략, 이전 자세 재사용, 입력 해상도 축소, 모델·점수 기준 변경을 하지 않습니다. 실제 장비의 처리율 개선과 CUDA/CPU 결과의 수치 차이는 별도 확인해야 합니다.

## 최신 카메라 영상과 분석 프레임

카메라의 개별 화면은 기본 `관절·침대 영역 확인`입니다. 분석 프레임에 해당 관절과 지정된 침대 영역을 함께 표시합니다. 영상 위의 `최신 영상 · 침대 영역` 버튼으로 수신 영상을 볼 수 있습니다. 자세 카드의 결과는 마지막 분석 프레임 기준이고, 최신 영상에는 과거 관절을 겹치지 않습니다. `관절·침대 영역 확인` 버튼을 누르면 관절·실루엣과 해당 분석 영상을 함께 확인합니다. 침대 영역 지정 시 자동으로 분석 프레임을 사용합니다. 여러 화면 격자와 저장 영상은 분석 프레임 표시입니다.

분석이 느려도 수신 대기열을 늘리지 않고 최신 프레임으로 진행합니다. 중간 프레임은 분석하지 않으며 이 수를 기록합니다. 빠른 자세 전환이 누락될 수 있으므로 전체 프레임 검증이 필요하면 저장 영상을 순차 분석합니다. 최신 보기의 부드러움은 자세 분석 FPS 상승과 구분합니다. CLIP 근거 창이 닫혀 있으면 입력 확인 PNG 생성을 중단합니다.

지정된 침대 영역은 최신 수신 영상에도 계속 표시합니다. 수신 영상의 원본 크기로 좌표를 변환하고 여백을 반영합니다. 입력 전환·영역 해제·영상 크기 불일치·표시 중단에서는 이전 영역을 겹치지 않습니다. 스켈레톤과 실루엣은 해당 분석 프레임에서만 표시합니다.

화면을 보지 않는 동안 최신 영상용 추가 JPEG 인코딩은 마지막 요청으로부터 약 1초 후 중단됩니다. 최신 영상 모드로 돌아오면 새 프레임부터 재개합니다. 카메라 수신·자세 분석·기록은 계속됩니다. 설정 변경과 오류는 캐시 때문에 숨겨지지 않도록 다시 반영합니다.

## 두 카메라 통합 자세

두 입력에서 침대 영역을 각각 지정하고 확인한 뒤 허용 수신 시각 차이를 입력해 그룹 측정을 시작합니다. 사람이 없어도 기록이 시작됩니다. CLIP을 사용하는 경우 측정 중 양쪽 화면에 침대 안 사람 한 명씩 관측되면 자동으로 영상 점수를 결합합니다. 이 대응은 동일인 인증이 아닙니다. 침대 밖에 사람이 함께 검출되어도 침대 영역 안의 대상 한 명을 우선 사용합니다. 침대 영역 안에 여러 명이 검출되거나 골반·영역 관계가 불명확하면 통합하지 않습니다. 개별 카메라 결과 아래의 `두 카메라 통합 자세`에서 결과를 확인하고, 기여 시점과 통합 점수 등은 `자세 판단 상세 보기`를 펼쳐 확인합니다. 한 시점만 사용하면 그렇게 표시하고, 시간/대상 대응 실패 시 보류합니다. 종료 후 그룹의 posture_predictions.jsonl에 정책과 근거가 남습니다. 한 명씩이라는 조건도 두 화면이 같은 사람임을 보장하지 않습니다. 기준 미달 등으로 확정하지 못했더라도 유효한 현재 영상 점수에서 유일한 지원 자세가 가장 높으면 실시간 화면에 해당 자세 이름을 표시하고 기준 미달을 안내합니다. 앉은 형태는 침대 가장자리 확인이 필요합니다. 후보는 확정 판정이나 저장 기록을 바꾸지 않으며 시간·대상 게이트 실패, 동점, 서 있음·엎드림 등 범위 밖 또는 근거 부재에는 임의로 세 자세를 표시하지 않습니다.

통합 로직은 운영체제나 GPU 종류에 종속되지 않습니다. 현재 실행 환경에서 지원되는 카메라/모델 제공자를 사용하며 macOS 실기기 실행은 별도 검증이 필요합니다. 이 기능이 특정 GPU를 필수로 요구하지는 않습니다.

실행기는 `USB2.0 PC CAMERA`를 이름으로 찾아 OpenCV가 제공한 백엔드 포함 번호로
연결하고, Pi 입력을 함께 연 뒤 기존 측정 작업실을 띄웁니다. 이름이 없거나 중복되면
중단하므로 내장 카메라로 자동 대체하지 않습니다. Pi 목록의 이름은 제조사를
추정하지 않는 `라즈베리파이 · USB 카메라`입니다. 이 설치의 Pi 장치는 C920입니다.
MediaPipe는 CPU, CLIP은 기존 자동 장치 선택을 사용합니다.

새 설치의 기본 기록 폴더는 `recordings/mac-pi-20261107`입니다. 이전 설치의
침대 모서리·보정 파일을 복사하지 않고 3D 미리보기는 꺼서 시작합니다.
각 영상의 새 침대 영역을 지정한 뒤 사용하며, 3D는 새 설치의 보정과 확인이 필요합니다.
사용자가 말한 약 2.1m 높이는 추정 설치 정보이며 보정된 카메라 좌표로 입력하지 않습니다.
자동 보정·측정·영상 저장·ToF 학습을 실행기가 자동 시작하지 않습니다.

다시 카메라를 이동했다면 `./Start-MacPi.command --installation mac-pi-new-position`처럼
새 이름을 지정하세요. 같은 설치의 이름은 재실행 때 재사용할 수 있습니다.
`--camera-name`, `--clip-device mps|cpu|auto`, `--without-clip`, `--no-browser`도 지원합니다.
접속 정보는 로컬 전용 `outputs/mac-pi-connection.json`에 소유자 읽기/쓰기 권한으로
저장합니다. 종료는 기존 **작업실 종료** 또는 실행 터미널의 Ctrl+C를 사용합니다.

### 보정판 없는 걸터앉음 테스트

영상을 눌러 **점 위치 수정**으로 검토할 수 있습니다. 카메라 이동 후에는 새 영역이 필요합니다.

골반이 침대 범위에 있는지, 허벅지가 침대 면을 따르는지, 무릎이 굽고 종아리가 아래로

표시합니다. 기존 단일/그룹 저장 판정 버전과 정답·학습 승인은 별도입니다.
엉덩이를 침대 안쪽에 두어도 다리를 아래로 내릴 수 있으므로 골반의 가장자리 근접은
필수가 아닙니다. 양쪽이 앉음으로 보이고 한쪽만 다리 기하가 유효하면 그 근거로
세부 자세를 구분하며, 반대쪽에도 유효한 상충 다리 근거가 있으면 불일치를 유지합니다.

않은 앉음은 **앉음·다리 위치 확인 중**이며, 머리 관절은 걸터앉음의 필수 조건이
아닙니다. 패널의 머리/몸통/다리 관절 수와 통합 판정 제외 여부를 확인할 수 있습니다.
관측 공백/끊김 때 결과를 지우며 다리 관절을 보간해 만들어내지 않습니다.
새 수치와 임시 영역은 실제 자세 정확도를 검증한 결과가 아닙니다.

테스트는 **바닥에 발을 둔 걸터앉음 → 다리를 침대 위에 올린 앉음 → 서 있음**을
각각 잠시 유지하고, 양쪽 영상의 관절과 카메라별 조건/보류 사유를 비교합니다.
화면을 여는 것만으로 측정·녹화·ToF 학습을 시작하지 않습니다.

### 공통 설치

현재 고정된 MediaPipe 0.10.35의 공식 macOS wheel은 arm64용입니다. PyAV 18.1.0 arm64 wheel의 최소 대상은 macOS 14입니다. 따라서 현재의 Mac 우선 대상은 **Apple Silicon(M1 이상), macOS 14 이상, ARM64 Python 3.12**입니다. Intel Mac과 Rosetta/x86 Python 조합은 현재 의존성 그대로 지원된다고 보장하지 않습니다. Windows와 Mac에서 같은 코드를 사용하지만 가상환경은 각 OS에서 새로 만듭니다.

프로젝트 폴더의 Terminal에서 실행합니다. MediaPipe .task 모델은 앞의 공통 안내대로 별도 준비합니다.

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -e ".[live,clip]"
.venv/bin/python -m bed_pose clip-setup
.venv/bin/python -m bed_pose live
```

MPS를 명시하려면 마지막 명령에 `--clip-device mps`, CPU로 확인하려면 `--clip-device cpu`를 사용합니다. 명시한 장치를 쓸 수 없으면 오류를 표시합니다. 카메라 접근 권한은 macOS 개인정보 보호 설정에서 실행 앱에 허용해야 합니다. 동일한 단일/두 카메라 판정 로직을 사용하며 MediaPipe는 CPU 실행입니다.

CLIP은 고정 문장 특징을 만든 뒤 문장 인코더/문장 projection 가중치를 해제합니다. 이미지 인코더와 캐시된 문장 특징·점수 계산은 그대로 유지합니다. 모델 파일의 크기와 로딩 중 최대 메모리를 줄이는 변경은 아니며, 로딩 후 불필요한 가중치의 상주를 줄이는 변경입니다. 실제 프로세스 사용량은 실행 장치의 메모리 할당 방식에 따라 다릅니다.

작은 무작위 CLIP 모델의 CPU 검사에서 해제 전후 이미지 점수가 동일하고 가중치 수가 감소함을 확인합니다. 이 검사는 사전학습 정확도나 Mac MPS 실기기 검증을 대신하지 않습니다. GPU 백엔드 간 수치 차이·실제 카메라 입력·MPS 실행은 Mac에서 확인해야 합니다.

배포 파일 확인: [MediaPipe 0.10.35](https://pypi.org/project/mediapipe/0.10.35/#files), [PyAV 18.1.0](https://pypi.org/project/av/18.1.0/#files). 배포 대상 확인과 실제 장치 검증은 구분합니다.


## CLIP 최적화 · 2026-10-31

모델은 기존 OpenAI CLIP ViT-B/16, 초기 점수 기준·문장은 그대로입니다. Mac/CPU 지원을 유지합니다. **기본은 FP32·모델 공유·묶음 크기 1**입니다. CUDA FP16과 묶음 추론은 실제 장치 비교 전 선택 옵션이며 자동 활성화하지 않습니다.

### 처리 자원과 지연 확인

작업실의 ‘처리 자원·전달 지연’을 펼치면 이미지 전처리, 추론/점수/CPU 회수, 공유 대기 시간, 실제 묶음 크기와 GPU 메모리를 확인할 수 있습니다. 전처리/전송/추론 수치는 GPU 커널 단독 시간이 아닌 호스트 벽시계 시간이며, 비동기 전송 대기는 추론/회수 구간에 포함될 수 있습니다. 메모리는 약 1초 주기로 읽는 **프로세스 전체 allocator 할당/예약 값**입니다. 입력별 사용량이나 장치 전체 점유율이 아닙니다. CPU에서는 GPU 메모리 값을 만들지 않습니다.

분석 화면은 수신→서버 응답까지의 나이, 브라우저 요청 왕복·이미지 디코딩·canvas 그리기 시간과 최근 2초의 서로 다른 분석 프레임 갱신률을 표시합니다. 각 값은 별도 구간이므로 합산해 정확한 종단 지연으로 해석하지 않습니다. 카메라 노출 시각·모니터 실제 출력 시각·최신 영상 모드/격자 갱신률은 측정하지 않습니다. 멈춘 영상의 나이는 계속 늘 수 있습니다.

새 측정의 각 프레임에는 실제 이미지 추론을 수행했을 때만 `image_runtime_metrics`가 기록되고, manifest의 `image_runtime`에는 정밀도·공유·묶음 설정이 남습니다. 미검출/입력 품질 보류에서 직전 추론 시간을 새 결과로 재사용하지 않습니다. 자원 진단값은 판정 근거가 아니며 정확도 지표도 아닙니다.

### CUDA 혼합 정밀도

```powershell
& .\.venv\Scripts\python.exe -m bed_pose live --clip-device cuda --clip-precision amp-fp16
```

이미지 인코더에만 CUDA autocast FP16을 적용합니다. 문장 특징·이미지 특징 정규화·유사도·최종 점수 계산은 FP32로 유지합니다. FP32 원본 가중치를 유지하므로 가중치 메모리가 절반이 되는 방식이 아니며, autocast 임시 캐시까지 포함한 총 메모리 감소를 보장하지 않습니다. 반복 추론 속도와 실제 할당/예약 값을 확인해야 합니다. 이 실행의 정책은 `clip-posture-0.3`, 이전 FP32는 `0.2`로 보존합니다. 같은 초기 기준이라도 경계 점수의 라벨/보류는 바뀔 수 있습니다. CPU/MPS에서 이 옵션은 거부하며 조용히 다른 정밀도로 실행하지 않습니다.

기존 FP32 비교 실행:

```powershell
& .\.venv\Scripts\python.exe -m bed_pose live --clip-precision fp32
```

### 모델 공유와 여러 카메라 묶음 추론

기본 실행은 같은 자산 해시·경로·장치·정밀도·실행 옵션의 CLIP을 한 번만 로딩합니다. 대상 추적·자세 점수·입력 이미지 미리보기·판정 설정은 입력별로 독립입니다. 한 입력을 닫아도 다른 입력이 사용 중이면 모델을 유지하며 마지막 사용자가 닫힐 때 해제합니다. 공유 실행기는 요청을 순서대로 처리하고 입력당 동시에 하나만 제출해 프레임 요청이 무한히 쌓이지 않게 합니다. 공유 대기로 입력별 지연이 늘 수 있으므로 이전 개별 모델과 비교하세요.

```powershell
# 두 입력의 준비된 요청을 최대 2개씩 처리, 수집 대기 상한 2ms
& .\.venv\Scripts\python.exe -m bed_pose live --clip-device cuda --clip-precision amp-fp16 --clip-batch-size 2 --clip-batch-wait-ms 2

# 이전 개별 모델·FP32와 비교
& .\.venv\Scripts\python.exe -m bed_pose live --no-clip-share --clip-precision fp32
```

한 입력만 있으면 묶음 수집 대기를 하지 않습니다. 여러 입력도 정해진 카메라나 미래 프레임을 기다리지 않고 준비된 요청만 모읍니다. 수집 대기는 0~10ms, 최대 묶음 크기는 1~4입니다. GPU 실행·앞선 요청을 기다리는 시간은 이 수집 상한과 별도입니다. 추론 자체가 느리면 전체 대기는 더 길 수 있습니다. 묶음 연산은 FP32에서도 작은 수치 차이가 날 수 있습니다. 서로 다른 정밀도의 시점 점수는 통합하지 않습니다.

CUDA 입력 전송은 재사용하는 pinned 메모리와 비동기 복사를 사용하고, 준비된 묶음은 전처리/이미지 추론/CPU 회수를 함께 처리합니다. 기존 Pillow 비율 유지 여백과 CLIP 정규화는 보존합니다. 실제 CUDA 속도·메모리 이득은 미검증입니다.

## 카메라 영상 녹화와 로그 대조

단일 카메라는 측정 시작 옆 **영상 녹화**, 두 카메라 그룹은 그룹 시작 전 **두 카메라 영상 녹화**를 선택합니다. 기본값은 꺼짐입니다. 두 카메라를 녹화하려면 두 입력이 모두 카메라여야 합니다. 녹화를 끄면 이전과 같이 관절·자세·시각 로그만 저장합니다.

각 카메라 기록 폴더에 `analysis_video.mkv`와 `video_frames.jsonl`을 저장합니다. 로그의 `frame_id`·`stream_frame_id`·정확한 수신 시각을 영상 프레임의 밀리초 PTS와 연결합니다. 그룹의 `alignment.jsonl`은 두 카메라 로그 프레임을 연결하므로 같은 인덱스로 각 영상 프레임을 찾을 수 있습니다. 녹화 후 **측정 기록**에서 측정을 열고 프레임 번호를 선택하면 저장 영상과 해당 로그·관절을 함께 확인합니다. 각 카메라는 개별 기록으로 표시되며 그룹의 기록 경로는 그룹 측정 영역에서 확인합니다.

영상은 **분석에 사용한 프레임만** 포함하며 카메라가 수신했지만 분석 전에 건너뛴 프레임은 녹화되지 않습니다. 무손실 FFV1 영상은 저장 공간을 많이 사용할 수 있고 인코딩이 분석 속도에 영향을 줄 수 있습니다. 영상 PTS는 측정 시작 기준 수신 시각을 밀리초 단위로 기록하며, 원래 나노초 수신 시각은 인덱스에 남습니다. 두 장치의 수신 시각 정렬은 근사값이며 실제 노출 시각 동기화는 보장하지 않습니다. 카메라 이동·장치 지연과 장시간 녹화 성능은 실제 환경에서 별도 확인이 필요합니다. 녹화 파일에는 사람이 식별될 수 있으므로 저장 위치와 접근 권한을 관리하세요.

단일·두 입력에서 **블랙박스 저장**과 구간 길이, 최대 용량을 선택하면 별도 `blackbox` 폴더에 영상과 로그를 구간별로 저장합니다. 두 입력은 각 구간에 양쪽 영상·로그와 수신 시각 근사 정렬·통합 결과를 연결하며, 한쪽을 보관 대상으로 지정하면 같은 구간의 양쪽을 함께 보관합니다. **측정 기록 → 블랙박스 별도 기록**에서 구간을 열고 **이 구간 보관** 또는 **보관 해제**를 선택합니다. 그룹 경로에서 구간별 통합 기록과 삭제 상태를 확인할 수 있습니다.

용량을 넘으면 완료된 가장 오래된 블랙박스 구간부터 삭제하며, 두 입력 구간은 양쪽 영상·로그와 통합 기록을 함께 정리합니다. 기존 일반·테스트 기록과 진행·열람·보관 중인 구간은 삭제하지 않습니다. 기존에 분할 없이 저장된 그룹 기록은 자동 삭제 대상이 아니지만 용량에는 포함됩니다. 보호된 기록 때문에 공간을 확보할 수 없거나 디스크 여유가 256 MiB 미만이면 측정을 종료합니다. 약 5초 간격 점검이므로 일시적으로 한도를 넘을 수 있습니다. 두 카메라의 분할 완료 시점은 정확히 같지 않으므로 경계 부근의 프레임이 서로 다른 구간에 들어가 미매칭될 수 있습니다. 각 프레임의 수신 시각과 미매칭 기록은 보존하며, 실제 노출 시각의 동기화를 뜻하지 않습니다. 분할 마감 중 입력 프레임이 빠질 수 있으며 실제 카메라 장시간 검증은 남아 있습니다.

## 침대 영역의 사람 우선 선택

새로 연결한 입력은 MediaPipe에 최대 3명의 후보를 요청합니다. 침대 영역이 지정된 경우 검출된 각 사람의 양쪽 골반 관절이 영역 안에 있고 좌표·제공된 관절 신뢰도가 유효한지 확인합니다. 해당 조건을 충족하는 후보가 한 명이면 화면 밖 주변 사람보다 그 대상을 우선해 관절·영상 자세를 판단합니다. 두 카메라는 각 화면에서 같은 절차를 독립 수행합니다.

두 카메라 통합에서는 골반이 가려져 위치를 확인할 수 없거나 영역 안 후보가 여러 명이면 대상을 확정하지 않습니다. 침대 안 후보가 없을 때 개별 카메라의 기존 단일 인물 진단은 유지합니다. 화면상 겹침은 침대 점유의 물리적 확인이 아니며 두 영상의 동일인을 자동 인증하지 않습니다. 최대 3명은 모델에 요청하는 상한이지 검출 성능 보증이 아닙니다. 여러 명 감지는 더 많은 연산과 지연을 유발할 수 있고 MediaPipe의 단일 인물 내부 평활화가 꺼질 수 있습니다. 이미 연결된 입력은 다시 연결해야 설정이 적용됩니다. 실사 영상에서 우선 선택 정확도·성능은 검증되지 않았습니다.
