## 구현한 기능

| 명령 | 입력과 출력 | 해석 |
|---|---|---|
| `evaluate` | 기존 run → 새 `evaluations/<evaluation_id>/aggregate_metrics.json`, `report.md`, 완결/해시 manifest | 후보 출력률, 처리 성공률, 오프라인 전체 경로 FPS, 단계별 p50/p95와 표본/누락 수 |
| `compare` | 요청한 모든 run 경로 → 새 출력 폴더의 `comparison.json`, `report.md`, 완결/해시 manifest | 누락·손상·실패 실행도 행에 남김. 같은 조건 그룹·scope·대상 연결 방식인지 표시. 순위·우열 결론 없음 |
| `render` | run + 같은 원본 영상 → 새 폴더의 프레임별 SVG, `frames.json`, `index.html`, 완결/해시 manifest | 원본 RGB를 무손실 PNG로 포함하고 공통 17점·연결선과 상태/PTS를 표시. 단일 HTML에서 큰 영상·정보 패널·이전/다음·슬라이더·관절 표시 전환 |

모든 명령은 모델을 재호출하지 않습니다. 원본 run의 결과 파일은 수정하지 않으며 기존 출력 폴더는 덮어쓰지 않습니다. 평가는 매번 새 ID를 사용합니다. 추론 설정에 GT나 외부 센서 입력을 추가하지 않았습니다.

## 실행 예

아래 `<run_id>`는 demo가 출력한 run_directory의 ID입니다. 자신의 영상 대신 생성 영상으로 기능을 점검할 수 있습니다.

```sh
python -m pip install -e .
python -m bed_pose demo --output data/demo_01
python -m bed_pose evaluate --run data/demo_01/runs/<run_id>
python -m bed_pose render --run data/demo_01/runs/<run_id> --video data/demo_01/synthetic_input.mkv --output data/overlay_01
python -m bed_pose compare --runs data/demo_01/runs/<run_id> --output data/comparison_01
```

`render` 출력의 `index.html`에는 모든 SVG와 필요한 기록이 포함됩니다. 이 파일 하나를 내려받아 브라우저로 열면 됩니다. 외부 폰트·CDN·서버·JSON fetch가 없습니다. 큰 영상과 현재 프레임 정보, 프레임 목록을 분리했고, 모바일에서는 영상 바로 다음에 탐색 조작이 나옵니다. 이전/다음·슬라이더·목록·좌우 키와 관절 표시 전환을 지원합니다. 이는 실시간 모니터나 동영상 파일이 아닙니다. VFR·누락 PTS를 임의의 고정 FPS로 바꾸지 않기 위해 첫 구현은 프레임 이미지와 원본 PTS/time base/duration 목록으로 제공합니다. 모델의 내부 전처리 영상 대신 실제 분석 입력의 정규 RGB 프레임 위에 그립니다.

실패 실행의 기록이 완결되어 있을 때 부분 진단은 다음과 같이 명시합니다.

```sh
python -m bed_pose evaluate --run data/demo_01/runs/<run_id> --scope diagnostic_partial
```

## 계산 규칙과 한계

- 후보 출력률은 `후보 수>0인 프레임/원래 입력 프레임 전체 수`, 처리 성공률은 `ok/원래 전체 수`입니다. 정상 0명은 처리 성공이며, 실패·미처리를 분모에서 빼지 않습니다. **사람 검출 정확도나 침대 자세 정확도가 아닙니다.**
- full은 성공·기록 완결·무결성이 확인된 실행에만 계산합니다. 실패/취소 실행을 full로 요청하면 모든 성능 지표가 `unavailable/INCOMPLETE_RUN`입니다. 실행 상태·오류·프레임 수는 계속 보고합니다.
- diagnostic_partial은 기록이 완결된 실패 실행에서도 전체 입력 분모로 출력률을 계산합니다. 시간은 실제 측정된 표본만 사용하며 프레임 ID 목록·표본 수·측정 누락 수를 남깁니다. FPS는 미계산합니다.
- 전체 FPS의 T는 기존 manifest의 `pipeline_started_ns`부터 `data_finished_ns`까지입니다. 첫 호출, 디코딩·기록·정리·최종 데이터 fsync를 포함하고 초기화·warm-up·최종 manifest 교체·후처리를 제외합니다. 실시간 카메라 지연이 아닙니다.
- 단계별 시간은 프레임 처리 상태 ok/failed로 분리합니다. 그룹의 실패가 해당 단계의 SDK 실패를 뜻하는 것은 아닙니다. 첫 측정 프레임/값도 별도로 보존합니다. p50/p95는 `(n-1)*p` 위치의 선형 보간입니다. 빈 표본은 0으로 만들지 않습니다.
- 원본 결과/참조/파일 해시 외에 입력 스냅샷·프레임 해시, 요청/해석 설정의 비경로 필드, 어댑터·매핑 profile 해시를 확인합니다. 읽는 중 변경도 검사합니다. 손상된 기록의 지표는 모두 `invalid/INPUT_INTEGRITY_ERROR`이며 CLI 종료 코드는 4입니다.
- 프레임 간 시계 순서와 전체 실행 시간 경계도 확인합니다. 이상이 있으면 시간 지표는 `invalid/CLOCK_INVALID`입니다. 유효한 프레임 수 기반 출력률은 별도로 유지합니다. `integrity`는 기록 정합성, `evaluation_status`는 지표 평가의 invalid 여부를 나타냅니다.
- 정답·인물 연결 입력은 이번 버전에서 받지 않습니다. PCK·정지 떨림은 `NO_VERIFIED_GT`, 대상 관절 출력률은 `NO_TARGET_ASSOCIATION`으로 미계산합니다. 자세/이벤트 정확도는 제공하지 않습니다. GT 주석 형식·주석 지침·대상 연결·scale/alpha 및 정답 기반 평가 구현은 후속 작업입니다.
- 비교 그룹에는 동일 입력 manifest, scope, 연결 방식, 합성/모델 종류, 실행 모드, warm-up, 실행 환경, 추론 코드 source hash, 평가 정책 hash가 반영됩니다. 다른 그룹은 같은 조건의 비교로 취급하지 않습니다. 모델별 설정·자산·장치·SDK 정보는 각 행의 JSON에 보존합니다. 같은 그룹이어도 주석·독립 반복·장비 부하 등을 확인하지 않고 품질이나 속도 우열을 확정하지 않습니다.
- 비교 요청의 누락/손상 경로는 삭제하지 않으며 진단 행과 종료 코드 4로 남깁니다. 존재하지 않는 run을 평가하면서 해당 run 폴더를 새로 만들지 않습니다.

## 표시 규칙

HTML 상단에는 합성 실행의 `합성 데이터 · 실제 인식 아님` 또는 모델 경로의 `모델 출력 · 정답 미확인`을 지속 표시합니다. 별도 SVG에도 작은 `SYNTHETIC`/`MODEL OUTPUT` 표식을 남깁니다. 전체 run 상태·프레임 처리 상태·후보 수와 시간은 별도 패널에 표시합니다. 정확한 PTS·time base·실패 코드·식별자는 접힌 상세 영역에 둡니다. 소수 시간은 표시용 반올림값이며 원본 PTS는 변경하지 않습니다. 후보 수 null은 0으로 바꾸지 않습니다.

유한하고 화면 안에 있는 예측 관절만 그립니다. 누락·화면 밖 관절을 보간하거나 테두리에 강제로 옮기지 않고, 양끝 관절이 모두 표시 가능할 때만 선을 그립니다. confidence 임계값이나 해부학적 합격 판정은 추가하지 않았습니다. 후보 색/ID는 프레임 안의 표시이며 동일 인물 추적을 의미하지 않습니다.

영상 SHA-256과 프레임별 PTS·픽셀·회전을 재검증합니다. 렌더링이 중단되면 manifest는 `complete:false`로 남으며, 완성된 출력으로 취급하면 안 됩니다. 생성물의 이미지와 식별 정보는 원본 영상과 같은 접근/보관 범위로 관리합니다. 원본 영상·실험별 결과·오버레이는 공개 GitHub 업로드 대상이 아닙니다.

현재 후처리는 결과 프레임·쓰기 시각·필요한 관절을 메모리에서 읽습니다. 대규모/장시간 영상에서의 메모리 사용, 동영상 인코딩·자동 재생, 실시간 표시, GT 기반 평가, 연속 누락·떨림 분석, 외부 센서 비교는 이번 완료 범위에 포함하지 않습니다. 파생 보고 파일의 전원 장애 내구성을 보장하지 않습니다.

## 개발 검증

생성한 비인체 6프레임 VFR 영상과 합성/오류 주입 기록으로 확인했습니다. 수작업 기대값에는 출력률 0.5, 실패 후 전체 분모 6 유지, `[10,20,30,40]ms`의 p50=25/p95=38.5, 정상 0명·실패·미처리의 표시 구분, SVG 속 PNG를 복호화했을 때 원본 RGB와 픽셀 일치를 포함합니다. 기존 SDK 경계 검사와 함께 전체 테스트를 실행합니다. 실제 모델·침대 정확도를 검증한 작업이 아닙니다.

전체 51개 검사가 통과했고, 0.4.0 wheel을 별도 디렉터리에 설치해 저장소 밖에서 demo/evaluate/render, 오류 주입의 부분 진단, 누락 실행을 포함한 compare의 종료 코드 4, 기존 inspect를 실행했습니다. 별도 CairoSVG 개발 도구로 생성 SVG를 PNG로 렌더링해 합성 표시·시각·관절 표시도 확인했습니다. CairoSVG는 제품 의존성에 추가하지 않았습니다. 이 환경의 headless Chromium은 제한 시간 안에 스크린샷을 생성하지 못했으므로 HTML 프레임 선택의 실제 브라우저 동작은 미확인입니다. SVG 구조·내장 PNG 복호화·카탈로그와 링크 생성은 검사했습니다. Windows 및 실제 모델/침대 영상 검증은 별도로 남아 있습니다.

## 시인성·화면 구성 개선 · 2026-10-27

0.4.1에서 `viewer.py`와 패키지 HTML 템플릿을 추가했습니다. SVG의 최소 640px 빈 캔버스·긴 문구 배너를 제거하고 원본 종횡비로 확대합니다. 원본 픽셀·관절 좌표는 그대로 유지하며 연결선은 화면 확대에 따라 과도하게 굵어지지 않도록 표시합니다. 정보 패널의 관절 수는 모든 후보의 화면 내 공통 관절 합계이지 정확한 관절 수나 품질 점수가 아닙니다. 합성 관절을 사람 모양으로 바꾸거나 실제 자세 판정 값을 추가하지 않았습니다.

Playwright와 직접 실행한 Chromium으로 HTML 내용을 로드해 데스크톱 1440px·모바일 390px 화면을 확인했습니다. 프레임 이동·슬라이더·좌우 키·관절 표시·선택 항목의 가로 스크롤·모바일 배치 순서·후보 없음·추론 실패·미처리·null 수·JS 비활성의 첫 프레임/합성 표시를 검사했습니다. 가로 화면 넘침·JS 오류·외부 네트워크 요청이 없었습니다. 앞 절의 브라우저 미확인은 이전 0.4.0 검증 상태이며, 새 템플릿은 이 방식으로 확인했습니다. 이 환경의 file:// 정책 제한으로 직접 파일 경로 탐색 대신 같은 파일 내용을 브라우저에 로드했습니다. Windows 실제 동작·모델/침대 성능 검증을 대체하지 않습니다.

이미지를 HTML 안에도 포함하므로 긴 영상의 HTML 크기·메모리 사용은 증가합니다. 현재 프레임 이미지 기반 후처리의 제약이며 실시간 모니터 구현으로 취급하지 않습니다.

0.4.1 wheel을 별도 경로에 설치하고 저장소 밖에서 템플릿 포함과 demo/render/inspect 실행을 확인했습니다. 전체 개발 검사 53개를 통과했습니다.

## 긴 영상의 첫 프레임만 표시

`render --max-frames 30`은 처음 최대 30개만 HTML에 포함합니다. 전체 입력/추론 기록 검사는 유지하고 표시 목록만 줄입니다. 원본 프레임 ID·PTS와 전체 프레임 수를 보존하며, 출력 manifest의 `rendered_frame_range`는 끝을 제외한 [0,N) 범위입니다. 선택한 접두 구간만 다시 디코딩하며 나머지 프레임을 재생 검증했다고 주장하지 않습니다. 미리보기 제한은 인식 결과·평가 분모를 변경하지 않습니다.

## 관절 이름·원본 점수 검사 · 0.5.0

기존 run의 raw_results.jsonl과 공통 관절을 후보 ID·source_index로 연결해 표시합니다. 모델 재실행 없이 새 출력 폴더로 render만 다시 수행하면 됩니다. 원본 추론 파일·공통 좌표·프레임 상태·임계값은 변경하지 않습니다.

- 오른쪽 ‘관절 살펴보기’에서 후보와 공통 관절을 선택하면 영상의 해당 점에 흰 테두리를 표시합니다. 흰색은 선택 표시이며 품질 합격 표시가 아닙니다. 영상의 점을 클릭하거나 전체 관절 표의 이름으로도 선택할 수 있습니다.
- ‘관절 이름’을 켜면 선택 후보의 화면 내 관절 이름을 표시합니다. 좌우는 신체 기준입니다. 관절 누락·화면 밖 점을 새 위치에 보간하거나 끌어오지 않습니다.
- visibility는 모델의 가시성 관련 원본 점수, presence는 장면 내 존재 관련 원본 점수입니다. 실제 가림 라벨·좌표 정확도·보정된 확률로 취급하지 않습니다. 설치 SDK의 NormalizedLandmark 설명은 모델에 따라 sigmoid 출력 또는 sigmoid 입력일 수 있다고 명시하므로, 임의 변환·0~1 클램핑·백분율·공통 임계값을 추가하지 않았습니다.
- image 좌표 블록에 연결된 score_blocks만 사용합니다. MediaPipe의 공통 왼쪽 무릎은 원본 인덱스 25로 연결하며 공통 인덱스 13으로 원본 점수를 읽지 않습니다. world 점수로 대체하지 않습니다.
- 표시는 소수 셋째 자리이며 마우스를 올리면 원본 숫자를 확인할 수 있습니다. 0은 0.000, null/미제공은 ‘미제공’, 비유한값은 ‘비유한값’, 형식·길이·중복 블록 이상은 ‘형식 불일치’로 구분합니다. 원본 파일의 값은 보존됩니다.
- 좌표 누락과 점수 부재는 독립적으로 표시합니다. 좌표가 없는데 점수가 있거나, 화면 밖 좌표에 점수가 있어도 그대로 분리해서 보여 줍니다. 후보 0개·실패·미처리에는 이전 프레임 점수나 가짜 0을 남기지 않습니다.
- 이는 수동 분석 보조 기능입니다. 실제 구동 중 사용할 품질 거부/보류 정책, 판정 기준과 검증용 임계값은 아직 설계·검증 전입니다.

기존 SDK 원본 점수의 설명은 [v0.10.35 landmark.py](https://github.com/google-ai-edge/mediapipe/blob/v0.10.35/mediapipe/tasks/python/components/containers/landmark.py)의 NormalizedLandmark를 기준으로 설치본도 확인했습니다. SDK score 필드를 정답으로 검증한 것은 아닙니다.

합성 좌표·SDK 결과 형식의 가상 자료로 공통→원본 매핑, 후보 순서, image/world 분리, 0/null/비유한/형식 오류, 좌표 누락·화면 밖, 기록 보존을 검사했습니다. 실제 Chromium에서 후보·관절·표·점 클릭·이름·관절 표시 전환과 PC/모바일 배치, 프레임 변경 시 이전 점수 제거를 확인했습니다. JS 오류·외부 요청이 없었습니다. 개발 검사는 총 61개입니다. 실제 사용자 영상은 이 작업 공간으로 가져오지 않았습니다.

0.5.0 wheel을 별도 설치해 저장소 밖에서 점수 연결·부분 render·템플릿·원본 기록 무결성을 확인했습니다. 점수 연결을 위해 원본 JSONL도 읽으므로 --max-frames는 HTML에 넣는 이미지 수를 제한하는 옵션이며 전체 기록 검사나 JSONL 읽기까지 제한하지는 않습니다.
