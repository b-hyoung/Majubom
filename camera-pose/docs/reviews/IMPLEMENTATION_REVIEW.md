## 결론

핵심 원칙인 목표·예측·정답·외부 센서의 분리, 미구현 판정의 명시, 원본 관절과 시각의 보존은 검토한 코드에서 유지된다. 학습보다 운영 기능을 먼저 연결하는 순서는 DECISIONS의 사용자 요청과 일치한다. 다만 아래 실행 오류·요구사항 차이·데이터 계약 및 문서 문제가 있어, 현재 상태를 문제없는 완료 구현으로 판단할 수 없다.

## 발견 사항

### R1 · P2 · 그룹 정리 중 입력 삭제 요청이 유실됨 — 재현 확인

- 위치: `src/bed_pose/live_web.py:228`, `src/bed_pose/group_session.py:75`.
- 조건: 그룹 종료 후 `finalizing` 중 입력 삭제/닫기.
- API는 `accepted=true`를 반환하지만 `MeasurementGroup.stop()`이 `_finalize_job` 존재 시 즉시 반환해 Worker에 닫기 요청을 보내지 않는다. 입력 제거는 `closed`를 기다리므로 완료되지 않는다.
- 합성 입력의 최종 생성 작업을 Event로 잠시 지연시켜 재현했다. 삭제 응답은 HTTP 200, `stop_requested=False`; 그룹 완료 뒤에도 입력과 실행 중 Worker가 남았다.
- 영향: 사용자가 삭제했다고 생각해도 영상 입력·추론이 계속된다. 실제 카메라에서도 같은 제어 경로를 사용하지만 이번 검증은 합성 입력이다.
- 권고: 파생 기록 정리와 장치 닫기를 분리하고 정리 중 삭제/닫기도 처리한다. 정리 결과와 원본 기록은 보존한다. 해당 단계의 삭제 회귀 검사를 추가한다.

### R2 · P2 · 그룹 측정에서는 침대 영역의 즉시 수동 보정이 차단됨 — 재현 확인

- 위치: `src/bed_pose/live_web.py:228`; 요구 근거: `docs/REQUIREMENTS.md`의 침대 영역 항목, `docs/LIVE_MEASUREMENT.md:60`.
- 활성 그룹이면 삭제/닫기 외의 입력 명령을 모두 거부한다. `region` 변경/해제도 HTTP 400과 “그룹 종료 버튼을 사용하세요”로 거부되는 것을 확인했다.
- 영향: 잘못 지정한 영역을 발견해도 같은 그룹 측정을 유지하며 바로 고칠 수 없다. 개별 측정의 영역 변경 이력 기능과 그룹 동작이 다르다.
- 권고: 준비/기록 중 영역 수정 경로를 허용하고 입력별 버전·적용 프레임 이력을 유지한다. 영역 해제 구간은 통합 입력을 보류한다. 시작/종료 중 경계 처리는 따로 검사한다.
- 합의된 최종 요구사항과의 차이이며, 모든 운영 기능이 이미 완료되었다는 의미는 아니다.

### R3 · P2 · bed_mask의 의미가 문서에서 명확하지 않음 — 출력 확인

- 위치: `src/bed_pose/fusion_inputs.py:68`, `docs/TWO_VIEW_INPUTS.md:55`.
- 코드는 `bed_mask = bool(inside_image and region)`이다. 침대 사각형 안에 있는지는 검사하지 않는다.
- 640×360 영상에서 영역 (10,10)~(100,100), 관절 (250,250)을 넣으면 `bed_xy=[2.666...,2.666...]`, `image_mask=true`, `bed_mask=true`가 나온다.
- 문서는 이미지 밖/침대 밖 좌표를 두 마스크로 구분한다고 읽힐 수 있지만, 실제 bed_mask는 화면 내 좌표와 기준 영역의 존재를 뜻한다. 침대 내부 여부로 소비하면 잘못된 결과가 된다.
- 권고: 좌표 계산 가능성과 침대 사각형 내부 여부를 별도 필드로 정의한다. 침대 밖 관절은 이탈 분석에 필요하므로 무조건 삭제하거나 결측 처리하지 않는다. 계약·정책 버전·기존 기록 호환성과 경계 검사를 함께 정리한다.

### R4 · P2 · 현재 상태 안내와 과거 기록이 혼재함 — 문서 대조 확인

- `docs/MEASUREMENT_PROTOCOL.md:91`: 계획 목표·준비/완료 입력이 미연결이라고 하지만 `SINGLE_POSTURE_PLAN.md`와 구현에는 두 입력 그룹의 단일 계획 측정이 있다.
- `ROADMAP.md:64`: 최소 영역·단일 자세·준비 완료가 미완료로 남아 있는 반면 하단 단일 계획 섹션은 완료다. 단일 입력 지원과 두 입력 그룹 지원을 구분해야 한다.
- `docs/LIVE_MEASUREMENT.md:30`: 번호 탐색 안내가 현재 사용법처럼 남아 있고, 54행은 대상 선택/추적이 없다고 설명한다. 하단에는 이름 기반 장치 선택과 잠정 추적 구현이 기록돼 있다.
- `docs/PROJECT_STATUS.md` 상단 후속 작업에는 실시간 측정기 구현·평가/시각화 등이 과거 미완료 상태로 남아 있다. 단순히 문서 아래에 새 항목을 추가해서는 첫 독자의 현재 상태 오해를 막지 못한다.
- 권고: 현재 지원/부분 지원/미구현 표를 앞에 유지하고 과거 변화는 별도 이력으로 분리한다. 실제 모델 실행의 사용자 보고, 합성 개발 검사, 정답 기반 성능 검증도 구별한다.

## 확인된 일치 사항과 남은 범위

| 항목 | 리뷰 판단 |
|---|---|
| 초기 자세 범위 | supine/side/edge_sitting 유지 |
| 목표와 정답 | 계획 목표만 기록, verified_gt는 null, 예측으로 전용하지 않음 |
| 외부 센서 독립성 | 센서 결과를 카메라 예측에 넣는 경로 없음; 센서 연동 자체는 미구현 |
| 두 카메라 | 원본 기록·종료 후 수신 시각 정렬·시점별 특징 준비까지 구현. 실시간 통합 자세 판정은 미구현 |
| 시각 | 수신 시각을 노출 시각으로 주장하지 않음. 파일은 미디어 오프셋 미확인 시 정렬 보류 |
| 추적 | 관절 이동 기반 잠정 추적과 보류/수동 재지정. 실제 동일인 검증은 아님 |
| 모델 | MediaPipe 실험용 경로. 후보 비교에 따른 최종 선정 근거는 아직 없음 |
| 계획 측정 | 두 입력 그룹의 단일 목표 지원. 단일 입력 계획·여러 자세 순차 진행은 미완료 |
| 자세·이벤트 | 분류, 점유, 이탈·복귀 판정 미구현. 화면 미검출을 이탈로 확정하지 않음 |
| 다른 운영 목표 | 선택적 영상 녹화·자동 침대 인식·정답 수집/평가 및 외부 센서 비교는 후속 |

## 수정 결과 · 2026-10-28

- R1: 정리 중에도 입력 닫기를 전달한다. 파생 파일 생성과 장치 연결 종료를 독립 처리한다.
- R2: 그룹 준비/기록 단계의 영역 수정·해제를 서버와 HTML에서 허용한다. 시작/종료/정리 중은 제한한다. 영역 없는 준비 상태에서 시작하면 기록 생성 전 실패 처리한다.
- R3: bed_mask의 기존 가용성 의미를 유지하고 inside_bed(true/false/null, 사각형 경계 포함)를 추가했다. 새 스키마/정책은 0.2이며 0.1 파일은 기존 정책으로 검사한다.
- R4: 진행 현황·사용법 앞에 현재 지원 표를 추가하고 측정 절차·로드맵의 상충 상태, 장치 선택/대상 추적 안내를 수정했다. 날짜별 이력은 과거 근거로 남긴다.

후속 검증: `/tmp/bed-review-env/bin/python -m unittest discover -s tests -q`로 **124개 통과(54.821초)**. 추가한 5개는 정리 중 삭제/양쪽 닫기 및 기록 보존, 그룹 영역 수정·해제·복구/보류 이력, 사각형 내부·외부·경계·결측 구분, 기존 0.1 기록 검사, 준비 중 영역 해제 후 잘못된 시작 방지를 확인한다.
