## 2. 프로젝트의 핵심 경계

목적은 카메라 영상으로 침대 위 자세·움직임을 분석하고 외부 ToF·mmWave 시스템의 독립 결과와 같은 시간대에 비교하는 것입니다.

- **독립성:** 외부 센서 결과와 계획 목표를 카메라의 자세·이벤트 예측 입력으로 사용하지 않습니다.
- **라벨 출처:** 계획 목표, 카메라 예측, 외부 센서 결과, 확인된 실제 정답을 각각 관리합니다. 목표·버튼 입력·예측을 실제 정답으로 자동 대체하지 않습니다.
- **출력 구분:** 스켈레톤 추정, 자세 분류, 침대 점유 상태, 이탈·복귀 이벤트는 서로 다른 역할입니다.
- **평가 구분:** 두 시스템의 일치도와 실제 정답 기준 정확도는 별도 지표입니다. 정답이 확인된 구간에서만 정답 기반 성능을 평가합니다.
- **실패 처리:** 사람 미검출·관절 불량·침대 영역 불확실을 구분합니다. 화면에서 사라졌다는 이유만으로 이탈을 확정하지 않습니다.

## 3. 합의와 후보를 구분하기

범위의 상세 기준은 [결정 사항](docs/DECISIONS.md)입니다. 아래 내용과 최신 결정이 다르면 변경 근거를 확인하고 관련 문서를 함께 정리합니다.

| 상태 | 유지할 내용 |
|---|---|
| 합의된 목표 | 실시간 분석·기록, 선택적 녹화, 침대 영역 자동 인식·재인식·즉시 수동 보정 |
| 합의된 운영 | 자유·단일·순차 측정, 자동·수동 진행, 자세별 준비 시간과 준비 완료 입력 모두 지원 |
| 합의된 초기 범위(2026-10-27) | 바로 누움·옆으로 누움·걸터앉음, 자세 변화·이탈·복귀, 내려와 완전히 서면 이탈 완료, 세션 중 카메라 고정 |
| 잠정·설계 제안 | 복귀 운영 해석의 세부 조건, 단일 대상 선택·추적, 안정·변화 후보·판정 보류, 외부 비교 범위와 실험 순서 |
| 미정 | 자세 주석 경계·이벤트 시작 및 세부 판정 기준, 외부 라벨 매핑·시간 기준, 구체적 촬영 배치, 개발 기술·모델, 성능 목표 |
| 보류 | 스마트폰 웹 원격 제어·모바일 표시, 사후 정답 수정 UI, 추가 자세 세분화·이불 대응·실사용 확대 |

- 최소 실증에서 수동 침대 영역 지정과 단순 조작부터 시작할 수 있습니다. 구현 순서를 뒤로 미룬 것을 합의된 목표의 삭제로 처리하지 않습니다.
- 녹화를 꺼도 분석과 결과 기록은 계속되어야 합니다.
- 스마트폰을 **카메라 입력**으로 쓰는 후보와 **웹 원격 조작** 보류 기능을 혼동하지 않습니다.
- 기술 후보는 침대 환경의 인식 품질·실험 결과를 근거로 비교하며, 코드 최적화·모듈 분리·지연 측정은 별도로 고려합니다. 현재 구현은 로컬 Python 추론이며 최종 실행 플랫폼 선정과 성능 실증은 별도입니다.
- MediaPipe Pose Landmarker·YOLO Pose·RTMPose의 우선 비교와 MoveNet 대안은 제안입니다. 실험 없이 채택 기술이나 성능 순위로 바꾸지 않습니다.

## 4. 자료와 검증 원칙

- 논문의 보고 결과, 프로젝트 적용 제안, 실제 자체 실험 결과를 구분합니다.
- **본문 미확인 논문은 서지(제목·저자·연도·DOI)만 후보로 관리하고 연구의 방법·데이터·성능·한계·효과에 관한 사실 판단, 기술 선정·설계 근거에서 제외합니다.** 초록·검색 요약에 나온 주장을 사실로 확정하거나 근거 표에 재사용하지 않습니다. 현재 P11·P12·P19·P34가 이에 해당합니다.
- 논문 내용을 추가·수정할 때는 해당 원문의 방법·실험·표를 직접 확인하고 **확인한 정확한 판본·절·표**를 기록합니다. 공개판만 확인한 경우 최종 출판본에도 같은 내용이 있다고 주장하지 않습니다. P35의 2022 ACM 최종판은 **본문 미확인·해당 판본 판단 제외**입니다.
- 본문 미확인·판본 미확인·수치 불일치를 명시하며, **해결되지 않은 주장은 선정·비교의 사실 근거에서 제외**합니다. 기존 요약을 읽은 것만으로 원문을 새로 검증했다고 쓰지 않습니다.
- API·설치·모델 기능은 구현 시점의 공식 자료와 실제 환경을 확인합니다. 존재하지 않는 옵션·명령·성능 수치를 만들지 않습니다.
- 관절의 정의·좌표계·신뢰도·결측을 보존합니다. 신체 정규화 때문에 침대 상대 위치가 사라지지 않게 하고, 추정 3D와 센서 실측 거리를 구분합니다.
- 촬영·수신·처리·출력·버튼 시각을 구분합니다. 시간 모델의 미래 프레임 사용과 평활화 지연을 기록합니다.
- 참가자·세션 분할과 인접 프레임·겹치는 시간 창의 데이터 누출을 확인합니다. 유효 구간 성능과 판정 불가 비율을 함께 보고합니다.
- 원본 영상·개인정보·학습/평가 데이터는 GitHub에 올리지 않습니다. 촬영 동의·접근 권한·보관 방식은 수집 전에 정합니다.

## 5. 작업 진행과 완료 기준

1. 이번 목표, 변경 범위, 완료 기준을 짧게 정리하고 관련 작업을 진행합니다.
2. 필요한 설정이 이미 문서·코드에 있으면 재사용합니다. 기술·라벨·성능 목표를 임의로 확정하지 않습니다.
3. 결과를 바꾸는 필수 정보가 없으면 필요한 항목만 질문합니다. 그 답에 의존하지 않는 작업은 계속하고, 임시 가정은 명시합니다.
4. 기존 변경 사항을 보존하고 요청과 관계없는 기능 추가·대규모 재구성을 피합니다.
5. 변경에 맞는 확인을 수행합니다. 문서는 링크·상태·용어의 일관성을, 코드는 실제로 실행 가능한 검사와 관련 동작을 확인합니다.
6. 실행 명령은 저장소·환경에서 확인한 것만 사용합니다. 장비·데이터가 없어 못 한 검증과 모의 입력으로만 확인한 부분을 구분합니다.
7. 진행 상태가 바뀌면 [진행 현황](docs/PROJECT_STATUS.md)과 [로드맵](ROADMAP.md)의 관련 항목을 갱신합니다. 새로운 합의는 [결정 사항](docs/DECISIONS.md)에 날짜·근거·미해결 조건을 남깁니다.

**구현 완료, 실행 확인, 실제 환경 성능 검증은 서로 다른 상태입니다.** 문서 작성이나 모의 실행을 실제 측정 성공으로 보고하지 않습니다.

## 문서 관리

README는 소개·진입점, PROJECT_STATUS는 현재 지원·검증, ROADMAP은 다음 작업, DECISIONS는 합의·미정 항목을 관리합니다. 기능별 사용법은 guides, 기술 계약은 design/development, 연구는 research, 리뷰는 reviews, 과거 과정은 archive에 둡니다. 같은 변경 문단을 여러 문서에 반복해서 추가하지 않습니다.

미완료 목표·연구 과제·후속 검증은 ROADMAP에 단계·의존 조건·완료 기준과 함께 유지합니다. 요약·폴더 정리를 이유로 archive에만 남기지 않습니다. 삭제·보류 전환은 사용자 결정과 근거를 확인합니다.

문서의 이전 버전은 Git 이력의 고정 커밋 링크로 참조합니다. BEFORE/OLD/BACKUP 복사본을 새로 만들지 않고, 같은 사용 흐름의 문서는 통합하며 기존 링크를 갱신합니다.
