## 1. 동일 I2C 주소 충돌 — 듀얼 VL53L5CX

**문제**
VL53L5CX 2개의 **기본 I2C 주소가 0x52로 동일**. 한 버스(SDA·SCL 공유)에 둘 다 붙이면 통신 충돌로 둘 중 하나도 제대로 못 읽음.

**원인 분석**
- 두 센서를 구분하려면 한쪽 주소를 바꿔야 하는데, 주소 변경 명령(`vl53l5cx_set_i2c_address`)을 쏘는 순간 **같은 주소를 가진 두 센서가 동시에 반응**.
- 즉 "둘을 분리하려면 먼저 둘을 분리해 둔 상태여야 하는" 닭-달걀 문제.

**해결** — LPN 핀으로 순차 부팅 ([`main.ino:164-193`](src/main.ino))
1. 두 센서를 모두 LPN LOW로 꺼둠(`begin()`).
2. **센서2만 LPN HIGH** → 0x52로 부팅 → **0x54로 주소 변경** → 펌웨어 로드.
3. 그다음 **센서1 LPN HIGH** → 0x52 그대로 유지.
4. 결과 버스 상태: `tof1@0x52`, `tof2@0x54` — 충돌 없음.

**결과**
점퍼 와이어 4선(SDA·SCL 공유 + LPN 2개)으로 **단일 I2C 버스에서 듀얼 센서 동시 운용** 성공.

## 2. 주소 리셋 함정 — 전원 재공급 없이 재플래시

**문제**
한 번 0x54로 바꾼 센서가, 재플래시할 때마다 어떤 주소에 있는지 알 수 없음. 펌웨어를 다시 구우면 코드는 "기본 0x52"를 가정하는데 센서는 0x54에 남아 있어 부팅 실패.

**원인 (데이터시트 함정)**
- VL53L5CX 주소는 **USB 전원 재공급(완전 OFF→ON) 때만 0x52로 리셋**.
- **LPN 토글로는 주소가 안 바뀜** → 재플래시할 때마다 USB를 물리적으로 뽑았다 꽂아야 하는 비효율.

**해결** — 부팅 시 I2C 버스 전체 스캔 ([`main.ino:39-63`](src/main.ino))
```cpp
// 0x08~0x77 전체를 스캔해 현재 살아있는 주소를 자동 감지
for (uint8_t a = 0x08; a <= 0x77; a++) {
  wi->beginTransmission(a);
  if (wi->endTransmission() == 0) {           // ACK 응답 = 그 주소에 센서 존재
    if (curAddr == 0) curAddr = (a << 1);     // 7bit → 8bit 변환
  }
}
p_dev->platform.address = curAddr;            // 드라이버 주소를 실제 주소에 맞춤
if (curAddr != addr) vl53l5cx_set_i2c_address(addr);  // 목표와 다를 때만 변경
```

**결과**
센서가 0x52든 0x54든 펌웨어가 **현재 주소를 스스로 찾아 정렬** → **전원을 끊지 않고도 몇 번이고 재플래시 가능**. (이미 목표 주소면 변경 명령을 생략해 불필요한 충돌도 회피)

## 3. 8×8 해상도에서 I2C 버스 wedge

**문제**
VL53L5CX의 최대 해상도(8×8=64존)로 설정하면, 이 배선 구성에서 I2C 버스가 **wedge(멈춤)** 되어 측정이 끊김.

**원인 분석**
- 8×8은 한 프레임당 전송량이 4×4의 4배 → 점퍼 와이어 배선(부유용량/노이즈)과 400kHz 클럭 조합에서 버스 안정성 한계.

**해결** ([`main.ino:19`](src/main.ino), `vl53l5cx_set_resolution(...4X4)`)
- 재실 감지에는 64존까지 필요 없다고 판단 → **4×4(16존)으로 다운스케일**.
- 침상 점유 판정에 충분한 공간 해상도를 유지하면서 버스 안정성 확보.

**결과**
끊김 없이 **2Hz로 안정적 연속 측정**. (해상도 코드는 8×8 수용 가능하게 남겨 두어 배선 개선 시 확장 가능)

## 4. 센서 전원 인가 직후 I2C stuck 회복

**문제**
LPN으로 센서를 켜는(전원 인가) 순간 버스가 stuck 상태에 빠져 초기화 실패하는 경우 발생.

**해결** — 전원 ON 후 I2C 재초기화 ([`main.ino:32-37`](src/main.ino))
```cpp
vl53l5cx_on();
delay(1000);                                   // 부팅 안정화 대기
p_dev->platform.dev_i2c->begin(SDA_PIN, SCL_PIN);  // 버스 재초기화 → stuck 회복
p_dev->platform.dev_i2c->setClock(400000);
```

**결과**
전원 인가 시점의 일시적 버스 stuck을 자동 회복 → 초기화 성공률 안정화.

## 5. 무효 거리값 필터링 — 데이터 품질

**문제**
ToF 원시 출력에는 측정 실패/약신호 존이 섞여 들어와 거리 격자에 노이즈가 낌.

**해결** — 유효 타깃만 채택 ([`main.ino:108-117`](src/main.ino), [`128-137`](src/main.ino))
```cpp
if (r.nb_target_detected[z] > 0) {
  uint8_t st = r.target_status[VL53L5CX_NB_TARGET_PER_ZONE * z];
  if (st == 5) d = r.distance_mm[...];   // status 5(유효 측정)만 거리 채택
}
// 그 외에는 -1(무효)로 표시해 서버가 제외
```

**결과**
서버·대시보드가 신뢰 가능한 거리값만 사용 → 재실 판정 정확도 향상.

## 6. 뒤척임으로 인한 재실 오탐 (서버 측)

**문제**
환자가 잠깐 뒤척이거나 한 프레임 튀는 값 때문에 "침상 있음↔없음"이 깜빡거리는 오탐.

**해결** — 베이스라인 대비 + 연속 프레임 확정 ([`tof_server.py:63-93`](../server/tof_server.py))
- **빈 침대 베이스라인**을 저장(`/tof/calibrate`)하고, 그보다 `PRESENCE_DELTA_MM(150mm)` 이상 가까운 존이 `PRESENCE_MIN_ZONES(4)`개 이상이면 그 센서 "감지".
- 상태가 바뀌어도 **연속 `CONFIRM_FRAMES(3)`프레임** 동안 유지될 때만 최종 전환 → 단발 튐 무시.
- 베이스라인이 없을 땐 `ABS_FALLBACK_MM(1500)` 절대거리 기준으로 폴백.

**결과**
뒤척임·일시적 노이즈에도 흔들리지 않는 **안정적 재실(있다/없다) 판정**. 양쪽 센서 중 하나만 감지해도 점유로 인정해 사각지대 최소화.

## 회고 (포트폴리오용 요약)

ToF 듀얼 센서 통합의 핵심 난관은 **하드웨어 제약(동일 주소·버스 대역폭)** 이었다.
데이터시트의 숨은 조건(주소 리셋 트리거)을 파악하고, **부팅 시 I2C 자동 스캔**으로 운영 편의성까지 해결한 점,
그리고 무리하게 8×8을 고집하지 않고 **요구사항(재실 감지)에 맞춰 4×4로 결정**한 트레이드오프 판단이 주요 성과다.
센서단(유효값 필터)과 서버단(베이스라인·연속프레임 확정)에 **2중으로 노이즈를 거른** 설계로 안정적인 재실 판정을 달성했다.
